## summary
Флеш-пам'ять польотника не гумова: увімкнути все одразу не можна, а отже, прошивка під твій апарат — це вибір. Модуль пояснює, як у Betaflight зібрати прошивку під свій набір функцій через Cloud Build і коли потрібні custom defines, і як в ArduPilot зібрати свій варіант із вихідного коду — наприклад, прибрати GPS і зайві драйвери, щоб умістити потрібне на F405. З прикладом із проєкту HeeWing.

## theory
### Навіщо взагалі збирати
- На F411/F405 стандартна прошивка з усіма опціями не влазить або влазить без потрібної функції.
- Потрібна опція, якої немає в стандартному наборі (далекомір, транспондер, екзотичний протокол).
- Потрібно прибрати те, чого на борту немає і не буде (GPS, компас, OSD-чип), звільнивши місце та пам'ять.

### Betaflight: Cloud Build
Починаючи з 4.4, прошивку збирає хмарний сервер під твій список опцій. У Firmware Flasher вибираєш протокол приймача, тип OSD, телеметрію, ESC-протокол тощо; кожна опція — це прапорець `USE_*` у вихідному коді, ім'я вводиться без префікса. Вибір сам тягне залежності: CRSF додасть CRSF-телеметрію, `GPS` — GPS Rescue та елементи OSD. Драйвери конкретної плати (гіроскоп, флеш, OSD-чип) додаються за таргетом автоматично.

**Custom defines** — поле в експертному режимі для опцій поза списками. Вони не тестуються на всіх платах; якщо опції потрібен пін, його призначають у CLI через `resource`. Завелика прошивка — збірка просто падає.

Перевірка на платі: команда `version` у CLI показує версію й таргет, а `BUILD KEY` виводить `status` — ключ, за яким Cloud Build збере рівно таку саму прошивку ще раз. У `diff all` ключа немає — вивід `status` зберігай окремо.

### ArduPilot: збірка з вихідного коду
ArduPilot збирається `waf`: `./waf configure --board <board>` і `./waf copter` (або `plane`). Таргет описується в `libraries/AP_HAL_ChibiOS/hwdef/<board>/hwdef.dat`: піни, шини, які драйвери вмикати. Там само через `define`-рядки вимикають непотрібне.

Для плат із маленькою флеш-пам'яттю існують урізані конфігурації: багато функцій у коді обгорнуто перевірками `#if AP_<FEATURE>_ENABLED`, і hwdef може задати `define AP_<FEATURE>_ENABLED 0`. Веб-інструмент Custom Firmware Builder (посилання в документації «Building the code») робить те саме через інтерфейс: ставиш галочки, отримуєш прошивку.

### Кейс: HeeWing F405 без GPS
Стоковий F405 у проєкті HeeWing T1 — плата з обмеженою флеш-пам'яттю: немає Lua-скриптингу, частину можливостей урізано. Варіанти прошивки, які планувалися для нього: прибрати підтримку GPS (на цій збірці він не використовується для арму та базового польоту) і зайві драйвери, щоб звільнити місце під потрібне. Це осмислене рішення, якщо розумієш наслідки: без GPS у прошивці не буде ні RTL, ні геозони за координатами — не лише «зараз», а взагалі.

### Правила власних збірок
1. Зберігати конфігурацію збірки в git поруч із параметрами: список опцій Betaflight або `hwdef`-патч ArduPilot.
2. Називати збірку з датою та хешем коміту; вивід `version` і BUILD KEY зі `status` мають збігатися із записом.
3. Перед прошиванням — повний бекап (`diff all` / файл параметрів), після — перечитати все критичне.
4. Не змішувати: власна збірка + стандартний конфіг від іншої версії = непередбачуваність.

### Локальна збірка Betaflight (коли Cloud Build не підходить)
```bash
git clone https://github.com/betaflight/betaflight && cd betaflight
make arm_sdk_install                      # toolchain
make configs                              # unified target configs
make STM32H743 EXTRA_FLAGS="-DUSE_RANGEFINDER -DUSE_GPS_LAP_TIMER"   # family target + extra defines
# або з конфігом конкретної плати:
make SPEEDYBEEF405V4 EXTRA_FLAGS="-DUSE_..."
```
Результат — `obj/betaflight_<ver>_<target>.hex`, прошивається конфігуратором «Load Firmware [Local]». Для перевірки без заліза — `make SITL` і `make test` (юніт-тести gtest, модуль «Як читати вихідний код»). Розмір прошивки — наприкінці збірки; F411 (512 КБ flash) вимагає вимикати опції `-DUSE_*` через `EXTRA_FLAGS` з мінусом або урізані target-конфіги.

### Що ламається після власної збірки і як перевіряти
1. за BUILD KEY зі `status` (`https://build.betaflight.com/api/builds/<key>/json`) — очікувані опції; 2. `status` — гіроскоп знайдено; 3. Ports/Receiver — приймач відповідає; 4. Motors — DShot і bidir працюють без пропів; 5. OSD видно; 6. `diff all` збігається з бекапом за змістом. Чек-лист — у журнал апарата разом із хешем коміту та `EXTRA_FLAGS`.

## practice
### Betaflight: збірка під конкретний апарат
1. Firmware Flasher → таргет плати → версія.
2. Опції: приймач (CRSF), OSD (аналог або цифра), телеметрія, ESC-протокол (DShot), GPS лише якщо він є.
3. Expert mode → Custom Defines, якщо потрібно щось поза списками.
4. Build → Flash. Після прошивання в CLI: `version` і `status` — зберегти вивід (BUILD KEY — у `status`) у папку дрона.
5. Відновити конфіг із `diff all` **тієї самої** мажорної версії, перечитати ключові параметри.

### ArduPilot: збірка з вихідного коду
```
git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git
cd ardupilot
Tools/environment_install/install-prereqs-ubuntu.sh -y
./waf configure --board MatekF405-Wing   # example board name; use yours
./waf plane
ls build/MatekF405-Wing/bin/             # arduplane.apj / .bin / .hex
```

Вимкнення функції: додати в `hwdef.dat` плати (або в окремий файл extra hwdef) рядок вигляду `define AP_<FEATURE>_ENABLED 0`, перезібрати, перевірити розмір у виводі збірки. Для першого досвіду простіше Custom Firmware Builder на сайті.

### Лабораторна
Збери дві прошивки ArduPlane для своєї плати: стандартну й без однієї підсистеми. Порівняй розмір бінарників, проший другу в SITL-подібний стенд (плата на столі) і переконайся, що вимкнена підсистема справді зникла з параметрів.

### Що має вийти і що записати
- **Betaflight.** Після прошивання урізаної збірки `version` і `status` збережено у файл поруч із конфігом (BUILD KEY дає змогу перезібрати рівно ту саму прошивку). Конфіг відновлено з `diff all` тієї самої мажорної версії, а ключові параметри перечитано через `get`. Налаштувань вимкнених опцій у CLI немає — перевір, наприклад, що після збірки без GPS команда `get gps` нічого не знаходить.
- **ArduPilot.** Вивід збірки показує розмір прошивки та вільну flash. Запиши обидва числа для двох збірок: різниця — ціна вимкненої підсистеми в байтах. Після прошивання параметри підсистеми (її префікс) зникають із повного списку параметрів у наземці — зроби скриншот пошуку за префіксом до і після.
- **Git.** Файл з опціями збірки (`hwdef` з `define AP_<FEATURE>_ENABLED 0` або список опцій Custom Firmware Build) лежить у репозиторії поруч із конфігом. За пів року на питання «чому на цьому дроні немає X» відповість коміт, а не пам'ять.

Лабораторна зараховується, коли зібрано стандартну й урізану прошивки, розміри порівняно і вивід `version`/BUILD KEY збережено, зникнення вимкненої підсистеми з параметрів підтверджено скриншотом або виводом CLI, а конфігурація збірки лежить у git.

## diagnostics
- **Симптом:** Cloud Build падає з помилкою розміру
  - Можлива причина: забагато опцій для флеш-пам'яті плати.
  - Що зробити: прибрати невикористовуване (другий OSD, зайві протоколи, GPS без GPS).
- **Симптом:** після власної збірки функція «є», але не працює
  - Можлива причина: опції потрібен пін, не призначений через `resource`.
  - Що зробити: `resource` у CLI, перезавантаження, перевірити `status`.
- **Симптом:** ArduPilot `waf configure` не знаходить плату
  - Можлива причина: одрук в імені, немає сабмодулів.
  - Що зробити: `./waf list_boards`, `git submodule update --init --recursive`.
- **Симптом:** після власної збірки частина параметрів зникла
  - Можлива причина: це і є ефект вимкненої підсистеми.
  - Що зробити: звірити із записом про збірку; якщо параметр потрібен — повернути функцію.

## checklist
- Знаю, які опції реально потрібні моєму апарату
- Збірку описано в git: опції / hwdef-патч, дата, хеш
- Вивід `version` і `status` (BUILD KEY) збережено після прошивання
- Конфіг відновлюється з тієї самої мажорної версії
- Розумію, що втрачаю, вимикаючи підсистему
