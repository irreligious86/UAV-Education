## summary
Місія INAV — список точок із діями, який апарат виконує в режимі NAV WP. Модуль показує, з чого складається точка, які є дії (WAYPOINT, POSHOLD_TIME, RTH, JUMP, SET_POI, LAND), як записати місію через конфігуратор і через CLI командою `wp`, де задається висота і як INAV захищає від зльоту з «чужою» місією.

## theory
### Структура точки
У CLI: `wp <n> <action> <lat> <lon> <alt> <p1> <p2> <p3> <flag>`.

- `lat`, `lon` — градуси × 10⁷ (123456789 = 12.3456789°).
- `alt` — сантиметри; біт 0 у `p3` задає, відносно дому (0) чи над рівнем моря (1).
- `action`: 1 WAYPOINT, 3 POSHOLD_TIME, 4 RTH, 5 SET_POI, 6 JUMP, 7 SET_HEAD, 8 LAND.
- `p1`: для WAYPOINT — швидкість до точки (см/с; лише мультиротор і лише якщо 50 < p1 < `nav_auto_speed`); для POSHOLD_TIME — час у секундах; для RTH — p1 > 0 дозволяє посадку; для JUMP — індекс цілі.
- `p2`: для POSHOLD_TIME — швидкість; для JUMP — кількість повторів.
- `flag` останньої точки — 165 (0xA5).

`wp load` завантажує список з EEPROM, `wp save` — зберігає, `wp reset` — очищає.

### Виконання
Режим NAV WP вмикається тумблером. Апарат летить від точки до точки на `nav_auto_speed` (або зі швидкістю з `p1`), радіус захоплення точки — `nav_wp_radius`. JUMP дає цикли, SET_POI — поворот камери на точку інтересу, LAND — посадку на точці.

### Захист від чужої місії
Якщо завантажено місію, перша точка якої далі за `nav_wp_max_safe_distance`, арм блокується. Це захист від сценарію «приїхав на інше поле з учорашньою місією». Обхід — `nav_extra_arming_safety = ALLOW_BYPASS` плюс yaw-стік під час арму, і це саме обхід.

### Кілька місій
Конфігуратор уміє зберігати кілька місій в одному списку точок і перемикатися між ними; операнди Programming Framework для точок стосуються вибраної місії.

### Порівняно з ArduPilot
В INAV місія простіша: немає CONDITION-команд, немає DO-команд у чистому вигляді (частина дій — через user actions у `p3` і логічні умови), завантаження через MSP/CLI, MAVLink-протокол місій (MISSION_COUNT/MISSION_ITEM) підтримується спрощено. Для зйомки ділянки й обльоту — достатньо; для складної логіки — Programming Framework або ArduPilot.

### Параметри виконання і захисту
`nav_auto_speed` (500 см/с) — швидкість за замовчуванням, `nav_wp_radius` (100 см) — радіус захоплення точки (для крила — більший, 1000–3000), `nav_wp_max_safe_distance` (100 м; 0 — вимкнути) — перша точка далі за цю відстань від місця арму → арм заблоковано («учорашня місія на новому полі»). Для крила точки проходяться по дузі, для мультиротора — із зупинкою; `nav_mc_wp_slowdown` керує гальмуванням біля точки.

### Розібраний приклад: обліт ділянки 200×100 м для зйомки
Висота 60 м, поперечне перекриття кадрів 70% за горизонтального FOV камери 84° (охоплення впоперек галсу ≈ 2·60·tan42° ≈ 108 м) → відстань між галсами 108 × (1 − 0.7) ≈ 32 м → на 100 м ширини 4 галси; точки: WAYPOINT ×8 з `p1` = 0 (швидкість `nav_auto_speed` = 5 м/с), наприкінці RTH з `p1` = 1 (посадку дозволено). Час: ~1 км шляху / 5 м/с ≈ 3.5 хв + розвороти. У CLI це 9 рядків `wp`, останній із прапорцем 165. Тригер камери — через PINIO/user action за `p3` або інтервальна зйомка на самій камері. Перевірка місії в конфігураторі на карті: жодна точка не над людьми/дорогою, висота вища за дерева.

### Що відбувається, коли в місії щось ламається
- **Втрата RC у NAV WP**: спрацьовує failsafe INAV (`failsafe_procedure`, зазвичай RTH); місію за замовчуванням **не** продовжує — це рішення пілота, а не прошивки. Перевіряйте, що висота RTH вища за перешкоди на всьому маршруті.
- **Втрата GPS**: навігаційні режими неможливі — апарат переходить в аварійну посадку (`nav_emerg_landing_speed`). Місія над водою чи лісом — із запасом висоти й зрозумілим планом «куди впаде».
- **Низький заряд**: плануйте місію на 60–70 % ємності й стежте за попередженнями OSD; не розраховуйте, що прошивка сама перерве місію вчасно.
- **Пілот вимкнув NAV WP**: апарат повертається в режим, вибраний тумблером; що буде при повторному ввімкненні — продовження чи початок спочатку — задає `nav_wp_mission_restart`.

## practice
### Крок 1. Місія в конфігураторі
1. Вкладка Mission Control: поставити 3–4 точки, висота 30 м відносно дому.
2. Остання — RTH із посадкою (або без для крила).
3. Зберегти у FC (Save to FC) і у файл.

### Крок 2. Та сама місія в CLI
```
wp reset
wp 0 1 505000000 304000000 3000 0 0 0 0
wp 1 1 505005000 304005000 3000 0 0 0 0
wp 2 3 505010000 304000000 3000 20 0 0 0
wp 3 4 0 0 0 1 0 0 165
wp save
wp
```

Точка 2 — POSHOLD_TIME 20 с, точка 3 — RTH із посадкою, останній прапорець 165.

### Крок 2б. Генератор CLI зі списку координат
Вручну переводити градуси в «× 10⁷» і сантиметри — певний спосіб помилитися на порядок. Скрипт:
```python
def wp_cli(points, alt_m=30, rth_land=True):
    # points: [(lat, lon), ...] in degrees -> INAV CLI lines; altitude relative to home
    lines = ["wp reset"]
    for i, (lat, lon) in enumerate(points):
        lines.append(f"wp {i} 1 {round(lat * 1e7)} {round(lon * 1e7)} {round(alt_m * 100)} 0 0 0 0")
    n = len(points)
    lines.append(f"wp {n} 4 0 0 0 {1 if rth_land else 0} 0 0 165")   # RTH, last point flag 0xA5
    lines += ["wp save", "wp"]
    return "\n".join(lines)

print(wp_cli([(50.4500000, 30.5200000), (50.4505000, 30.5205000), (50.4510000, 30.5200000)]))
```
Вивід вставити в CLI, потім порівняти з тим, що показує вкладка Mission Control. Розбіжність у координатах на 7-му знаку — норма округлення; на 1–2-му — помилка в порядку lat/lon.

### Крок 3. Політ
1. 3D-фікс, дім записано, місію завантажено (`wp` показує список).
2. Арм, ANGLE, зліт вручну на безпечну висоту.
3. Увімкнути NAV WP тумблером. Стежити за проходженням точок в OSD.
4. Будь-коли — вимкнути NAV WP і забрати керування.

### Лабораторна
Записати одну місію двома способами (конфігуратор і CLI через генератор), порівняти вивід `wp` — він має збігтися. Прогнати з POSHOLD_TIME і RTH. Для кожної точки маршруту записати, що буде при втраті RC і GPS саме там (висота RTH над перешкодами, місце аварійної посадки).

## diagnostics
- **Симптом:** не армиться із завантаженою місією
  - Можлива причина: перша точка далі за `nav_wp_max_safe_distance`.
  - Що зробити: перезаписати місію під поточне місце або скинути.
- **Симптом:** апарат іде до точок, але не сідає наприкінці
  - Можлива причина: у RTH p1 = 0 (посадку заборонено) або `nav_rth_allow_landing` = NEVER.
  - Що зробити: поставити p1 = 1 і перевірити `nav_rth_allow_landing`.
- **Симптом:** висота місії не та
  - Можлива причина: біт 0 у p3 (абсолютна висота) або плутанина сантиметрів і метрів.
  - Що зробити: перевірити `p3` і одиниці `alt`.
- **Симптом:** `wp` показує порожній список після перезавантаження
  - Можлива причина: не виконано `wp save`.
  - Що зробити: зберегти й перевірити `wp load`.
- **Симптом:** апарат пролітає повз точки
  - Можлива причина: `nav_wp_radius` замалий для швидкості (особливо крило).
  - Що зробити: радіус більший, швидкість біля точок менша.

## checklist
- Розумію поля точки й одиниці (градуси × 10⁷, сантиметри)
- Остання точка з прапорцем 165
- Місію перезаписано під поточне поле, арм не заблоковано
- NAV WP на тумблері, керування повертається миттєво
- Місію збережено у файл і у FC
