## summary
Пошук несправності — не перебір здогадок, а виключення гілок дерева, де кожен крок підтверджується фактом: вимірюванням мультиметра, повідомленням прошивки, рядком логу. Модуль дає дерево для п'яти типових ситуацій — «не армиться», «мотори не крутяться або крутяться не так», «божеволіє на газу», «ESC/плата горить під час підключення АКБ», «втрачає зв'язок або відео» — і правило, як додавати до нього власні випадки. Інструменти: smoke stopper, мультиметр, CLI `status`/повідомлення pre-arm, Blackbox/DataFlash.

## theory
### Правила діагностики
1. **Спочатку факт, потім гіпотеза.** Прошивка майже завжди *каже*, що не так: Betaflight — `status` у CLI (рядок Arming disable flags), INAV — вкладка Status і `status` у CLI, ArduPilot — повідомлення PreArm у GCS. Починати з них, а не з перепаювання.
2. **Одна зміна — одна перевірка.** Змінив два параметри й запрацювало — не знаєш, який допоміг, і не знаєш, що зламав.
3. **Від дешевого до дорогого.** Огляд і мультиметр — раніше, ніж осцилограф і заміна плати.
4. **Безпека на кожному кроці.** Пропи зняті для всього, що пов'язано з моторами. Перше ввімкнення після будь-якого паяння — через smoke stopper.
5. **Записуй шлях.** Кроки з результатами — у нотатку; знайдену причину — у дерево і в журнал апарата.

### Дерево 1. Не армиться
Прочитай причину: Betaflight CLI → `status` → `Arming disable flags: ...`. CLI друкує короткі імена з `runtime_config.c` (FAILSAFE, CALIB, NO_ACC_CAL, CMS, BOOTGRACE, MOTOR_PROTO, DSHOT_TELEM, ARMSWITCH у 4.5 / ARM_SWITCH у 2025.12+); нижче частину прапорців названо за документацією. Найчастіші:
- **RXLOSS / RX_FAILSAFE** — приймач не дає каналів. → Порт і протокол (UART, CRSF/SBUS, інверсія для SBUS на F4), бінд, живлення приймача (5 В мультиметром), вкладка Receiver — чи рухаються канали.
- **THROTTLE** — газ вище мінімуму. → Калібрування стіків у пульті, `min_check`, реверс каналу.
- **ANGLE** — апарат нахилений більше за `small_angle`. → Поверхня, калібрування акселерометра.
- **CALIBRATING / ACC_CALIBRATION / NOGYRO** — гіроскоп не відкалібровано або не знайдено. → Нерухомість під час увімкнення; NOGYRO — апаратна проблема або неправильна ціль прошивки.
- **ARM_SWITCH** — тумблер арму було ввімкнено під час подачі живлення. → Вимкнути, увімкнути.
- **MSP / CLI / CMS_MENU** — підключено конфігуратор або відкрито меню OSD. → Від'єднати USB, вийти з меню.
- **NOPREARM** — задано prearm-режим, не активовано.
- **DSHOT_TELEM** (до 4.5 — RPMFILTER) — увімкнено RPM-фільтр, немає телеметрії ESC (DShot bidir не підтримується прошивкою ESC або не ввімкнений).
- **BOOT_GRACE_TIME** — просто зачекати кілька секунд після ввімкнення.
- **MOTOR_PROTOCOL** — не вибрано протокол моторів.
INAV: вкладка Status показує причини (Navigation is unsafe, Compass not calibrated, Hardware failure...). ArduPilot: `PreArm: ...` у GCS — кожен рядок називає винуватця (Compass not calibrated, Gyros inconsistent, RC not calibrated, Throttle below failsafe, GPS: No Fix, Battery failsafe тощо); перевірки в `ARMING_SKIPCHK` (до 4.7 — `ARMING_CHECK`) не вимикати — лагодити причину.

### Дерево 2. Мотори не крутяться / крутяться не так
Пропи зняті.
- **Жоден мотор не реагує у вкладці Motors.** → Протокол (DShot300/600) і `motor_pwm_protocol` збігаються з ESC? → ESC отримують живлення (напруга на падах)? → Сигнальні проводи на потрібних падах (`resource MOTOR`)? → ESC пищать під час подачі живлення (стартова мелодія) — якщо ні, ESC не живий або немає живлення.
- **Один мотор не крутиться, решта так.** → Поміняти сигнальні проводи місцями з робочим: проблема пішла з проводом — сигнал/пад FC; лишилася — ESC або мотор. → Опір трьох фаз мотора однаковий? → Паяння фаз (холодне паяння — типово).
- **Мотор смикається, не стартує.** → Втрачено контакт однієї фази (паяння, перетертий провід) або пошкоджений ESC. → Фази продзвонити, поворушити.
- **Крутяться не в той бік / не той порядок.** → Вкладка Motors: по одному перевірити номер і напрямок за схемою рами; напрямок змінювати в прошивці ESC (BLHeli Suite/Configurator) або перепаюванням двох фаз. Напрямок «props in/out» — узгоджено в усіх чотирьох.
- **Дрон перевертається під час зльоту.** → Це дерево 2: порядок/напрямок або переплутаний міксер (`mixer` не для твоєї рами).

### Дерево 3. «Божеволіє» на газу
Симптом: висить нормально, вище 60–70% газу трясе, мотори гарячі, дрон поводиться непередбачувано.
- **Лог Blackbox є?** Якщо ні — записати, інакше вгадування. Спектр гіроскопа: пік на частоті моторів величезний → механіка (дисбаланс, пропи, люфт мотора); широкосмуговий шум зростає з газом → вібрації + брак фільтрації; пік не рухається з газом → резонанс рами.
- **Шум у гіроскопі зріс після заміни/ремонту?** → Конденсатор на силовій шині є? Паяння його виводів, ємність. → Кріплення FC (демпфери, натягнуті проводи).
- **ESC desync** (мотор раптово втрачає оберти, ривок, потім відновлюється; у лозі — провал eRPM одного мотора): → Налаштування ESC (timing, demag), DShot надто високий для довгих проводів, пошкоджений мотор; знизити протокол до DShot300, перевірити фази.
- **Просідання напруги:** у лозі VBAT падає нижче порога на газу → BEC перезавантажує FC (миттєва втрата контролю) або ESC ідуть у захист. → Роз'єм, АКБ, паяння.
- **PID/фільтри**: забагато D або P за недостатньої фільтрації → осциляції на високому газу, де шум більший. → Фільтри за спектром, потім знизити D.
- **Завади на приймач від VTX на повній потужності** (LQ падає з газом — рідко, але буває при пульсаціях на VTX): → фільтр живлення VTX, рознесення антен.

### Дерево 4. Щось горить/димить під час підключення АКБ
Від'єднати негайно. Далі — лише через smoke stopper (лампа/обмежувач у розриві плюса).
- **Лампа горить яскраво, борт не вмикається — КЗ.** → Від'єднувати споживачі по одному (ESC, FC, VTX, камера), починаючи з останнього припаяного; де лампа гасне — там КЗ. → Продзвонка + і − у кожного пристрою окремо. → Типові місця: перемичка припою на падах, гвинт в обмотці мотора (довгий гвинт), провід, затиснутий рамою, переплутана полярність роз'єму (2-піновий JST-PH у різних виробників розпаяний зі зворотною полярністю — класика), конденсатор навпаки.
- **Лампа тьмяно світиться, борт працює** — норма (струм заряду конденсаторів і робота BEC).
- **Запах, але лампа не горіла** — компонент згорів раніше; перевірити напруги BEC (5 В на виході?), температуру чипів пальцем після короткого ввімкнення, видимі пошкодження під лупою.
- **ESC згорів під час першого підключення** → полярність, напруга вища за допустиму (6S на ESC 4S), фази замкнені на землю (гвинт), паяння перемичкою фаза–живлення.
- **Згоріло після перепрошивки ESC** → неправильна ціль/налаштування, випадок рідкісний; але 90% «згоріло після прошивки» — збіг із новим паянням.

### Дерево 5. Втрачає зв'язок або відео
- **Failsafe на малій відстані** → LQ і RSSI в OSD: RSSI низький — антена (паяння, роз'єм U.FL, під карбоном), потужність TX, бінд-фраза; LQ низький за нормального RSSI — завада поруч із приймачем (VTX, buck, companion). → Тест дальності на землі (див. антени).
- **Відео шумить на газу** → пульсації живлення (конденсатор, LC-фільтр), земля, антена VTX.
- **Відео зникає далеко, RC тримає** → бюджет відео вичерпано — очікувано; антени, потужність, чи дозволена потужність.
- **Зв'язок зникає під час повороту апарата** → поляризація/провал діаграми: друга антена під 90°.
- **GPS не ловить** → під карбоном, поруч із завадами, немає живлення (світлодіод модуля), неправильний протокол/швидкість UART.

### Як розширювати дерево
Кожен свій випадок: симптом → кроки (з фактами) → причина → у яку гілку додати. За рік це твій головний довідник. Частину гілок курсу вже зібрано автоматично: сторінка «Фейли» — усі розділи «Діагностика» всіх модулів.

## practice
### Крок 1. Розбір трьох несправностей
Три несправності — свої, навчальні (створити: від'єднати сигнальний провід мотора, вимкнути приймач, задати `min_check` неправильно) або з форуму з логом. Іти суворо за деревом, записуючи кожен крок і факт.

### Крок 2. Факт на кожному кроці
У записі кожного кроку — що виміряно/прочитано: «status: RXLOSS», «5 В на RX: 4.98 В», «фаза A–B 0.08 Ом, B–C 0.08, A–C обрив». Кроки без факту — переробити.

### Крок 3. Доповнити дерево
Хоча б один свій випадок, якого в дереві немає, — вписати у свою копію дерева (файл `troubleshooting.md` в інженерній папці).

### Розібраний запис одного випадку
Несправність: мотор 3 не крутиться під час арму, решта крутяться.

| Крок дерева | Перевірка | Факт | Висновок |
|---|---|---|---|
| Команда доходить до ESC? | вкладка Motors, повзунок мотора 3 | ESC пищить під час подачі живлення, на повзунок не реагує | ESC живий, сигналу немає або він не той |
| Сигнал на виході FC | `resource` у CLI, осцилограф або перекидання сигнального проводу на сусідній вихід | на сусідньому виході мотор 3 крутиться | ESC і мотор справні |
| Вихід FC | паяння пада M3 під лупою, продзвонка | холодне паяння сигнального проводу | причину знайдено |
| Перевірка після ремонту | Motors, усі чотири мотори, помилки DShot | усі крутяться, помилок 0 % | закрито |

Кожен рядок — факт, який можна повторити. Рядок «мабуть, ESC» без перевірки — не крок, а здогадка.

### Що записати щодо трьох несправностей
- **Для кожної** — таблиця кроків, як вище, і час, витрачений на пошук. Через місяць порівняй, наскільки він скоротився.
- **Навчальні несправності** створюй так, щоб не нашкодити: від'єднаний сигнальний провід (без живлення!), вимкнений приймач (Betaflight покаже прапорець `RXLOSS` у `status`), неправильний `min_check` (стік газу внизу не розпізнається як «газ унизу», арм не проходить через прапорець `THROTTLE`).
- **Свій випадок у дерево:** гілка з питанням, перевіркою й ознакою. Наприклад: «мотори смикаються під час увімкнення відеопередавача → завада на сигнальних проводах → перенести VTX, ферити, DShot300».

### Лабораторна
Три несправності знайдено за деревом із записом кроків; кожен крок підтверджено вимірюванням або повідомленням прошивки; дерево доповнено своїм випадком.

Лабораторну зараховано, коли для кожної з трьох несправностей є таблиця кроків із фактами й висновком, жодного висновку не зроблено без вимірювання або повідомлення прошивки, а в `troubleshooting.md` додано свою гілку дерева.

## diagnostics
- **Симптом:** «ніщо не допомогло, перепрошив, запрацювало»
  - Можлива причина: причину не знайдено, збіг (частіше — перескладання контактів).
  - Що зробити: вважати нерозв'язаним; записати як відкритий випадок, стежити.
- **Симптом:** проблема плаваюча, з'являється раз на кілька польотів
  - Можлива причина: контакт/паяння, вібрація, температура.
  - У лозі/приладі: подія в лозі (провал eRPM, стрибок VBAT, RXLOSS) у момент симптому.
  - Що зробити: лог на кожному польоті; поворушити джгути за ввімкненого борту; точковий нагрів феном.
- **Симптом:** після заміни деталі симптом лишився
  - Можлива причина: деталь не була винна — гілку виключено неправильно.
  - Що зробити: повернутися до останнього підтвердженого факту.
- **Симптом:** дрон перевертається одразу на зльоті
  - Можлива причина: переплутано порядок моторів або напрямок обертання, неправильний міксер.
  - Що зробити: без пропів перевірити кожен мотор за схемою рами у вкладці Motors.

## checklist
- Починаю з повідомлення прошивки (`status` / PreArm), а не з паяльника
- Одна зміна — одна перевірка, кожен крок із фактом
- Перше ввімкнення після паяння — через smoke stopper
- Три несправності знайдено за деревом і записано
- Своє дерево діагностики заведено в інженерній папці
