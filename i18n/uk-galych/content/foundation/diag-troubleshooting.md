## summary
Пошук несправності — то не перебір здогадок, а виключення гілок дерева, де кожен крок підтверджується фактом: вимірюванням мультиметра, повідомленням прошивки, рядком логу. Модуль дає дерево для п'яти типових ситуацій — «не армиться», «мотори не крутяться або крутяться не так», «дуріє на газу», «ESC/плата горить при підключенні АКБ», «губить зв'язок або відео» — і правило, як додавати до нього власні випадки. Інструменти: smoke stopper, мультиметр, CLI `status`/повідомлення pre-arm, Blackbox/DataFlash.

## theory
### Правила діагностики
1. **Спершу факт, потім гіпотеза.** Прошивка майже завжди *каже*, що не так: Betaflight — `status` у CLI (рядок Arming disable flags), INAV — вкладка Status і `status` у CLI, ArduPilot — повідомлення PreArm у GCS. Починай з них, а не з перепаювання.
2. **Одна зміна — одна перевірка.** Змінив два параметри й запрацювало — не знаєш, котрий поміг, і не знаєш, що зламав.
3. **Від дешевого до дорогого.** Огляд і мультиметр — раніше, ніж осцилограф і заміна плати.
4. **Безпека на кожному кроці.** Пропи зняті для вшиткого, що пов'язане з моторами. Перше ввімкнення по будь-якому паянні — через smoke stopper.
5. **Записуй шлях.** Кроки з результатами — у нотатку; знайдену причину — в дерево і в журнал апарата.

### Дерево 1. Не армиться
Прочитай причину: Betaflight CLI → `status` → `Arming disable flags: ...`. CLI друкує короткі імена з `runtime_config.c` (FAILSAFE, CALIB, NO_ACC_CAL, CMS, BOOTGRACE, MOTOR_PROTO, DSHOT_TELEM, ARMSWITCH у 4.5 / ARM_SWITCH у 2025.12+); нижче частину прапорців названо за документацією. Найчастіші:
- **RXLOSS / RX_FAILSAFE** — приймач не дає каналів. → Порт і протокол (UART, CRSF/SBUS, інверсія для SBUS на F4), бінд, живлення приймача (5 В мультиметром), вкладка Receiver — ци рухаються канали.
- **THROTTLE** — газ вище мінімуму. → Калібрування стіків у пульті, `min_check`, реверс каналу.
- **ANGLE** — апарат нахилений більше за `small_angle`. → Поверхня, калібрування акселерометра.
- **CALIBRATING / ACC_CALIBRATION / NOGYRO** — гіроскоп не відкалібровано або не знайдено. → Нерухомість при увімкненні; NOGYRO — апаратна біда або хибна ціль прошивки.
- **ARM_SWITCH** — тумблер арму був увімкнений, коли подавали живлення. → Вимкнути, увімкнути.
- **MSP / CLI / CMS_MENU** — підключено конфігуратор або відкрито меню OSD. → Від'єднати USB, вийти з меню.
- **NOPREARM** — задано prearm-режим, не активовано.
- **DSHOT_TELEM** (до 4.5 — RPMFILTER) — увімкнено RPM-фільтр, а телеметрії ESC нема (DShot bidir не підтримується прошивкою ESC або не ввімкнений).
- **BOOT_GRACE_TIME** — просто зачекай кілька секунд по ввімкненні.
- **MOTOR_PROTOCOL** — не вибрано протокол моторів.
INAV: вкладка Status показує причини (Navigation is unsafe, Compass not calibrated, Hardware failure...). ArduPilot: `PreArm: ...` у GCS — кожен рядок називає винуватця (Compass not calibrated, Gyros inconsistent, RC not calibrated, Throttle below failsafe, GPS: No Fix, Battery failsafe тощо); перевірок в `ARMING_SKIPCHK` (до 4.7 — `ARMING_CHECK`) не вимикай — лагодь причину.

### Дерево 2. Мотори не крутяться / крутяться не так
Пропи зняті.
- **Жоден мотор не реагує у вкладці Motors.** → Протокол (DShot300/600) і `motor_pwm_protocol` збігаються з ESC? → ESC мають живлення (напруга на падах)? → Сигнальні дроти на тих падах, що треба (`resource MOTOR`)? → ESC пищать, коли подаєш живлення (стартова мелодія)? Як ні — ESC неживий або живлення нема.
- **Один мотор не крутиться, решта так.** → Поміняй сигнальні дроти місцями з робочим: біда пішла з дротом — сигнал/пад FC; лишилася — ESC або мотор. → Опір трьох фаз мотора однаковий? → Паяння фаз (холодне паяння — типово).
- **Мотор смикається, не стартує.** → Нема контакту однієї фази (паяння, перетертий дріт) або пошкоджений ESC. → Фази продзвонити, поворушити.
- **Крутяться не в той бік / не той порядок.** → Вкладка Motors: по одному перевір номер і напрямок за схемою рами; напрямок міняй у прошивці ESC (BLHeli Suite/Configurator) або перепаюванням двох фаз. Напрямок «props in/out» — однаковий в усіх чотирьох.
- **Дрон перевертається на зльоті.** → То дерево 2: порядок/напрямок або переплутаний міксер (`mixer` не для твоєї рами).

### Дерево 3. «Дуріє» на газу
Симптом: висить файно, вище 60–70% газу трясе, мотори гарячі, дрон поводиться непередбачувано.
- **Лог Blackbox є?** Як ні — запиши, бо інакше то вгадування. Спектр гіроскопа: пік на частоті моторів величезний → механіка (дисбаланс, пропи, люфт мотора); широкосмуговий шум росте з газом → вібрації + брак фільтрації; пік не рухається з газом → резонанс рами.
- **Шум у гіроскопі зріс по заміні/ремонті?** → Конденсатор на силовій шині є? Паяння його виводів, ємність. → Кріплення FC (демпфери, натягнуті дроти).
- **ESC desync** (мотор нагло губить оберти, ривок, потім відновлюється; у лозі — провал eRPM одного мотора): → Налаштування ESC (timing, demag), DShot зависокий для довгих дротів, пошкоджений мотор; знизь протокол до DShot300, перевір фази.
- **Просідання напруги:** у лозі VBAT падає нижче порога на газу → BEC перезавантажує FC (миттєва втрата контролю) або ESC ідуть у захист. → Роз'єм, АКБ, паяння.
- **PID/фільтри**: забагато D або P за слабкої фільтрації → осциляції на високому газу, де шум більший. → Фільтри за спектром, потім знизити D.
- **Завади на приймач від VTX на повній потужності** (LQ падає з газом — рідко, але трафляється при пульсаціях на VTX): → фільтр живлення VTX, рознесення антен.

### Дерево 4. Щось горить/димить при підключенні АКБ
Від'єднай зара. Далі — лиш через smoke stopper (лампа/обмежувач у розриві плюса).
- **Лампа горить яскраво, борт не вмикається — КЗ.** → Від'єднуй споживачі по одному (ESC, FC, VTX, камера), починаючи з останнього припаяного; де лампа гасне — там КЗ. → Продзвонка + і − у кожного пристрою окремо. → Типові місця: перемичка припою на падах, шруба в обмотці мотора (задовга шруба), дріт, затиснутий рамою, переплутана полярність роз'єму (2-піновий JST-PH у різних виробників розпаяний зі зворотною полярністю — класика), конденсатор навпаки.
- **Лампа тьмяно світиться, борт працює** — норма (струм заряду конденсаторів і робота BEC).
- **Запах є, а лампа не горіла** — компонент згорів раніше; перевір напруги BEC (5 В на виході?), температуру чипів пальцем по короткому ввімкненні, видимі пошкодження під лупою.
- **ESC згорів при першому підключенні** → полярність, напруга вища за допустиму (6S на ESC 4S), фази замкнені на землю (шруба), паяння перемичкою фаза–живлення.
- **Згоріло по перепрошивці ESC** → хибна ціль/налаштування, випадок рідкісний; але 90% «згоріло по прошивці» — збіг із новим паянням.

### Дерево 5. Губить зв'язок або відео
- **Failsafe на малій відстані** → LQ і RSSI в OSD: RSSI низький — антена (паяння, роз'єм U.FL, під карбоном), потужність TX, бінд-фраза; LQ низький при нормальному RSSI — завада коло приймача (VTX, buck, companion). → Тест дальності на землі (див. антени).
- **Відео шумить на газу** → пульсації живлення (конденсатор, LC-фільтр), земля, антена VTX.
- **Відео зникає далеко, RC тримає** → бюджет відео вичерпано — очікувано; антени, потужність, ци дозволена потужність.
- **Зв'язок зникає, коли апарат ся повертає** → поляризація/провал діаграми: друга антена під 90°.
- **GPS не ловить** → під карбоном, коло завад, нема живлення (світлодіод модуля), хибний протокол/швидкість UART.

### Як розширювати дерево
Кожен свій випадок: симптом → кроки (з фактами) → причина → у яку гілку додати. За рік то буде твій головний довідник. Частину гілок курсу вже зібрано автоматично: сторінка «Фейли» — вшиткі розділи «Діагностика» всіх модулів.

## practice
### Крок 1. Розбір трьох несправностей
Три несправності — свої, навчальні (зробити: від'єднати сигнальний дріт мотора, вимкнути приймач, задати `min_check` неправильно) або з форуму з логом. Іди строго за деревом, записуючи кожен крок і факт.

### Крок 2. Факт на кожному кроці
У записі кожного кроку — що виміряно/прочитано: «status: RXLOSS», «5 В на RX: 4.98 В», «фаза A–B 0.08 Ом, B–C 0.08, A–C обрив». Кроки без факту — переробити.

### Крок 3. Доповнити дерево
Хоч один свій випадок, якого в дереві нема, — впиши у свою копію дерева (файл `troubleshooting.md` в інженерній папці).

### Розібраний запис одного випадку
Несправність: мотор 3 не крутиться при армі, решта крутяться.

| Крок дерева | Перевірка | Факт | Висновок |
|---|---|---|---|
| Команда доходить до ESC? | вкладка Motors, повзунок мотора 3 | ESC пищить, коли подаєш живлення, на повзунок не реагує | ESC живий, сигналу нема або він не той |
| Сигнал на виході FC | `resource` у CLI, осцилограф або перекидання сигнального дроту на сусідній вихід | на сусідньому виході мотор 3 крутиться | ESC і мотор справні |
| Вихід FC | паяння пада M3 під лупою, продзвонка | холодне паяння сигнального дроту | причину знайдено |
| Перевірка по ремонті | Motors, усі чотири мотори, помилки DShot | усі крутяться, помилок 0 % | закрито |

Кожен рядок — факт, який можна повторити. Рядок «мабуть, ESC» без перевірки — то не крок, а здогадка.

### Що записати щодо трьох несправностей
- **Для кожної** — таблиця кроків, як вище, і час, витрачений на пошук. За місяць порівняй, наскільки він скоротився.
- **Навчальні несправності** роби так, щоб ніц не нашкодити: від'єднаний сигнальний дріт (без живлення!), вимкнений приймач (Betaflight покаже прапорець `RXLOSS` у `status`), хибний `min_check` (стік газу внизу не розпізнається як «газ унизу», арм не проходить через прапорець `THROTTLE`).
- **Свій випадок у дерево:** гілка з питанням, перевіркою й ознакою. Наприклад: «мотори смикаються, коли вмикаєш відеопередавач → завада на сигнальних дротах → перенести VTX, ферити, DShot300».

### Лабораторна
Три несправності знайдено за деревом із записом кроків; кожен крок підтверджено вимірюванням або повідомленням прошивки; дерево доповнено своїм випадком.

Лабораторну зараховано, коли для кожної з трьох несправностей є таблиця кроків із фактами й висновком, жодного висновку не зроблено без вимірювання або повідомлення прошивки, а в `troubleshooting.md` додано свою гілку дерева.

## diagnostics
- **Симптом:** «ніц не помагало, перепрошив — запрацювало»
  - Можлива причина: причини не знайдено, збіг (частіше — перескладання контактів).
  - Що зробити: вважати нерозв'язаним; записати як відкритий випадок, пантрувати.
- **Симптом:** біда плаваюча, вилазить раз на кілька польотів
  - Можлива причина: контакт/паяння, вібрація, температура.
  - У лозі/приладі: подія в лозі (провал eRPM, стрибок VBAT, RXLOSS) у момент симптому.
  - Що зробити: лог на кожному польоті; поворушити джгути при ввімкненому борті; точковий нагрів феном.
- **Симптом:** по заміні деталі симптом лишився
  - Можлива причина: деталь не була винна — гілку виключено неправильно.
  - Що зробити: вернутися до останнього підтвердженого факту.
- **Симптом:** дрон перевертається відразу на зльоті
  - Можлива причина: переплутано порядок моторів або напрямок обертання, хибний міксер.
  - Що зробити: без пропів перевірити кожен мотор за схемою рами у вкладці Motors.

## checklist
- Починаю з повідомлення прошивки (`status` / PreArm), а не з паяльника
- Одна зміна — одна перевірка, кожен крок із фактом
- Перше ввімкнення по паянні — через smoke stopper
- Три несправності знайдено за деревом і записано
- Своє дерево діагностики заведено в інженерній папці
