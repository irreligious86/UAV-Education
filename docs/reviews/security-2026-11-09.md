# Security review: multi-user access model (2026-11-09)

Scope: `supabase/migrations/0001_accounts_roles_progress.sql`, `assets/account.js`, `assets/account-page.js`,
`assets/admin-page.js`, `assets/backend-config.js`, against the access matrix in `docs/MULTIUSER-PLAN.md`.
Method: an independent reviewer (separate agent) reproduced attacks on Postgres 16 with the Supabase stub,
as the `anon` and `authenticated` roles with JWT claims set, and read the client code.

Verdict: no way for a student, admin or anonymous visitor to read others' grades or emails, change roles,
demote the superadmin, create a second superadmin or edit someone else's progress.

| # | Severity | Finding | Fix | Test |
|---|---|---|---|---|
| M1 | medium | `bootstrap_superadmin(email)` promoted an unconfirmed account, so an attacker who signed up with the owner's public email first could become superadmin | bootstrap requires a confirmed email and the expected username, drops old sessions; go-live order: bootstrap before the key is public | `test_bootstrap_refuses_unconfirmed_preregistration`, `test_bootstrap_requires_the_expected_username`, `test_bootstrap_drops_old_sessions` |
| M2 | medium | a student could store `{"done": 1}`; the admin page crashed for everyone, including the superadmin's role controls | `progress_shape` check constraint; tolerant `norm()`; per-row try/catch in the admin page | `test_progress_shape_enforced` (8 shapes), `merge.test.js` "malformed documents never throw" |
| M3 | medium | after a session was revoked elsewhere, the previous account's local progress stayed and merged into the next account on a shared browser | owner key in localStorage, wipe on owner change and on `SIGNED_OUT`; local-scope sign-out; refuse an offline logout that would drop unsynced progress unless confirmed | e2e step "shared browser" |
| L1 | low | unconfirmed sign-ups appeared as students; email cells could start a spreadsheet formula in CSV | `profiles.confirmed_at` kept in sync, admin view filters unconfirmed; CSV prefixes `= + - @` | `test_unconfirmed_signups_hidden_from_admin_view` |
| L2 | low | delete + insert let a student set `updated_at` in the future | touch trigger on insert and update | `test_updated_at_cannot_be_forged` |
| L3 | low | taken usernames can be probed via rename errors | accepted, documented | — |

Checked and sound: grants (anon has nothing; authenticated updates only `username`), every SECURITY DEFINER
function pins `search_path`, `set_role` rules, the single-superadmin index, RLS on all tables and the
`security_invoker` view, metadata cannot set roles, XSS (all DB strings escaped or set via `textContent`),
redirect URLs, the service worker never caches cross-origin (Supabase) responses.
