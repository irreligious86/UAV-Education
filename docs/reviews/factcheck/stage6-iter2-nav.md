## nav-indoor

22. **fixed**: `content/estimation/nav-indoor.md`, trap 2. Quote: "изменение параметра требует перезагрузки". `VISO_DELAY_MS` has no `@RebootRequired`. `writeExtNavData()` subtracts the current `delay_ms` from each packet straight away, but the time is clamped to `imuDataDelayed.time_ms`, and the buffer horizon is sized at init from `MIN(get_delay_ms(), 250)`. So the 250 ms cap is correct, and increases beyond the boot value only take full effect after a reboot. Text reworded.
