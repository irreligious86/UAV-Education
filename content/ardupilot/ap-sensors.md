## summary
Модуль про три датчика, которые в ArduPilot настраиваются до первого полёта и чаще всего настраиваются наполовину: компас, датчик воздушной скорости и мониторы батарей. По исходникам 4.7.2 разобрано, что прошивка делает с сырым полем компаса (смещения, матрица, компенсация по току), четыре способа калибровки и правило выбора между ними, точные строки отказов перед армом, стендовая сторона датчика скорости и все типы `BATT_MONITOR` — от аналогового до «суммы». После модуля ты выбираешь способ калибровки компаса под конкретный аппарат, проверяешь её результат по числам и раскладываешь несколько батарей по мониторам так, чтобы failsafe и OSD смотрели на нужную. Лабораторная расчётная, без железа и симулятора: компенсация помех по току, смещения «большого аппарата», поправки масштабов двух мониторов, маска суммы и три ошибки в файле параметров.

## theory
### Как читать модуль
Модуль закрывает стол, а не полёт: всё, что нужно задать и проверить у компаса, трубки скорости и датчиков батарей до взлёта. Порядок такой: сначала компас — экземпляры и приоритеты, формула коррекции поля, четыре способа калибровки, таблица выбора и отказы перед армом; затем короткая стендовая часть про воздушную скорость; затем мониторы батарей — типы, пороги, «сумма» и раскладки на несколько АКБ. Первую калибровку одного аналогового монитора даёт `ap-setup-scratch`, параметры `ARSPD_*` для полёта — `ap-setup-plane`; здесь они не повторяются. Поведение описано по чтению исходников тега Copter-4.7.2, прошивка в этом проходе не запускалась.

### Компас: экземпляры, приоритеты, внешний и внутренний
Прошивка при загрузке находит все магнитометры, каждому присваивает идентификатор устройства (тип шины, номер шины, адрес, тип микросхемы в одном числе) и раскладывает их по трём слотам приоритета. Параметры с суффиксами 2 и 3 относятся к **слоту приоритета**, а не к «внутреннему» или «внешнему» компасу.

| Параметр | По умолчанию | Значения | Смысл |
|---|---|---|---|
| `COMPASS_ENABLE` | 1 | 0 / 1 | драйверы и запись `MAG` в лог; нужна перезагрузка |
| `COMPASS_USE`, `COMPASS_USE2`, `COMPASS_USE3` | 1 | 0 / 1 | использовать ли компас слота 1, 2, 3 для курса |
| `COMPASS_PRIO1_ID`…`PRIO3_ID` | 0 | идентификатор | какой компас стоит в слоте; 0 — заполнить автоматически; нужна перезагрузка |
| `COMPASS_DEV_ID`, `DEV_ID2`, `DEV_ID3` | 0 | только чтение | идентификатор, с которым сохранена калибровка слота |
| `COMPASS_DEV_ID4`…`DEV_ID8` | 0 | только чтение | найденные компасы сверх трёх слотов (до пяти) |
| `COMPASS_EXTERNAL`, `EXTERN2`, `EXTERN3` | 0 | 0 внутренний; 1 внешний; 2 принудительно внешний | при 0 и 1 автоопределение по шине может переписать значение, при 2 — нет |
| `COMPASS_ORIENT`, `ORIENT2`, `ORIENT3` | 0 | 0 None; 2 Yaw90; 4 Yaw180; 6 Yaw270; 8 Roll180; 10 Yaw90Roll180; 12 Pitch180; 14 Yaw270Roll180 и другие до 43; 101, 102 — свои углы | поворот **внешнего** компаса относительно рамы; у внутреннего действует `AHRS_ORIENTATION` |
| `COMPASS_AUTO_ROT` | 2 | 0 выключено; 1 только проверить; 2 проверить и исправить; 3 то же с одинаковым допуском для поворотов на 45° | проверка ориентации в конце калибровки вращением |
| `COMPASS_DISBLMSK` | 0 | маска типов драйверов (бит 11 — DroneCAN, бит 7 — IST8310…) | не искать микросхемы этого типа при загрузке |
| `COMPASS_OPTIONS` | 0 | бит 0 — калибровка только при фиксе GPS; бит 1 — подменять пропавший DroneCAN-компас | бит 0 стоит включить, см. ниже про масштаб |
| `COMPASS_AUTODEC`, `COMPASS_DEC` | 1; 0 рад | 0 / 1; −3.142…3.142 | склонение из встроенной модели поля по координатам или вручную |

Правило выбора. Компас на мачте с GPS — в слот 1. Внутренний компас платы, лежащей в 2–3 см от силовых проводов, отключают: `COMPASS_USEn = 0` для его слота (обычно 2 или 3 — смотри по `COMPASS_PRIOn_ID`, а не по номеру). Он не добавляет точности, зато даёт отказ `Compasses inconsistent`. `COMPASS_DEV_ID*` руками не меняют: после перезагрузки калибровка привяжется к чужому датчику.

### Что прошивка делает с сырым полем
Каждое измерение проходит `correct_field` (`AP_Compass_Backend.cpp`) в строго заданном порядке:

B = M · ((B_сырое + OFS) · SCALE) + MOT · k

- OFS — `COMPASS_OFS_X/Y/Z`, мГс, **прибавляется** (hard iron, `est-sensors`);
- SCALE — `COMPASS_SCALE`; применяется, только если лежит в пределах 0.667–1.5, иначе пропускается (значение 0 — «не задан»);
- M — симметричная матрица: диагональ `COMPASS_DIA_X/Y/Z` (по умолчанию 1), вне диагонали `COMPASS_ODI_X` (xy), `ODI_Y` (xz), `ODI_Z` (yz) (soft iron);
- MOT — `COMPASS_MOT_X/Y/Z`; k зависит от `COMPASS_MOTCT`.

| `COMPASS_MOTCT` | k | Единица `COMPASS_MOT_*` |
|---|---|---|
| 0 | компенсации нет | — |
| 1 | газ от 0 до 1 | мГс при полном газе |
| 2 | ток **первого** монитора батареи, А | мГс/А |

Компенсация прибавляется после матрицы. При `COMPASS_MOTCT = 2` ток берётся только у монитора 1 (`BATT_*`): если у него нет измерения тока, поправка молча равна нулю. Для второго и третьего слота параметры те же с суффиксами: `COMPASS_OFS2_*`, `DIA2`, `ODI2`, `SCALE2`, `MOT2`. Есть ещё покомпонентная компенсация по каждому мотору `COMPASS_PMOT_*` — только для первого компаса; в модуле не разбирается.

В логе итог лежит в сообщении `MAG` (поле `I` — экземпляр): `MagX/Y/Z` — уже исправленное поле, `OfsX/Y/Z` — текущие смещения, `MOX/MOY/MOZ` — поправка по мотору в этот момент, `Health`.

### Калибровка вращением: что такое fitness
Onboard-калибровка (кнопка в наземной станции или тумблер `RCx_OPTION = 171`, только в дизарме) собирает 300 отсчётов при вращении аппарата всеми сторонами к земле и подгоняет к ним сначала сферу, потом эллипсоид. **Fitness** — корень из среднего квадрата невязки: на сколько миллигаусс в среднем точки отстоят от подогнанной поверхности. Чем меньше, тем лучше.

Калибровка принимается, если одновременно:

| Условие | Порог (`CompassCalibrator.cpp`) |
|---|---|
| fitness | ≤ `COMPASS_CAL_FIT` для внешнего компаса в слоте 1; ≤ 2 × `COMPASS_CAL_FIT` для всех остальных, включая внутренний в слоте 1 |
| радиус сферы | от 150 до 950 мГс |
| каждое смещение по модулю | < `COMPASS_OFFS_MAX` |
| диагональ | от 0.2 до 5.0 |
| внедиагональные | по модулю < 1.0 |
| масштаб (ожидаемое поле / радиус) | от 0.667 до 1.5, иначе `Mag(n) bad radius` |

`COMPASS_CAL_FIT`: 4 очень строго, 8 строго, 16 по умолчанию, 32 мягко (диапазон 4–32). `COMPASS_OFFS_MAX` — 1800 по умолчанию, диапазон 500–3000. В вики встречаются старые числа 850 и «смещение больше 600»; в 4.7.2 их нет.

Что записывается: `OFS`, `DIA`, `ODI`, `SCALE`, а у внешнего компаса при `COMPASS_AUTO_ROT` ≥ 2 — ещё и `COMPASS_ORIENT`. Масштаб считается как отношение поля из встроенной модели Земли к найденному радиусу, поэтому нужны координаты: без фикса прошивка пишет `MagCal: No location, fix_radius skipped` и оставляет `COMPASS_SCALE = 0`. Отсюда правило: калибровать на улице с 3D-фиксом, а `COMPASS_OPTIONS` бит 0 превращает это правило в запрет. После успеха нужна перезагрузка — до неё арм закрыт строкой `Compass calibrated requires reboot`. Запуск калибровки сбрасывает `COMPASS_LEARN` в 0.

Если калибровка не проходит раз за разом, поднимать `COMPASS_CAL_FIT` до 32 — последний шаг, а не первый. Сначала уйти от металла, проверить ориентацию и расстояние до силовых проводов (`el-emi`).

### Large Vehicle MagCal: смещения по известному курсу
Аппарат в 25 кг не повертишь. Команда `MAV_CMD_FIXED_MAG_CAL_YAW` (в Mission Planner — блок Large Vehicle MagCal; интерфейс по исходнику не проверялся) делает калибровку на месте. Входы: param1 — **истинный** курс носа в градусах, param2 — маска компасов (0 — все используемые), param3 и param4 — широта и долгота (0 и 0 — взять из AHRS или GPS с 3D-фиксом).

Что считает `mag_cal_fixed_yaw`:

1. По координатам берёт из встроенных таблиц мировой модели напряжённость F, склонение D и наклонение I. Поле в осях «север, восток, вниз»: N = F·cos I·cos D, E = F·cos I·sin D, Dn = F·sin I.
2. Поворачивает его в оси аппарата по текущим крену и тангажу из AHRS и по заданному курсу ψ. Для горизонтального аппарата: X = N·cos ψ + E·sin ψ, Y = −N·sin ψ + E·cos ψ, Z = Dn.
3. Берёт текущее измерение без старых смещений и матрицы и записывает **OFS = ожидаемое − измеренное**.
4. Ставит `DIA` = 1, `ODI` = 0. Масштаб и ориентацию не трогает.

Следствия. Способ исправляет только hard iron и считает, что датчик уже измеряет в миллигауссах и стоит в верной ориентации: при неверном `COMPASS_ORIENT` команда «успешно» запишет мусор. Курс нужен истинный: к показанию компаса телефона надо прибавить склонение. Ошибка курса на 8° даёт ошибку смещений в десятки миллигаусс (посчитано в практике). Масштаб из измерения не снимается: если после прошлой калибровки вращением `COMPASS_SCALE` не равен 0 или 1, записанные смещения будут неточны. Перед командой поставь `COMPASS_SCALE = 0` (масштаб не применяется). Рядом не должно быть металла и работающих моторов: одно измерение принимается как есть. Отказы: `Mag: no position available`, `Mag: WMM table error`, `Mag[n]: unhealthy`.

### Обучение в полёте: `COMPASS_LEARN`
| Значение | В 4.7.2 | Что происходит |
|---|---|---|
| 0 | по умолчанию | выключено |
| 1 | **убрано** из списка значений (в 4.6 — Internal-Learning) | в исходнике 4.7.2 закомментировано |
| 2 | EKF-Learning | Copter при дизарме копирует в `COMPASS_OFS*` смещения, оценённые EKF |
| 3 | InFlight-Learning | после 3 с полёта ждёт, пока оценщик курса GSF (`ap-ekf`) сойдётся до 5°, вызывает ту же `mag_cal_fixed_yaw` с этим курсом, пишет `CompassLearn: Finished` и возвращает параметр в 0 |

Пока `COMPASS_LEARN = 3`, компас для курса **не используется** (и проверки компаса перед армом пропускаются); на режимы с удержанием позиции не рассчитывай до сообщения `Finished`. Кроме сходимости GSF до 5° прошивка ждёт тангаж по модулю не больше 50° и не больше одного «клипа» IMU. Тумблер `RCx_OPTION = 62` включает то же самое без записи параметра. Вики называет обучение «для опытных и не рекомендуется» с тех пор, как есть Large Vehicle MagCal: результат тот же (только смещения), а первый полёт проходит без компаса.

### MagFit: калибровка по логу полёта
MagFit — подгонка параметров компаса к уже записанному логу. Инструмент не входит в дерево прошивки: веб-версия лежит в репозитории ArduPilot/WebTools (каталог `MAGFit`), вторая реализация — в MAVProxy (`modules/lib/magfit.py`, меню Tools в MAVExplorer). Экраны и кнопки по исходнику прошивки не проверяются.

Принцип по исходникам инструментов: для каждого отсчёта `MAG` из положения в логе и координат вычисляется ожидаемое поле мировой модели в осях аппарата, затем подбираются параметры формулы коррекции, при которых исправленное поле ближе всего к ожидаемому. Подбирать можно смещения, масштаб, `DIA`, `ODI` и `COMPASS_MOT_*` по току.

| Что нужно в логе | Зачем |
|---|---|
| `MAG` выбранного экземпляра | измеренное поле и смещения, с которыми летали |
| `ATT` (или кватернион EKF / `AHR2`) | ориентация аппарата |
| `GPS`, `POS` или `ORGN` | координаты для модели поля |
| `BAT.Curr` | ток для подгонки `COMPASS_MOT_*` |
| `PARM` | старые значения, чтобы снять их с данных |

Правила из вики и README инструмента: лог в несколько минут с несколькими полными разворотами; участки на земле и в руках исключить; начинать с одних смещений и добавлять `DIA`/`ODI` и ток, только если остаётся заметная невязка; результат принимать, если оставшееся отклонение курса меньше 10°; если расчётный курс после подгонки уходит от курса EKF больше чем на 20° — искать ошибку в другом месте (ориентация, GPS), а не записывать параметры. Первый полёт для лога делается с любой грубой калибровкой, в режиме без удержания позиции.

### CompassMot: помеха от силовой проводки
Процедура `compassmot` есть только в Copter (кроме вертолётов). **Она раскручивает моторы с пропеллерами**: полётник сам переходит в арм, газ со стика идёт на ESC напрямую, failsafe по газу на это время отключён. По вики пропеллеры переворачивают и переставляют на соседние лучи, чтобы тяга прижимала аппарат к земле, а сам аппарат крепят.

Что делает `compassmot.cpp`:

- при нулевом газе запоминает базовое поле B₀;
- при газе выше нуля считает помеху ΔB = B − B₀;
- если есть измерение тока и I ≥ 3 А: накапливает **MOT = −ΔB / I** (скользящее среднее), тип 2; без датчика тока — MOT = −ΔB / газ, тип 1;
- показывает процент помехи, пересчитанный на полный газ: |MOT| · (I_макс / газ_макс) / 530 · 100, где газ_макс — наибольший газ за процедуру от 0 до 1 (530 мГс — принятое в прошивке «типовое» поле); при компенсации по газу — |MOT| / 530 · 100. Процедуру ведут на 50–75 % газа, поэтому показанный процент больше, чем помеха на том газе, где ты остановился: 40 А на 75 % газа считаются как 53.3 А на полном;
- по окончании пишет `COMPASS_MOTCT` и `COMPASS_MOT*`, сообщение `Calibration successful`.

Оценка процента по вики: меньше 30 — приемлемо, 31–60 — серая зона, больше 60 — переносить компас. Компенсация по газу (тип 1) хуже: ток при том же газе зависит от напряжения батареи. Компенсация держится, пока провода и батарея не сдвинулись, поэтому сначала разносят компас и проводку (`el-emi`), а вычитают только остаток. Тот же вектор без раскрутки на столе даёт MagFit по логу.

### Какой способ для какого аппарата
{{diagram:ap-sensors-compass-flow|Способ калибровки выбирается двумя вопросами: можно ли аппарат вращать в руках и зависит ли поле от тока. Вращение даёт полную калибровку, известный курс — только смещения, а помеху от тока убирают переносом компаса и лишь остаток — CompassMot или MagFit.}}

| Аппарат | Способ | Почему | Что проверить после |
|---|---|---|---|
| Квадрокоптер 5″, компас в модуле GPS в 2–4 см над батареей | вращением; затем CompassMot или MagFit с током | вертеть легко, а провода рядом — помеха по току почти неизбежна | процент помехи < 30; `MAG.MOX/Y/Z` меняются с газом, а длина поля — нет |
| Коптер 7–10″, компас на мачте 8–10 см | вращением | мачта уже убрала ток | длина поля при полном газе меняется меньше чем на 5–10 % |
| Большой мультиротор, который не поднять | Large Vehicle MagCal; после первого полёта — MagFit | вращение невозможно; известный курс даёт только смещения | `COMPASS_ORIENT` задан вручную **до** команды; после MagFit отклонение курса < 10° |
| Самолёт | вращением (лёгкий) или Large Vehicle | `EK3_MAG_CAL = 0` у Plane: в полёте EKF сам оценивает поле; тока рядом с компасом в крыле мало | курс на стоянке совпадает с осью полосы в пределах 5–10° |
| VTOL | как большой мультиротор, если не повертеть; иначе вращением | в висении токи мультироторные — нужен MagFit на участке висения | `XKF3.IMX/IMY/IMZ` в висении и в самолётном полёте одного порядка |

Общие проверки после любой калибровки:

- длина вектора `COMPASS_OFS*` заметно меньше `COMPASS_OFFS_MAX`; сотни миллигаусс — норма для компаса рядом с металлом, больше тысячи — повод искать магнит или сталь рядом;
- длина `MAG.MagX/Y/Z` на земле близка к полю места (в умеренных широтах 450–550 мГс) и лежит между 185 и 875 мГс;
- в логе висения `XKF3.IMX/IMY/IMZ` (инновации магнитометра) колеблются около нуля, `XKF4.SM` меньше 1 (`ap-logs`, `ap-ekf`);
- в Loiter нет расширяющихся кругов («воронки») — это признак ошибки курса, а не PID (`nav-resilience`). Если воронка началась — сразу в режим без GPS.

### Отказы перед армом по компасу
Строки приходят с префиксом `PreArm:`; порядок проверок такой, как в таблице (`AP_Arming.cpp`, `compass_checks`).

| Строка | Условие | Что делать |
|---|---|---|
| `Compass calibration running` | калибровка не завершена | дождаться или отменить |
| `Compass calibrated requires reboot` | после onboard-калибровки | перезагрузить |
| `Compass n not healthy` | нет данных 0.5 с | проводка, шина, `COMPASS_DISBLMSK` |
| `Compass n not found` | компас из слота приоритета не обнаружен | вернуть датчик или убрать его из `COMPASS_PRIOn_ID` |
| `Compass order change requires reboot` | меняли приоритеты | перезагрузить |
| `Compass not calibrated` | смещения нулевые или `DEV_ID` не совпал с найденным | калибровать |
| `Compass offsets too high` | **длина** вектора смещений первого компаса > `COMPASS_OFFS_MAX` | убрать металл; не поднимать порог вслепую |
| `Check mag field: 912, max 875, min 185` | длина поля вне 185–875 мГс | магнит рядом, неверный масштаб |
| `Compasses inconsistent` | у двух используемых компасов угол между векторами > 90°, в горизонтальной плоскости > 60° или разность горизонтальных составляющих > 200 мГс | ориентация второго компаса; отключить внутренний |
| `Check mag field (xy diff:142>100)` | горизонтальная составляющая отличается от модели поля больше `ARMING_MAGTHRESH` | калибровка рядом с металлом, арматура под аппаратом |
| `Check mag field (z diff:260>200)` | вертикальная — больше 2 × `ARMING_MAGTHRESH` | то же |

`ARMING_MAGTHRESH` — 100 мГс по умолчанию, диапазон 0–500; 0 **отключает** сравнение с моделью поля. Обрати внимание на разницу: калибратор проверяет каждое смещение отдельно, а проверка перед армом — длину вектора. Калибровка с тремя смещениями по 1100 пройдёт, а арм — нет (длина 1905).

### Компас и EKF
Калибровка — это вход оценки состояния, а что EKF с ним делает, задают три параметра (подробно — `ap-ekf`):

{{lesson:ap-ahrs-choice|Полёт без компаса (GSF, `EK3_SRC1_YAW = 8`), выставка курса по GPS в полёте и когда EKF перестаёт верить компасу.}}

- `EK3_MAG_CAL`: 0 — в полёте оценивать поле по трём осям (умолчание Plane), 2 — только курс (Rover), 3 — три оси после первого набора высоты (умолчание Copter), 4 — всегда. Оценённые EKF смещения видны в `XKF2.MX/MY/MZ`.
- `EK3_SRC1_YAW`: 1 компас, 2 GPS (две антенны, `est-gnss`), 3 GPS с откатом на компас, 6 внешняя навигация, 8 GSF — курс по движению без компаса.
- `COMPASS_USE = 0` для всех слотов плюс `EK3_SRC1_YAW = 8` — законная конфигурация самолёта без компаса; на коптере курс до начала движения не определён (`nav-resilience`).

### Датчик воздушной скорости на столе
Настройка для полёта (`ARSPD_TYPE`, `ARSPD_USE`, `ARSPD_RATIO`, автокалибровка) — в `ap-setup-plane`. Здесь только то, что проверяется на столе.

| Параметр | По умолчанию | Смысл на стенде |
|---|---|---|
| `ARSPD_BUS` | 1 | номер шины I²C (0–3), может не совпадать с подписью на плате; нужна перезагрузка |
| `ARSPD_PIN` | по плате | вход АЦП аналогового датчика (`ARSPD_TYPE = 2`) |
| `ARSPD_PSI_RANGE` | 1.0 | диапазон датчика в psi; менять только по описанию микросхемы: MS4525 пересчитывает давление через это число |
| `ARSPD_OFFSET` | 0 | ноль датчика; пишется калибровкой при каждом включении |
| `ARSPD_SKIP_CAL` | 0 | 0 — калибровать ноль при загрузке; 1 — взять сохранённый, калибровка не требуется; 2 — не калибровать при загрузке, но требовать ручную раз за включение (значение 2 — новое в 4.7) |
| `ARSPD_PRIMARY` | 0 | какой датчик основной: 0 первый, 1 второй |
| `ARSPD2_TYPE`, `ARSPD2_BUS`, `ARSPD2_USE`… | 0 | второй датчик; в стандартной сборке датчиков два |
| `ARSPD_WIND_MAX` | 0 м/с | расхождение со скоростью GPS, выше которого датчик считается неисправным; 0 — нет проверки по разнице с GPS (проверка согласованности с EKF по `ARSPD_WIND_GATE` остаётся) |
| `ARSPD_WIND_WARN` | 0 м/с | порог предупреждения; 0 — равен `WIND_MAX` |
| `ARSPD_WIND_GATE` | 5.0 | ширина ворот проверки по EKF3 в стандартных отклонениях (0–10) |

Типы по шинам: I²C — MS4525 (1), MS5525 (3–5), SDP3X (6), DLVR (7, 9–12), ASP5033 (15), AUAV (17–19, новые в 4.7); АЦП — аналоговый (2); DroneCAN (8); MSP (14). Правило выбора: аналоговый датчик дрейфует с напряжением питания и стоит выбирать его только на готовой плате; на шине I²C длиннее 30–40 см надёжнее DroneCAN.

Ноль при загрузке: прошивка отбрасывает первые несколько отсчётов (6; в комментарии исходника — 5), усредняет остальные не меньше секунды и пишет `ARSPD_OFFSET` (`Airspeed 1 calibrated`). Если в трубку в это время дует ветер, ноль записан со скоростью, и все показания занижены. Поэтому трубку закрывают неплотным колпачком. Датчик с `ARSPD_OFFSET = 0` считается неисправным, если только не задан `ARSPD_SKIP_CAL = 1`.

Проверка трубок на утечку: надеть на приёмник полного давления кусок силиконовой трубки, слегка сжать её до показания 15–20 м/с и зажать. Показание должно держаться несколько секунд; падает — течёт соединение. То же с обратным знаком на статическом входе.

Контроль в полёте (`AP_Airspeed_Health.cpp`): пять раз в секунду вероятность исправности умножается на 0.9 при расхождении и медленно растёт при согласии; ниже 0.1 при `ARSPD_OPTIONS` бит 0 датчик отключается (`Airspeed sensor 1 failure. Disabling`), выше 0.95 при бите 1 включается обратно. По умолчанию `ARSPD_OPTIONS` = 11 (биты 0, 1 и 3): датчик отключается и включается обратно автоматически, а расхождение считается и по воротам EKF (`ARSPD_WIND_GATE` = 5) — даже при `ARSPD_WIND_MAX = 0`. Проверка выключена целиком, только когда и `ARSPD_WIND_MAX`, и `ARSPD_WIND_GATE` равны 0. Правило для `ARSPD_WIND_MAX`: максимальный ветер, в который ты летаешь, плюс 5 м/с; меньше — датчик отключится от порыва.

### Мониторы батарей: типы `BATT_MONITOR`
Монитор — это экземпляр с собственным набором параметров: `BATT_*` — первый, `BATT2_*`…`BATT9_*` — остальные. В стандартной сборке 4.7.2 их **девять** (`AP_BATT_MONITOR_MAX_INSTANCES = 9`); префиксы `BATTA_`…`BATTG_` и «до 16 мониторов» из вики появляются только в сборке с увеличенным числом экземпляров. После смены `BATTn_MONITOR` нужна перезагрузка.

| Значение | Тип | Что измеряет и когда выбирать |
|---|---|---|
| 0 | выключен | — |
| 3 | аналоговый, только напряжение | делитель на входе АЦП; батарея авионики, датчик без шунта. Тока и мА·ч нет |
| 4 | аналоговый, напряжение и ток | обычный power module; основной вариант до 6S и токов датчика |
| 31 | аналоговый, только ток (новый в 4.7) | отдельный датчик Холла на луче или на второй ветви; напряжение всегда 0 |
| 25 | напряжение + расчётный ток | ток оценивается по выходу газа самолёта; для крыла без датчика тока |
| 7, 13, 14, 15, 16, 19 | SMBus: общий, SUI3, SUI6, NeoDesign, Maxell, Rotoye | «умная» батарея по I²C: сама сообщает ёмкость, банки, серийный номер |
| 8 | DroneCAN BatteryInfo | датчик или батарея на шине CAN (`el-dronecan`); 12S и выше, длинные провода |
| 9 | ESC | среднее напряжение и **сумма** токов по телеметрии ESC (`ap-outputs`) |
| 10 | сумма выбранных мониторов | виртуальный монитор поверх других |
| 21, 26, 30, 22, 28 | INA2xx по I²C, INA239 по SPI, INA3221 (новый в 4.7), LTC2946, AD7091R5 | цифровые измерители на плате или модуле; точнее аналогового входа |
| 11, 12, 24 | расход топлива (импульсы), уровень топлива PWM и аналоговый | ДВС: «ёмкость» в миллилитрах |
| 17, 18, 27 | генератор (электрическая и топливная часть), EFI | гибридные установки |
| 20, 23, 29 | MPPT, Torqeedo, Lua-скрипт | солнечный контроллер, лодочный мотор, свой драйвер |
| 5, 6, 32 | Solo, Bebop, TI BQ76952 (только AP_Periph) | конкретные изделия |

Параметры аналогового монитора: `BATT_VOLT_PIN` и `BATT_CURR_PIN` (номера входов АЦП по `hwdef` платы; у MatekH743 первый датчик — 10 и 11, второй — 18 и 7), `BATT_VOLT_MULT`, `BATT_AMP_PERVLT`, `BATT_AMP_OFFSET`, `BATT_VLT_OFFSET`. Формулы из `AP_BattMonitor_Analog.cpp`:

- V = (V_вход − `BATT_VLT_OFFSET`) × `BATT_VOLT_MULT`;
- I = (V_вход − `BATT_AMP_OFFSET`) × `BATT_AMP_PERVLT`.

Обе величины прямо пропорциональны множителю, поэтому поправка всегда «новое = старое × эталон / показание»: для напряжения эталон — мультиметр, для тока — мА·ч, залитые зарядным устройством, против мА·ч по полётнику. Пошаговая процедура для первого монитора — в `ap-setup-scratch`; для второго она та же с префиксом `BATT2_`. У монитора ESC (тип 9) маска `BATT_ESC_MASK` выбирает, какие ESC входят в сумму (0 — все). Не путай с `BATT_ESC_INDEX`: тот, наоборот, отправляет данные монитора в телеметрию ESC под указанным номером.

### Пороги, таймер и напряжение покоя
| Параметр | По умолчанию | Смысл |
|---|---|---|
| `BATT_CAPACITY` | 3300 мА·ч | полная ёмкость; основа процента и порогов по мА·ч |
| `BATT_LOW_VOLT` / `BATT_CRT_VOLT` | 10.5 В (Copter), 0 (Plane) / 0 | пороги напряжения; 0 — выключено |
| `BATT_LOW_MAH` / `BATT_CRT_MAH` | 0 / 0 | пороги по **остатку**: `CAPACITY` − израсходовано |
| `BATT_LOW_TIMER` | 10 с | сколько напряжение должно держаться ниже порога; действует на оба порога напряжения |
| `BATT_FS_VOLTSRC` | 0 | 0 — измеренное напряжение, 1 — напряжение покоя |
| `BATT_FS_LOW_ACT` / `BATT_FS_CRT_ACT` | 0 / 0 | действие; 0 — только предупреждение (`ap-safety-fs`) |
| `BATT_ARM_VOLT` / `BATT_ARM_MAH` | 0 / 0 | минимум напряжения и остатка для арма |
| `BATT_SERIAL_NUM` | −1 | серийный номер SMBus или идентификатор батареи DroneCAN |
| `BATT_OPTIONS` | 0 | бит 6 — слать на землю напряжение покоя; бит 8 — монитор не показывать наземной станции; бит 9 — «сумма» берёт минимальное напряжение вместо среднего; биты 0, 7, 10 — DroneCAN; биты 1–5 — MPPT |

Логика `update_failsafes` и `check_failsafes`:

- пороги по мА·ч срабатывают **сразу**, по напряжению — после `BATT_LOW_TIMER` секунд непрерывно ниже порога; критический проверяется первым;
- `BATT_LOW_TIMER = 0` **отключает оба failsafe по напряжению**;
- проверка идёт только в арме и **для каждого монитора отдельно**: у каждого свои пороги и своё действие `BATTn_FS_*_ACT`; сообщение — `Battery 2 is low 21.40V used 5200 mAh`;
- монитор, молчащий 5 с, даёт только сообщение `Battery n is missing, last: …`, действия нет;
- счётчик мА·ч обнуляется при перезагрузке (кроме «умных» батарей): `BATT_ARM_MAH` не защитит от взлёта на полупустой батарее после перезапуска, нужен ещё `BATT_ARM_VOLT`.

Напряжение покоя. Прошивка непрерывно оценивает внутреннее сопротивление R по изменениям тока и напряжения (поле `BAT.Res` в логе) и считает V_покоя = V + I × R (`BAT.VoltR`). При `BATT_FS_VOLTSRC = 1` пороги сравниваются с ним. Правило выбора: на аппарате с большими бросками тока и «мягкой» батареей (Li-Ion, `el-battery-packs`) источник 1 убирает ложные срабатывания на наборе; пороги тогда задают по напряжению без нагрузки. Оценке нужен датчик тока; пока R не выучено, поправка мала.

Отказы перед армом: `Battery n unhealthy`, `below minimum arming voltage`, `below minimum arming capacity`, `low voltage failsafe`, `low capacity failsafe`, `critical voltage failsafe`, `critical capacity failsafe`, `capacity failsafe critical >= low`, `voltage failsafe critical >= low` — все с префиксом `PreArm: Battery n`.

### Монитор «сумма» и раскладки на несколько батарей
Монитор типа 10 (`AP_BattMonitor_Sum.cpp`) складывает ток, мА·ч и Вт·ч выбранных мониторов, а напряжение **усредняет** (или берёт минимум при `BATT_OPTIONS` бит 9). Выбор задаёт `BATTn_SUM_MASK`: бит 0 — монитор 1, бит 1 — монитор 2 и так далее до бита 8. Себя он не включает никогда. Значение 0 означает «все мониторы **с номером больше моего**». Неисправные слагаемые пропускаются молча: при отказе одного датчика сумма покажет половину тока без единого отказа. Монитор «сумма» собирается не на всех платах с 1 МБ флеша: если его нет, арм запрещён строкой `PreArm: Battery n feature BATTERY_SUM not available`.

{{diagram:ap-sensors-batt-sum|Сумма стоит первым монитором и складывает только силовые батареи 2 и 3 (маска 6): на неё смотрят наземная станция, OSD и компенсация компаса. Failsafe проверяется у каждого монитора отдельно, поэтому у батареи авионики свой порог и своё действие.}}

| Задача | Раскладка | Почему так |
|---|---|---|
| Одна батарея, один датчик | `BATT_MONITOR = 4` | базовый случай |
| Две батареи параллельно, у каждой свой датчик | `BATT_MONITOR = 10`, `BATT_SUM_MASK = 6`; `BATT2`, `BATT3` — датчики | общий ток и мА·ч на первом мониторе; пороги по мА·ч — на сумме от суммарной ёмкости |
| Силовая батарея и батарея авионики | `BATT` — силовая (тип 4), `BATT2` — авионика (тип 3) | авионика без тока; свой `BATT2_LOW_VOLT` и действие «посадка» |
| Нет общего датчика, есть телеметрия четырёх ESC | `BATT_MONITOR = 9`, `BATT_ESC_MASK = 15` | ток — сумма по ESC; потребители мимо ESC не учтены |
| Общий датчик напряжения и датчики тока на двух ветвях | `BATT` — сумма с маской 6; `BATT2`, `BATT3` — тип 31; `BATT4` — тип 3 с порогами по напряжению | у типа 31 напряжение равно 0, поэтому у суммы оно неверно (нули попадают и в среднее, и в минимум): на сумме держат только пороги по мА·ч |

Правило: первым ставят монитор, который описывает **силовую цепь целиком**, потому что именно его берут три потребителя без выбора — `SYS_STATUS` наземной станции, большинство элементов OSD и компенсация компаса по току.

### Что показывают наземная станция и OSD
- `SYS_STATUS` (напряжение, ток и процент в шапке наземной станции) — всегда монитор 1. `BATTERY_STATUS` шлётся по каждому монитору, кроме помеченных `BATT_OPTIONS` бит 8.
- OSD (`ap-osd-video`): `BAT_VOLT`, `CURRENT`, `BATUSED`, `RESTVOLT`, `AVGCELLV` — монитор 1; `BAT2_VLT`, `BAT2USED`, `CURRENT2` — монитор 2. Для мониторов 3–9 элементов нет.
- В логе сообщение `BAT` пишется по каждому экземпляру (поле `Inst`): `Volt`, `VoltR`, `Curr`, `CurrTot`, `EnrgTot`, `Res`, `RemPct`.

### Место в системе
- **Получает:** место компаса и разводку силовых проводов — от `el-emi` и `el-power-design`; ёмкость, число банок и допустимую просадку — от `el-battery-packs`; телеметрию ESC — от `ap-outputs`; процедуру первой калибровки монитора — от `ap-setup-scratch`.
- **Отдаёт:** исправленное поле и курс — оценке состояния (`ap-ekf`, `est-sensors`); напряжение, ток и мА·ч — порогам failsafe (`ap-safety-fs`) и экрану (`ap-osd-video`); ноль трубки — контуру скорости (`ap-setup-plane`).
- **Если ошибиться здесь:** курс по неверным смещениям даёт «воронку» в Loiter и отказ `EKF variance` (`nav-resilience`, `ap-ekf`); сумма без одной батареи занижает расход, и порог `BATT_LOW_MAH` срабатывает поздно (`ap-safety-fs`); ноль трубки на ветру занижает скорость до сваливания (`ap-setup-plane`).

## practice

### Шаг 1. Помеха от тока и проверка калибровки
Квадрокоптер 5″, компас в модуле GPS над батареей, внешний, в слоте 1. После калибровки вращением:

```
# учебный пример, собран вручную
COMPASS_OFS_X,112
COMPASS_OFS_Y,-48
COMPASS_OFS_Z,205
COMPASS_DIA_X,1
COMPASS_DIA_Y,1
COMPASS_DIA_Z,1
COMPASS_SCALE,1.0
COMPASS_CAL_FIT,16
COMPASS_OFFS_MAX,1800
COMPASS_MOTCT,0
```

Отчёт калибровки: fitness первого компаса 14.2, второго (внутреннего) 27.5. Аппарат закреплён, показания `MAG` первого компаса при разном токе:

| Ток, А | MagX | MagY | MagZ |
|---|---|---|---|
| 0 | 210 | −35 | 420 |
| 10 | 228 | −41 | 451 |
| 20 | 246 | −47 | 482 |
| 30 | 264 | −53 | 513 |
| 40 | 282 | −59 | 544 |

Найди: (а) прошла ли калибровка обоих компасов по fitness; (б) вектор `COMPASS_MOT_X/Y/Z` и значение `COMPASS_MOTCT`; (в) исправленное поле при 30 А после записи; (г) процент помехи, если 40 А получены на полном газе, и вывод; (д) пройдёт ли арм по длине смещений и по длине поля; (е) что будет с вектором смещений (640, −1310, 1150).

Результат. (а) Первый — внешний в слоте 1, порог 16: 14.2 ≤ 16, принят. Второй — порог 2 × 16 = 32: 27.5 ≤ 32, принят. (б) ΔB при 40 А = (72, −24, 124); MOT = −ΔB / I = (**−1.8, 0.6, −3.1**) мГс/А; `COMPASS_MOTCT = 2`. Строки 10, 20 и 30 А дают тот же вектор. (в) (264, −53, 513) + (−1.8, 0.6, −3.1) × 30 = (**210, −35, 420**) — базовое поле. (г) |MOT| = √(1.8² + 0.6² + 3.1²) = 3.635; 3.635 × 40 = 145.4 мГс; 145.4 / 530 = **27.4 %** (40 А — на полном газе; если те же 40 А получены на 75 % газа, процедура покажет 27.4 / 0.75 = 36.6 %) — меньше 30, приемлемо, но близко к границе; при 36.6 % — уже серая зона. (д) |OFS| = √(112² + 48² + 205²) = **238.5** < 1800; |B₀| = √(210² + 35² + 420²) = **470.9** мГс, внутри 185–875. (е) Каждое смещение меньше 1800 — калибратор примет; длина вектора **1856.9** > 1800 — `PreArm: Compass offsets too high`.

### Шаг 2. Large Vehicle MagCal вручную
Тяжёлый октокоптер стоит горизонтально, нос на ориентир с истинным курсом ψ = 60°. Данные модели поля для этой точки (заданы как входные): F = 500 мГс, склонение D = +8°, наклонение I = 66°. Компас в верной ориентации, старые смещения нулевые, `DIA` = 1, `ODI` = 0; измерение (310, −95, 250). Найди смещения, которые запишет команда. Затем повтори расчёт для ошибки оператора: введён магнитный курс 52°.

Результат. N = 500 · cos 66° · cos 8° = 201.39; E = 500 · cos 66° · sin 8° = 28.30; Dn = 500 · sin 66° = 456.77. В осях аппарата: X = 201.39 · 0.5 + 28.30 · 0.8660 = 125.21; Y = −201.39 · 0.8660 + 28.30 · 0.5 = −160.26; Z = 456.77. OFS = ожидаемое − измеренное = (**−184.8, −65.3, 206.8**). При ψ = 52° ожидаемое (146.29, −141.27, 456.77), смещения (−163.7, −46.3, 206.8): ошибка 21 и 19 мГс по горизонтальным осям, а курс после такой «калибровки» смещён на те самые 8°. Команда в обоих случаях ответит успехом.

### Шаг 3. Два датчика, сумма и failsafe
Тот же октокоптер: две батареи 6S по 10 000 мА·ч параллельно, у каждой свой аналоговый датчик; авионика от отдельной 3S. Раскладка: `BATT` — сумма, `BATT2` и `BATT3` — датчики, `BATT4` — авионика (тип 3).

(а) Обе силовые батареи на стенде соединены, мультиметр показывает 24.36 В. Наземная станция: монитор 2 — 23.90 В, монитор 3 — 24.60 В; у обоих `VOLT_MULT = 11.0`. Найди новые множители. (б) После полёта полётник насчитал 4150 мА·ч по монитору 2 и 4620 мА·ч по монитору 3; зарядное устройство залило 4480 и 4390 мА·ч; у обоих `AMP_PERVLT = 40`. Найди новые значения. (в) Какая `BATT_SUM_MASK` и что будет при маске 0? (г) Пороги суммы: `BATT_CAPACITY = 20000`, `BATT_LOW_MAH = 5000`, `BATT_CRT_MAH = 3000`, `BATT_LOW_VOLT = 21.6`, `BATT_CRT_VOLT = 21.0`, `BATT_LOW_TIMER = 10`, `BATT_FS_LOW_ACT = 2`, `BATT_FS_CRT_ACT = 1`, `BATT_FS_VOLTSRC = 0`. Реши четыре случая: 1) 21.9 В, израсходовано 15 200 мА·ч; 2) 21.4 В в течение 6 с, затем 22.0 В; 3) 20.8 В в течение 12 с, израсходовано 12 000 мА·ч; 4) при `BATT_FS_VOLTSRC = 1`: 21.4 В, ток 60 А, R = 0.012 Ом, держится 15 с. (д) Израсходовано 6000 мА·ч, ток висения 54 А: через сколько минут сработает `BATT_LOW_MAH`?

Результат. (а) 11.0 × 24.36 / 23.90 = **11.21**; 11.0 × 24.36 / 24.60 = **10.89**. (б) 40 × 4480 / 4150 = **43.18**; 40 × 4390 / 4620 = **38.01**. (в) Мониторы 2 и 3 — биты 1 и 2: 2 + 4 = **6**. При маске 0 сумма возьмёт мониторы 2, 3 и 4: ток не изменится (у авионики тока нет), а напряжение станет средним трёх: (24.36 + 24.36 + 11.9) / 3 = 20.2 В при 11.9 В на авионике — ниже `BATT_LOW_VOLT` и `BATT_CRT_VOLT`: арм не пройдёт, `PreArm: Battery 1 low voltage failsafe` (перед армом пороги проверяются без таймера, и низкий проверяется раньше критического). Если отключить эту проверку, через 10 с после арма будет ложный критический failsafe. (г) 1) остаток 4800 < 5000 — low сразу, RTL. 2) ничего: 6 с < 10 с, таймер сброшен. 3) ниже 21.0 дольше 10 с — critical, Land; остаток 8000 порогов не касается. 4) V_покоя = 21.4 + 60 × 0.012 = 22.12 В > 21.6 — ничего. (д) До порога (20000 − 5000) − 6000 = 9000 мА·ч; 9000 / 54 000 ч = 0.1667 ч = **10.0 мин**.

### Шаг 4. Выбор способа и три ошибки
(а) Назови способ калибровки компаса и раскладку мониторов для трёх аппаратов: A — квадрокоптер 5″, компас в модуле GPS в 3 см над батареей, одна батарея, датчик тока на плате; B — октокоптер 25 кг, компас на мачте 15 см, две батареи с датчиками и батарея авионики; C — VTOL-крыло, которое поднимают вдвоём, компас в законцовке, силовая 6S и авионика 3S, трубка MS4525.

(б) Найди ошибки в выдержке аппарата B:

Результат. (а) A — вращением, затем CompassMot или MagFit с током; `BATT_MONITOR = 4`. C — Large Vehicle MagCal (или вращение вдвоём), MagFit на участке висения; `BATT` — силовая, тип 4, `BATT2` — авионика, тип 3; ноль трубки под колпачком, проверка утечки.

(б) Ошибок ровно три. (1) `COMPASS_MOTCT = 2` при `BATT_MONITOR = 3`: у первого монитора нет тока, компенсация равна нулю. (2) `BATT4_SUM_MASK = 0` у монитора 4: «все с номером больше моего» — таких нет, сумма неисправна, `PreArm: Battery 4 unhealthy`; нужно сделать сумму первым монитором с маской 6 (или здесь — маску 6 на мониторе 4, но тогда остаётся ошибка 1). ### Переход на реальное железо
Пропеллеры сняты на всех шагах, кроме CompassMot. **CompassMot раскручивает моторы до 50–75 % газа** (процент помехи прошивка пересчитывает на полный газ, деля на наибольший газ процедуры): пропеллеры перевёрнуты и переставлены, аппарат привязан, люди за спиной оператора; на аппарате тяжелее 5 кг вместо него — MagFit по логу.

1. Сохрани параметры в файл. Выпиши `COMPASS_PRIOn_ID` и `COMPASS_DEV_ID*`, определи, в каком слоте внешний компас; отключи `COMPASS_USEn` внутреннего.
2. Калибровка по таблице выбора, на улице, с 3D-фиксом, в 10 м от машин и арматуры. Для Large Vehicle — сначала `COMPASS_ORIENT`, затем истинный курс по ориентиру на карте.
3. Перезагрузи. В Messages нет строк `PreArm` по компасу; поверни аппарат на 90° по ориентирам — курс в наземной станции меняется на 90 ± 10°.
4. Трубка: колпачок, включение, `Airspeed 1 calibrated`; проба на утечку; показание растёт при выдохе в трубку.
5. Каждый монитор: напряжение против мультиметра, ноль тока, после первого полёта — поправка по мА·ч зарядки. Отключи один датчик из суммы и убедись, что видишь это в наземной станции (ток вдвое меньше) — другого сигнала не будет.
6. Failsafe каждого монитора на земле без пропеллеров: подними `BATTn_LOW_VOLT` выше текущего напряжения, заармь, дождись `Battery n is low`; верни порог.

На железе работа выполнена, когда длина `COMPASS_OFS*` меньше `COMPASS_OFFS_MAX`, длина поля на земле в пределах 185–875 мГс, в логе висения `XKF4.SM` меньше 1, показания каждого монитора расходятся с мультиметром не больше чем на 0.1 В, а сообщение `Battery n is low` получено от каждого монитора с порогом.

Самопроверка: лабораторная выполнена, когда:
- шаг 1: MOT = (−1.8, 0.6, −3.1) мГс/А точно, `COMPASS_MOTCT = 2`; исправленное поле (210, −35, 420); помеха 27.4 ± 0.2 % на полном газе и 36.6 ± 0.2 % для 40 А на 75 % газа; длины 238.5 и 470.9 (± 0.5); для второго вектора длина 1857 ± 1 и строка `Compass offsets too high`;
- шаг 2: смещения (−184.8, −65.3, 206.8) с допуском ± 0.3; для курса 52° — (−163.7, −46.3, 206.8);
- шаг 3: множители 11.21 и 10.89 (± 0.01), 43.18 и 38.01 (± 0.02); маска 6; при маске 0 — отказ арма `PreArm: Battery 1 low voltage failsafe`; решения случаев «RTL сразу», «ничего», «Land», «ничего»; 10.0 мин;
- шаг 4: способы совпали с таблицей выбора; найдены именно три ошибки — ток для компенсации, маска суммы, перевёрнутые пороги — и названы две строки `PreArm`.

**Эталон для самопроверки.** Верный результат — числа из четырёх пунктов выше. Типичные ошибки: (1) MOT = (+1.8, −0.6, +3.1): забыт минус — компенсация прибавляется к полю и должна гасить помеху, а с таким знаком удвоит её. (2) В шаге 2 смещения (184.8, 65.3, −206.8): вычтено «измеренное − ожидаемое», а прошивка прибавляет смещение к измерению. (3) В шаге 3 множители 10.79 и 37.05: дробь перевёрнута — показание меньше эталона, значит, множитель должен вырасти. (4) Маска 3 вместо 6: биты посчитаны с единицы, а бит 0 — это монитор 1, то есть сама сумма, которая себя не включает; в сумме остался бы один монитор 2. (5) В случае 3 ответ «RTL по low»: критический порог проверяется первым. (6) Помеха 27.4 % для 40 А на 75 % газа: забыто деление на наибольший газ — прошивка пересчитывает ток на полный газ и покажет 36.6 %. (7) В (в) при маске 0 ответ «ложный failsafe через 10 с после арма»: до арма дело не дойдёт — проверка перед армом сравнивает напряжение с порогами без таймера.

## diagnostics
- **Симптом:** калибровка вращением не заканчивается или раз за разом начинается заново.
  Возможная причина: fitness выше порога — рядом металл, компас у силовых проводов, неверная `AHRS_ORIENTATION` для внутреннего компаса; у внутреннего компаса порог и так удвоен.
  Что сделать: уйти на открытое место, снять телефон и ключи, вращать медленнее; только потом `COMPASS_CAL_FIT = 32`. Компас, который не калибруется при исправных остальных, отключить через `COMPASS_USEn`.
- **Симптом:** `Mag(1) bad orientation: 4/0 1.6` или `Mag(1) internal bad orientation`.
  Возможная причина: фактический поворот датчика не совпадает с `COMPASS_ORIENT`, а уверенности для автоисправления не хватило; у внутреннего компаса неверна `AHRS_ORIENTATION`.
  Что сделать: посмотреть стрелку на модуле, задать ориентацию вручную и повторить.
- **Симптом:** `PreArm: Compasses inconsistent`.
  Возможная причина: внутренний компас возле проводки расходится с внешним больше чем на 60° в горизонте или на 200 мГс.
  Что сделать: найти слот внутреннего компаса по `COMPASS_PRIOn_ID` и задать ему `COMPASS_USEn = 0`; если расходятся два внешних — проверить ориентацию каждого.
- **Симптом:** `PreArm: Check mag field (xy diff:…>100)` только на одной площадке.
  Возможная причина: арматура, люк, машина под аппаратом или рядом.
  Что сделать: переставить аппарат на 5–10 м. Если отказ везде — перекалибровать. `ARMING_MAGTHRESH = 0` отключает проверку и оставляет тебя без неё в полёте.
- **Симптом:** в Loiter аппарат ходит расширяющимися кругами, курс в наземной станции плывёт с газом.
  Возможная причина: помеха от тока или неверные смещения.
  Что сделать: сразу режим без GPS (AltHold, Stabilize) и посадка; затем лог.
  Что видно в логе: `MAG.MagX/Y/Z` меняются вместе с `BAT.Curr`, `XKF4.SM` растёт выше 1, `XKF3.IYAW` уходит от нуля.
  Последствия: улёт по дуге, `EKF variance`, переключение EKF.
- **Симптом:** `COMPASS_MOTCT = 2`, а `MAG.MOX/MOY/MOZ` в логе нулевые.
  Возможная причина: первый монитор батареи без тока (тип 3, сумма без слагаемых, выключен).
  Что сделать: сделать первым монитор с током силовой цепи.
- **Симптом:** после Large Vehicle MagCal курс в наземной станции отличается от настоящего на 5–15°.
  Возможная причина: введён магнитный курс вместо истинного; рядом металл; неверный `COMPASS_ORIENT`.
  Что сделать: прибавить склонение и повторить на другом месте; после первого полёта — MagFit.
- **Симптом:** `COMPASS_LEARN = 3`, в Loiter и Auto курс неуверенный или режим не включается.
  Возможная причина: обучение не завершено — пока оно идёт, компас для курса не используется (откажет ли режим, зависит от источника курса EKF; по исходнику не прослежено).
  Что сделать: лететь прямо несколько секунд до `CompassLearn: Finished` или вернуть 0 и калибровать на земле.
- **Симптом:** воздушная скорость на стоянке 5–8 м/с или в полёте занижена.
  Возможная причина: ноль записан на ветру; утечка трубки.
  Что сделать: колпачок и повторная калибровка нуля; проба на утечку.
- **Симптом:** `Airspeed sensor 1 failure. Disabling` в ветреный день.
  Возможная причина: `ARSPD_WIND_MAX` меньше реального ветра с порывами.
  Что сделать: порог — максимальный рабочий ветер плюс 5 м/с.
- **Симптом:** `PreArm: Battery 3 unhealthy`.
  Возможная причина: тип монитора сменили без перезагрузки; у суммы нет исправных слагаемых (маска 0 у последнего монитора); `BATTn_VOLT_PIN` не тот.
  Что сделать: перезагрузить, разложить маску на биты, сверить номера входов с `hwdef` платы.
- **Симптом:** ток в наземной станции вдвое меньше ожидаемого, отказов нет.
  Возможная причина: один датчик из суммы неисправен и пропущен.
  Что сделать: посмотреть `BATTERY_STATUS` или `BAT` по каждому экземпляру.
  Последствия: мА·ч занижены, `BATT_LOW_MAH` сработает поздно.
- **Симптом:** напряжение первого монитора на 15–20 % ниже настоящего; на заряженных батареях `PreArm: Battery 1 low voltage failsafe`.
  Возможная причина: в сумму попала батарея авионики или монитор «только ток» (маска 0 берёт все мониторы с большим номером).
  Что сделать: задать маску явно.
- **Симптом:** `PreArm: Battery n feature BATTERY_SUM not available`.
  Возможная причина: в сборке для платы с 1 МБ флеша монитора «сумма» нет.
  Что сделать: обойтись без суммы (пороги на каждом мониторе) или взять плату с большим флешем.
- **Симптом:** failsafe по напряжению не срабатывает, хотя порог пройден.
  Возможная причина: `BATT_LOW_TIMER = 0`; `BATT_FS_VOLTSRC = 1`, и напряжение покоя выше порога; аппарат не в арме; действие 0.
  Что сделать: проверить четыре параметра этого монитора.
- **Симптом:** после перезагрузки в поле процент батареи снова 100.
  Возможная причина: счётчик мА·ч живёт до перезагрузки.
  Что сделать: `BATT_ARM_VOLT` по напряжению без нагрузки; не перезагружать с начатой батареей.

## checklist
- Внешний компас в слоте 1, внутренний у силовой проводки отключён через `COMPASS_USEn` своего слота
- Калибровка сделана на улице с 3D-фиксом; `COMPASS_SCALE` не равен 0
- Для Large Vehicle MagCal: `COMPASS_ORIENT` задан заранее, курс истинный
- Длина `COMPASS_OFS*` меньше `COMPASS_OFFS_MAX`, порог не поднимали вслепую
- `COMPASS_LEARN = 0` перед полётом с удержанием позиции
- `ARMING_MAGTHRESH` не равен 0
- CompassMot: пропеллеры перевёрнуты, аппарат привязан, люди за спиной — моторы раскручиваются
- `COMPASS_MOTCT = 2` только если у монитора 1 есть ток; процент CompassMot прочитан как помеха на полном газе
- Перед Large Vehicle MagCal `COMPASS_SCALE = 0`
- Ноль трубки записан под колпачком, утечки нет
- Первый монитор описывает всю силовую цепь; маска суммы задана явно
- У каждого монитора с порогом ненулевое `BATTn_FS_*_ACT` и `BATTn_LOW_TIMER` больше 0 — иначе failsafe по этой батарее отключён
- `BATT_CRT_*` ниже `BATT_LOW_*`; задан `BATT_ARM_VOLT`

## notes
Параметры, значения, строки сообщений и формулы проверены чтением дерева тега Copter-4.7.2 и метаданных 4.7.2; сравнение с 4.6 — по дереву 4.6.3. Прошивка в этом проходе не собиралась и не запускалась: поведение описано по исходнику. Не проверено и взято из вики и исходников инструментов: экраны Mission Planner (Large Vehicle MagCal, Compass/Motor Calib), интерфейс WebTools MAGFit и MAVExplorer, пороги «30 / 60 %» для CompassMot, «10° и 20°» для MagFit. Диапазон 450–550 мГс для умеренных широт, проба трубки на утечку и правило «ветер плюс 5 м/с» — инженерная практика, не исходник. Расхождения с вики на дату проверки: вики называет `COMPASS_OFFS_MAX` 850 и порог смещения 600 (в 4.7.2 — 1800 и проверка длины вектора) и «до 16 мониторов» (в стандартной сборке 4.7.2 — 9). Сайт ardupilot.org из среды подготовки модуля недоступен, поэтому страницы вики приведены ссылками на их исходные файлы в репозитории ardupilot_wiki.
