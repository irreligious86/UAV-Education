## summary
Управление мультиротором в PX4 — каскад из трёх контуров: позиция → ориентация → угловая скорость, плюс распределение моментов по моторам. Модуль объясняет, какой параметр за какой контур отвечает, в чём разница форм rate-регулятора (K-множитель против обычного P), как выглядит процедура ручного тюнинга по step response и почему для большинства рам правильный ответ — autotune. Для перешедших с Betaflight — таблица соответствий.

## theory
### Каскад
1. **Position controller** (`MPC_*`): из ошибки позиции — желаемая скорость (`MPC_XY_P`, `MPC_Z_P`), из ошибки скорости — желаемое ускорение/наклон (`MPC_XY_VEL_P_ACC` и др.). Здесь же газ висения `MPC_THR_HOVER` и ограничения скоростей `MPC_XY_VEL_MAX`, `MPC_Z_VEL_MAX_UP/DN`.
2. **Attitude controller** (`MC_ROLL_P`, `MC_PITCH_P`, `MC_YAW_P`): из ошибки угла — желаемая угловая скорость. Только P.
3. **Rate controller** (`MC_ROLLRATE_P/I/D/K`, то же для PITCH и YAW, плюс `MC_*RATE_FF`): из ошибки угловой скорости — момент. Самый быстрый контур, он определяет «ощущение» аппарата.
4. **Control allocation**: моменты и тяга → команды моторам по геометрии `CA_AIRFRAME`, `CA_ROTOR_COUNT`, `CA_ROTOR<n>_PX/PY/KM`.

### Форма rate-регулятора
PX4 использует параллельную форму с общим множителем K: выход = K × (P·e + I·∫e + D·de/dt). `MC_ROLLRATE_K` масштабирует все три сразу, поэтому первый шаг грубого тюнинга — K, а не P. У Betaflight такого множителя нет; его роль в слайдерах играет Master Multiplier.

### Соответствия с Betaflight
| Betaflight | PX4 |
|---|---|
| P/I/D roll (rate) | `MC_ROLLRATE_P/I/D` (× `MC_ROLLRATE_K`) |
| Feedforward | `MC_ROLLRATE_FF` |
| Angle mode strength | `MC_ROLL_P` |
| Фильтры гиро | `IMU_GYRO_CUTOFF`, `IMU_DGYRO_CUTOFF`, notch `IMU_GYRO_NF*_FRQ` |
| Throttle hover / air mode | `MPC_THR_HOVER`, `MC_AIRMODE` |

### Autotune
Для большинства рам документация прямо рекомендует autotune: быстрее и обычно даёт хороший результат. Он идентифицирует модель по откликам в висении и применяет найденные rate-гейны и P контура угла; применение управляется `MC_AT_APPLY` (сразу, после посадки или вручную). Ручной тюнинг — когда autotune не справляется: нестандартные рамы, сильные вибрации, большие аппараты.

### Ручной тюнинг по step response
Порядок: фильтры → rate (K, затем D, затем I) → attitude P → position. Шаг: Acro или Stabilized, резкие короткие движения стиком, лог, график `vehicle_rates_setpoint` против `vehicle_angular_velocity` в Flight Review. Перелёт — меньше K или больше D; медленный отклик — больше K; дрейф — больше I. Тот же метод и те же метрики, что в модуле про PID по данным.

### Умолчания и что они значат
`MC_ROLLRATE_P` = 0.15, `I` = 0.2, `D` = 0.003, `K` = 1.0, `FF` = 0 (выход — безразмерный момент на 1 рад/с ошибки); `MC_ROLL_P` = 4.0 (угловая скорость на радиан ошибки угла → 1/с; до 1.17 — 6.5), `MC_YAW_P` = 2.8; позиция: `MPC_XY_P` = 0.95 (1/с), скорость → ускорение `MPC_XY_VEL_P_ACC` = 1.8, `I_ACC` = 0.4, `D_ACC` = 0.2; `MPC_Z_P` = 1.0. Газ висения `MPC_THR_HOVER` = 0.5 (норм.) — уточняется оценщиком тяги висения (`HTE_*`, hover thrust estimator). Фильтры: `IMU_GYRO_CUTOFF` = 40 Гц, `IMU_DGYRO_CUTOFF` = 20 Гц (до 1.17 — 30), частота контура `IMU_GYRO_RATEMAX` = 800 Гц у мультиротора (airframe поднимает умолчание параметра 400), статический notch `IMU_GYRO_NF0_FRQ`/`BW` (0 = выкл, BW 20 Гц), динамический по ESC RPM `IMU_GYRO_DNF_EN` (битмаска: бит 0 — по ESC RPM, бит 1 — по бортовому FFT `IMU_GYRO_FFT_EN`), `IMU_GYRO_DNF_MIN` = 25 Гц. Air-mode `MC_AIRMODE` (0 выкл, 1 roll/pitch, 2 + yaw). Все отличия умолчаний 1.15 и 1.16 от 1.17 собраны в таблице перехода в px4-intro.

Единицы важны: ошибка в рад/с, выход — доля максимального момента. P = 0.15 означает: ошибка 1 рад/с (57°/с) даёт 15% момента. Для сравнения с Betaflight (безразмерные «45») — только качественно, через модуль «Теория управления» (ζ, запас по фазе).

### Умолчания по всем осям (v1.17.0; в v1.18.0 те же)
В 1.18 к контуру угла добавлен необязательный feed-forward от эталонной модели второго порядка: `MC_REF_FF` (0…1, по умолчанию 0 — прежнее поведение), собственная частота `MC_REF_W_N` (50 рад/с) и предел `MC_REF_FF_MAX` (100 °/с) (`mc_att_control_params.yaml`, v1.18.0). Таблица ниже — без него.

Правило чтения: вход — ось и уровень каскада; по таблице — с какого числа стартует универсальный airframe (4001 Generic Quadcopter усиления не переопределяет; готовые airframe конкретных рам могут); проверка — `param show MC_ROLLRATE*` (и `MC_PITCHRATE*`, `MC_YAWRATE*`; `*` допускается только в конце фильтра) в консоли совпадает с таблицей, пока ты ничего не менял.

| Уровень | Крен (roll) | Тангаж (pitch) | Рыскание (yaw) | Единица |
|---|---|---|---|---|
| rate P / I / D | 0.15 / 0.2 / 0.003 | 0.15 / 0.2 / 0.003 | 0.2 / 0.1 / 0 | доля момента на рад/с |
| rate K / FF | 1.0 / 0 | 1.0 / 0 | 1.0 / 0 | — |
| предел интеграла (`MC_RR_INT_LIM`, `MC_PR_INT_LIM`, `MC_YR_INT_LIM`) | 0.30 | 0.30 | 0.30 | доля момента |
| attitude P (`MC_ROLL_P`, `MC_PITCH_P`, `MC_YAW_P`) | 4.0 (до 1.17 — 6.5) | 4.0 (до 1.17 — 6.5) | 2.8 | 1/с |
| предел угловой скорости в режимах с углом (`MC_ROLLRATE_MAX`, `MC_PITCHRATE_MAX`, `MC_YAWRATE_MAX`) | 220 | 220 | 200 | °/с |

Рыскание отличается намеренно: D = 0, P больше, I меньше, а `MC_YAW_WEIGHT` = 0.4 (0…1) понижает приоритет рыскания относительно крена и тангажа в контуре ориентации; на само усиление `MC_YAW_P` он не влияет. Причина — у мультиротора по рысканию намного меньше управляющего момента (он создаётся разностью реактивных моментов пропов), а для висения рыскание не критично.

Вертикальный и горизонтальный контуры позиции (`mc_pos_control`):

| Параметр | Умолчание | Что задаёт |
|---|---|---|
| `MPC_Z_P` | 1.0 1/с | ошибка высоты → уставка вертикальной скорости |
| `MPC_Z_VEL_P_ACC` / `I_ACC` / `D_ACC` | 4.0 / 2.0 / 0 | ошибка вертикальной скорости → ускорение (м/с² на м/с) |
| `MPC_XY_VEL_P_ACC` / `I_ACC` / `D_ACC` | 1.8 / 0.4 / 0.2 | то же по горизонтали |
| `MPC_ACC_HOR` | 3 м/с² | ускорение в автоматических режимах; в ручных — только при `MPC_POS_MODE` = 4 (Acceleration based, умолчание) |
| `MPC_ACC_UP_MAX` / `MPC_ACC_DOWN_MAX` | 4 / 3 м/с² | пределы вертикального ускорения |
| `MPC_JERK_AUTO` | 4 м/с³ | рывок в автоматических режимах: меньше — плавнее Mission и Return |
| `MPC_JERK_MAX` | 8 м/с³ | рывок в Position и Altitude (только при `MPC_POS_MODE` = 4); максимум 500 фактически снимает ограничение |
| `MPC_VEL_MANUAL` | 10 м/с | скорость на полном стике в Position (должна быть меньше `MPC_XY_VEL_MAX` = 12) |

Порядок «сначала rate, потом attitude, потом скорость, потом позиция» относится и к этой таблице: если в Position аппарат качается, сначала проверяют `MPC_XY_VEL_P_ACC`, а не `MPC_XY_P`. С 1.16 (и в 1.17) у `MPC_POS_MODE` два значения — 3 Smoothed velocity из 1.15 удалено: 0 — Direct velocity (стик прямо в скорость, для тюнинга контура скорости) и 4 — Acceleration based.

Рейты и экспонента Acro для FPV-пилота (`MC_ACRO_R_MAX` и др., умолчание 100 °/с — в несколько раз медленнее привычного Betaflight), отклик стиков в Position (`MPC_VEL_MANUAL`, `MPC_MAN_Y_MAX`, `MAN_DEADZONE`) и подстройка усиления ручкой пульта в полёте (`RC_MAP_PARAM1…3`, QGC → Parameters → Set RC to Param) разобраны в `px4-rc-tuning`. Правило для этого модуля: ручкой пульта крутят один параметр за полёт — `MC_ROLLRATE_K` / `MC_PITCHRATE_K` или `MPC_XY_VEL_P_ACC`, а найденное значение после посадки проверяют записью step response, как в шаге 4.

### Autotune подробнее
`MC_AT_EN` = 1 включает модуль `mc_autotune_attitude_control` (на полётнике умолчание 0: поставить 1 и перезагрузить; SITL ставит 1 сам); запуск — из QGC (PID Tuning → Autotune), тумблера на пульте для autotune мультиротора нет (`FW_AT_MAN_AUX` — только для самолёта) в Altitude/Position в висении при штиле; модуль инжектирует возбуждение амплитудой `MC_AT_SYSID_AMP` (0.7) по каждой оси, идентифицирует модель rate-контура и считает коэффициенты: записывает `MC_*RATE_P/I/D` (множитель `MC_*RATE_K` ставит 1.0) и `MC_ROLL_P`/`MC_PITCH_P`/`MC_YAW_P` (`saveGainsToParams()` в `src/modules/mc_autotune_attitude_control/mc_autotune_attitude_control.cpp`); `MC_AT_APPLY` (0 — не применять, 1 — после посадки, 2 — сразу в полёте) — умолчание 1. После — контрольный полёт и Flight Review: отклик без перелёта > 10%, D без шума. Autotune не настраивает фильтры и не лечит вибрации — их делают **до** (спектр!).

{{diagram:px4-tune-order-flow|Фильтры настраивают до всего; autotune заменяет ручной rate и attitude P, а контуры скорости и позиции настраивают уже после него — сначала скорость.}}

### Разобранный пример: 7" 6S, 1.4 кг
Старт: airframe Generic Quad, `CA_ROTOR_COUNT` = 4, проверить `IMU_GYRO_RATEMAX` = 800 Гц (airframe уже поднял его с 400), `IMU_GYRO_CUTOFF` 40 → 80, `IMU_DGYRO_CUTOFF` 20 → 40 (до 1.17 умолчание было 30); eRPM от ESC: bidirectional DShot (в 1.18 — `PWM_AUX_TIMn` = −6/−7/−8 у группы моторов; в 1.16–1.17 — `DSHOT_BIDIR_EN` = 1; работает на поддерживаемых платах и выходах FMU) или телеметрия ESC по UART (`DSHOT_TEL_CFG` — в 1.15 единственный вариант), `IMU_GYRO_DNF_EN` = 1; `MPC_THR_HOVER` уточнится оценщиком HTE; первый полёт Stabilized — `MC_ROLLRATE_K` 1.0 → 0.7 если качает; autotune; `MPC_XY_VEL_MAX` под задачу. Лог → Flight Review: rate tracking, спектр, `vehicle_torque_setpoint` без насыщения.

{{diagram:px4-cascade|Каскад PX4: позиция → скорость → ориентация → угловая скорость → аллокатор, с параметрами каждого уровня.}}

### Место в системе

- **Получает:** отфильтрованный гироскоп `vehicle_angular_velocity` и оценку EKF2 (`px4-architecture`); обороты ESC для динамического notch (`f-motors-esc`); геометрию `CA_*` (`px4-setup-scratch`); теорию каскада и запаса по фазе (`ctl-theory`).
- **Отдаёт:** моменты и тягу — в control allocation (`ctl-allocation`); отклик на уставки позиции и скорости — режиму Offboard (`px4-ros2`); лог для тех же метрик step response, что в `bf-pid`.
- **Если ошибиться здесь:** запустил autotune при вибрациях и без фильтров → шум в D, горячие моторы; сначала спектр (`ctl-signals`). Обновил прошивку на умолчаниях → `MC_ROLL_P` молча стал 4.0 вместо 6.5 → контур угла мягче, уставки Offboard отрабатываются иначе; таблица перехода — `px4-intro`.

## practice
### Шаг 1. Сначала аллокация
Без пропов: Actuators в QGC — геометрия соответствует раме, каждый мотор крутится в нужную сторону по тесту.

### Шаг 2. Фильтры по логу
Полёт с логом, Flight Review → спектрограмма гироскопа. `IMU_GYRO_CUTOFF` и `IMU_DGYRO_CUTOFF` — так, чтобы срезать шум моторов, не задевая управление.

### Шаг 3. Autotune
`MC_AT_EN` = 1 и перезагрузка (на полётнике умолчание 0), затем QGC → PID Tuning → Autotune. Тумблера на пульте у autotune мультиротора нет. Висение, запуск, не трогать стики до завершения, посадка. Проверить, что новые `MC_*RATE_*` применены.

### Шаг 4. Проверка
Step response в Flight Review до и после: перелёт и время установления. При необходимости — ручная подстройка K/D на 10–20%.

### Что должно получиться и что записать
- **Шаг 1.** В QGC → Actuators схема рамы совпадает с реальной, а тест каждого мотора крутит именно тот мотор и в ту сторону, что на картинке. Ошибка здесь не лечится никаким тюнингом.
- **Шаг 2.** На спектрограмме гироскопа в Flight Review полосы шума моторов поднимаются вместе с газом. Частота среза `IMU_GYRO_CUTOFF` должна быть ниже этих полос, но заметно выше полосы управления (единицы–десятки герц). Запиши значения до и после и частоту полосы моторов на висении.
- **Шаг 3.** Autotune пишет новые коэффициенты `MC_ROLLRATE_*`, `MC_PITCHRATE_*` только после успешного завершения. Сравни их с умолчанием и запиши обе версии.
- **Шаг 4.** В Flight Review есть оценка переходной характеристики (step response) контура угловых скоростей. Запиши перелёт (%) и время выхода на уровень (мс) до и после.

### Лабораторная
В SITL: записать step response на гейнах по умолчанию, намеренно удвоить `MC_ROLLRATE_K`, записать снова, объяснить разницу по графику.

Ожидаемая картина: с удвоенным `MC_ROLLRATE_K` (общий множитель P, I и D контура) отклик быстрее, перелёт больше, а колебания после ступеньки затухают дольше и на более высокой частоте — запас по фазе уменьшился (модуль «Теория управления»). Ступеньки подавай резкими движениями стика по крену в Stabilized или Acro виртуальным джойстиком QGC, одинаково в обоих полётах.

Самопроверка: лабораторная выполнена, когда в Actuators схема рамы совпала с реальной и в тесте без пропов каждый мотор крутится тот и в ту сторону, step response записан с гейнами по умолчанию и при удвоенном `MC_ROLLRATE_K` на одинаковых резких ступеньках — с числами перелёта (%) и времени выхода (мс), и эти числа совпадают с ожидаемой картиной выше: с удвоенным K отклик быстрее, перелёт больше, колебания затухают дольше и на более высокой частоте.

**Эталон для самопроверки.** Верное объяснение: `MC_ROLLRATE_K` — общий множитель P, I и D контура, его удвоение поднимает усиление и уменьшает запас по фазе. Типичные неверные: (1) разницы между записями почти нет — ступеньки подавались плавно или по-разному: нужны резкие одинаковые движения стика по крену в Stabilized или Acro; (2) при удвоенном K перелёт получился меньше — перепутаны записи или изменён не тот параметр: проверь значение `MC_ROLLRATE_K` перед полётом.

## diagnostics
- **Симптом:** быстрые осцилляции после autotune
  - Возможная причина: шум не отфильтрован, autotune подобрал гейны под шумный сигнал.
  - Что сделать: фильтры, повторный autotune.
- **Симптом:** в Position аппарат медленно «качается»
  - Возможная причина: внешний контур (`MPC_*`) слишком агрессивен при слабом внутреннем.
  - Что сделать: сначала rate/attitude, потом position.
- **Симптом:** горячие моторы
  - Возможная причина: высокий D на шумном гироскопе.
  - Что сделать: снизить D, поднять фильтрацию, проверить механику.
- **Симптом:** мотор крутится не туда в тесте
  - Возможная причина: геометрия или направление в Actuators.
  - Что сделать: исправить `CA_ROTOR<n>_KM`/направление, перепроверить без пропов.
- **Симптом:** autotune прерывается
  - Возможная причина: ветер, вибрации, слишком низкий начальный тюн, недостаточно высоты.
  - Что сделать: штиль, спектр и notch до autotune, `MC_ROLLRATE_K` ниже, высота 5+ м.
- **Симптом:** медленные колебания позиции в Position mode
  - Возможная причина: `MPC_XY_P`/`MPC_XY_VEL_*` выше, чем позволяет качество GPS/задержка.
  - Что сделать: проверить EKF (innovations), снизить `MPC_XY_VEL_P_ACC`, затем `MPC_XY_P`.
