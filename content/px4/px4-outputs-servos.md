## summary
Экран Actuators в QGroundControl и то, что за ним стоит в коде PX4 1.18.0: как значение проходит путь от контроллера до пина, какие функции можно повесить на выход и под какими номерами, что значат `PWM_AUX_MINn` / `MAXn` / `DISn` / `FAILn` / `CENTn` / `REV` / `TIMn`, почему серва и мотор DShot не живут в одной группе таймера, чем MAIN (IO) отличается от AUX (FMU), как описать рулевые поверхности через `CA_SV_*` и чем в PX4 заменяют реле. После модуля ты по `timer_config.cpp` платы раскладываешь моторы, сервы и триггер камеры по выходам и считаешь импульс сервы так, как его считает `mixer_module`. Лабораторная — без железа и симулятора: план выходов для fmu-v6x, расчёт микросекунд, знаки `CA_SV_CSn_TRQ_*` и разбор параметров с ошибками, ответы сверяются с эталоном на странице.

## theory
### Путь значения: от момента до импульса
В PX4 нет «миксера моторов» в одном месте. Цепочка из четырёх звеньев:

1. **Контроллеры** выдают нормированный момент по трём осям и тягу.
2. **`control_allocator`** по геометрии `CA_*` делит их между исполнительными устройствами и публикует два топика: `actuator_motors` (0…1, у реверсивных −1…1, NaN — «мотор стоит») и `actuator_servos` (−1…+1). Математика деления — в модуле ctl-allocation, здесь она не повторяется.
3. **`mixer_module`** — библиотека внутри каждого драйвера выходов. Для каждого выхода она смотрит на его функцию, берёт значение у нужного источника и переводит −1…+1 в число для драйвера.
4. **Драйвер** (`pwm_out`, `dshot`, `px4io`, `uavcan`) передаёт число в таймер MCU или в шину.

{{diagram:px4-outputs-pipeline|Аллокатор знает только «Motor 3» и «Servo 2»; на каком пине они окажутся, с какими пределами и в каком состоянии арма — решает mixer_module внутри драйвера выходов.}}

Перевод в микросекунды — `output_limit_calc_single()`:

- значение NaN → `DIS`;
- если у выхода стоит бит в `REV`, значение меняет знак;
- обычный случай: `мкс = MIN + (v + 1) / 2 · (MAX − MIN)`, результат округляется (`lroundf`; в 1.18 — уже в драйвере, `PWMOut.cpp`);
- **с 1.17**, если функция — Servo, Gimbal или Landing Gear Wheel и `CENTn` задан (800…2200): две прямые, `v < 0` → `MIN + (v + 1) · (CENT − MIN)`, `v ≥ 0` → `CENT + v · (MAX − CENT)`.

У моторов аллокатор отдаёт 0…1, `mixer_module` сначала растягивает это в −1…+1 (`2·v − 1`), поэтому 0 % тяги даёт `MIN`, а не `DIS`.

### Функции выходов
Каждому выходу назначается одна функция — параметр `<префикс>_FUNCn`. Номера взяты из `output_functions.yaml`; менять их запрещено комментарием в файле, поэтому они одинаковы в 1.15–1.17.

| Функция | Номер | Источник значения | Примечание |
|---|---|---|---|
| Disabled | 0 | — | импульса нет вообще |
| Constant Min / Constant Max | 1 / 2 | константа −1 / +1 | выход держит `MIN` или `MAX` |
| Motor 1…12 | 101…112 | `actuator_motors` | в prearm не работает |
| Servo 1…15 | 201…215 | `actuator_servos` | поверхности, затем tilt-сервы; до 1.18 — Servo 1…8 (201…208) |
| Peripheral via Actuator Set 1…6 | 301…306 | `MAV_CMD_DO_SET_ACTUATOR` | «реле» PX4 |
| Landing Gear | 400 | топик `landing_gear` | выпущено −1, убрано +1 |
| Parachute | 401 | константа −1 | при termination +1 |
| RC Roll / Pitch / Throttle / Yaw / Flaps | 402…406 | `manual_control_setpoint` | сквозной канал пульта |
| RC AUX 1…6 | 407…412 | `RC_MAP_AUX1…6` | сквозной AUX-канал |
| Gimbal Roll / Pitch / Yaw | 420…422 | `gimbal_controls` | при `MNT_MODE_OUT` = 0 |
| Gripper | 430 | топик `gripper` | отпустить −1, схватить +1 |
| Landing Gear Wheel | 440 | `landing_gear_wheel` | носовое колесо |
| IC Engine Ignition / Throttle / Choke / Starter | 450…453 | управление ДВС | с 1.16 |
| Camera Trigger | 2000 | драйвер `camera_trigger` | только пины FMU |
| Camera Capture | 2032 | вход: обратная связь камеры | только пины FMU |
| PPS Input | 2064 | вход PPS от GNSS | только пины FMU |
| RPM Input | 2070 | вход датчика оборотов | только пины FMU, с 1.16 |

Источник «Servo n» — не конкретная серва, а n-й исполнитель типа «серва» в геометрии: у самолёта Servo 1 — это поверхность `CA_SV_CS0`, у тилтротора с четырьмя поверхностями и двумя tilt-сервами Servo 5 и 6 — наклон моторов (аллокатор добавляет сначала поверхности, потом tilt).

### Параметры выхода
Префикс зависит от платы. На плате с IO-процессором (Pixhawk 6X, 6C) выходы IO — `PWM_MAIN_*`, выходы FMU — `PWM_AUX_*`. На плате без IO со своей прошивкой (Kakute H7, Pixhawk 6U) выходы FMU называются `PWM_MAIN_*`, а `PWM_AUX_*` нет. Исключение — платы без IO, которые шьются прошивкой «старшей сестры» с IO (Pixhawk 6C Mini на fmu-v6c): там выходы FMU остаются `PWM_AUX_*`, хотя на корпусе написано MAIN. Смотри не на корпус, а на вкладки экрана Actuators. Выходы DroneCAN — отдельные наборы `UAVCAN_EC_*` и `UAVCAN_SV_*` (модуль el-dronecan).

| Параметр | Умолчание | Диапазон | Что делает |
|---|---|---|---|
| `PWM_AUX_FUNCn` | 0 | номера из таблицы функций | функция выхода n |
| `PWM_AUX_DISn` | 1000 | 800…2200 мкс | значение без арма и при kill |
| `PWM_AUX_MINn` | 1000 | 800…1400 мкс | значение при −1 |
| `PWM_AUX_MAXn` | 2000 | 1600…2200 мкс | значение при +1 |
| `PWM_AUX_CENTn` | −1 | −1, 800…2200 мкс | центр сервы; −1 — прямая от MIN до MAX. **Новый в 1.17**, на выходах IO его нет |
| `PWM_AUX_FAILn` | −1 | −1, 800…2200 мкс | значение при flight termination; −1 — по функции |
| `PWM_AUX_REV` | 0 | битовая маска | бит n−1 разворачивает диапазон выхода n |
| `PWM_AUX_TIMn` | 400 | −8, −7, −6 (с 1.18), −5, −4, −3, −1, 50, 100, 200, 400, любое > 0 | протокол группы таймера с индексом n |

`FAILn` = −1 означает «по функции»: Constant Min → `MIN`, Constant Max и Parachute → `MAX`, Servo → значение 0 (середина между `MIN` и `MAX` или `CENT`), всё остальное, включая моторы, → `DIS`. Значения `TIMn`: −8 BDShot150, −7 BDShot300, −6 BDShot600 (bidirectional, с 1.18), −5 DShot150, −4 DShot300, −3 DShot600, −1 OneShot, 50/100/200/400 — PWM с этой частотой в герцах; любое другое положительное число — своя частота PWM. Смена `TIMn` требует перезагрузки. В 1.15 было ещё −2 = DShot1200; в 1.16 значение убрано.

Если `MIN` записан больше `MAX`, прошивка молча меняет их местами: развернуть серву так не получится, для этого есть `REV`.

### Что прошивка выставляет сама
Не QGC, а драйвер (`PWMOut::update_params`, то же в `px4io`) — в тот момент, когда функция выхода при работающей прошивке меняется с Disabled на Motor или Servo. Первый проход после загрузки пропускается: функции, которые уже записаны airframe-файлом или сохранены до перезагрузки, автоматика не трогает. Обратная сторона: при загрузке файла параметров в чистую прошивку функции тоже меняются «на ходу», и драйвер может записать свои числа в `MIN`/`MAX` моторов и `DIS` серв поверх значений из файла — результат зависит от порядка, в котором приходят параметры. После загрузки сверь эти три параметра с файлом. Что именно записывается:

- **Motor** → `MINn` = 1100, `MAXn` = 1900. `DISn` остаётся 1000.
- **Servo** → `DISn` = 1500. `MINn` и `MAXn` остаются 1000 и 2000, `CENTn` — −1. Частота группы переключается с 400 на 50 Гц, только если ни у одного выхода этой группы раньше не было функции и `TIMn` был ровно 400.

Отсюда частая ошибка: в группу, где уже стоял мотор, добавили серву — частота осталась 400 Гц. Аналоговая серва на 400 Гц греется и гудит.

### Группы таймеров, MAIN и AUX
Несколько выходов висят на одном аппаратном таймере: общий счётчик и общий период. Поэтому протокол и частота задаются на группу, а не на выход — одним параметром `TIMn`. Состав групп зашит в `boards/<производитель>/<плата>/src/timer_config.cpp`, QGC рисует группы по этим данным. DShot доступен только в группах, у таймера которых в `timer_config.cpp` описан канал DMA; для остальных значения DShot в списке `TIMn` не показываются.

{{diagram:px4-outputs-timers-v6x|У fmu-v6x на FMU три группы выходов — 4 + 2 + 2, DShot умеют первые две; три сервы и триггер камеры в оставшиеся четыре выхода не помещаются, третью серву приходится выносить на MAIN.}}

| | MAIN на плате с IO (`px4io`) | AUX — выходы FMU (`pwm_out`, `dshot`) |
|---|---|---|
| Протоколы | PWM 50…400 Гц, OneShot | PWM, OneShot, DShot150/300/600, с 1.18 — BDShot150/300/600 |
| DShot, bidirectional DShot | нет | да, в группах с DMA |
| Camera Trigger / Capture, PPS, RPM | нет | да |
| `CENTn` (с 1.17) | нет | да |
| Задержка | выше: значение идёт FMU → IO по UART | ниже |
| Если FMU завис при арме | через 0.5 с IO сам выдаёт `FAILn` (при `CBRK_FLIGHTTERM` = 0) | подстраховки нет: выходами управляет сам FMU |

Куда подключать ESC на Pixhawk с двумя рядами выходов: DShot — только в AUX (на корпусе Pixhawk 6X это «FMU PWM OUT», MAIN — «I/O PWM OUT»), PWM-ESC можно и в MAIN, но документация советует AUX из-за меньшей задержки. Сервы самолёта часто держат на MAIN: там их не задевает раскладка DShot, но нет `CENTn`.

Триггер камеры, назначенный на выход, забирает таймер целиком: остальные выходы этой группы нельзя занять мотором, сервой или захватом кадра.

### DShot и телеметрия ESC
| Параметр | Умолчание | Смысл |
|---|---|---|
| `DSHOT_MIN` | 0.055 | минимальная команда при арме, доля от полной (в 1.15–1.16 единица подписана как %) |
| `PWM_AUX_TIMn` = −6 / −7 / −8 | — | bidirectional DShot (BDShot600 / 300 / 150): eRPM по сигнальному проводу, выбирается **по группе таймера** (с 1.18; в 1.16–1.17 — общий `DSHOT_BIDIR_EN`), нужна перезагрузка |
| `DSHOT_BIDIR_EDT` | 0 | Extended DShot Telemetry (с 1.18): в кадрах eRPM приходят температура, напряжение и ток ESC; перезагрузка |
| `DSHOT_TEL_CFG` | 0 (Disabled) | порт UART для телеметрии ESC по отдельному проводу; номера портов — в `px4-hardware-peripherals` |
| `DSHOT_3D_ENABLE` | 0 | 3D-режим: диапазон делится на два направления, `DSHOT_MIN` ставят в 0 |
| `DSHOT_3D_DEAD_L` / `DSHOT_3D_DEAD_H` | 1000 / 1000 | мёртвая зона 3D в единицах 0…1999 |
| `DSHOT_MOT_POL1…12` | 14 | число магнитов ротора, свой у каждого мотора: пересчёт eRPM → RPM (до 1.18 — один `MOT_POLE_COUNT`; при обновлении его значение копируется во все 12) |
| `CA_R_REV` | 0 | маска реверсивных моторов (бит 0 — Motor 1) |

Что нужно знать:

- В группе DShot параметры `MINn` / `MAXn` / `DISn` / `FAILn` не действуют: драйвер ставит свои значения 1…1999, «стоп» = 0, минимум = `DSHOT_MIN` × 1999 (при 0.055 — 109).
- Все группы DShot работают на одной скорости. Если в двух группах выбраны разные, драйвер 1.18 пишет «Mixed DShot frequencies across timers, using freq: …» и берёт скорость последней группы (в 1.17 — «Only supporting a single frequency» с правкой параметра).
- **Bidirectional DShot.** В 1.15 его нет вообще — только телеметрия по UART (`DSHOT_TEL_CFG`). В 1.16–1.17 его включал `DSHOT_BIDIR_EN`, и в коде STM32 DShot тогда оставался только у таймера с индексом 0 (на fmu-v6x и fmu-v6c — AUX1–4; моторы 5–6 гексакоптера сигнала не получали). В 1.18 протокол выбирается на группу: `PWM_AUX_TIMn` = −6/−7/−8 — BDShot600/300/150. Драйвер STM32 запускает каждую группу по очереди со своим каналом DMA и в каждом цикле читает ответ одного канала группы по кругу (`dshot.c`, `up_dshot_init`): обороты обновляются у каждого мотора, но реже, чем выходов в группе. Ограничение «только таймер 0» снято; группа без DMA (`DMA{…}` в `timer_config.cpp`) DShot по-прежнему не берёт. Работает ли конкретная плата и ESC — проверяй `dshot status` на столе (не проверено на железе).
- С `DSHOT_BIDIR_EDT` = 1 (1.18) bidirectional DShot приносит, кроме оборотов, температуру, напряжение и ток (Extended DShot Telemetry, если ESC её умеет: Bluejay, AM32; у штатного BLHeli_S нет ни bidirectional DShot, ни EDT). Без EDT обороты — по сигнальному проводу, остальное — по UART-телеметрии.
- RPM считается целочисленно: `RPM = eRPM / (DSHOT_MOT_POLn / 2)` (`DShot.cpp`, v1.18.0; до 1.18 — общий `MOT_POLE_COUNT`). При неверном числе полюсов обороты в `esc_status` врут ровно в отношение пар полюсов, и динамический notch встаёт не на ту частоту.

Что за протоколы и что такое eRPM — в модуле f-esc-firmware.

### Сервы и рулевые поверхности: `CA_SV_*`
Поверхности описываются в блоке Geometry того же экрана. Индексы начинаются с нуля: `CA_SV_CS0_*` — поверхность, которой управляет функция Servo 1.

| Параметр | Умолчание | Значения |
|---|---|---|
| `CA_SV_CS_COUNT` | 0 | 0…8 поверхностей |
| `CA_SV_CSn_TYPE` | 0 | 1 Left Aileron, 2 Right Aileron, 3 Elevator, 4 Rudder, 5 Left Elevon, 6 Right Elevon, 7 Left V-Tail, 8 Right V-Tail, 9 Left Flap, 10 Right Flap, 11 Airbrake, 12 Custom, 13 Left A-tail, 14 Right A-tail, 15 Single Channel Aileron, 16 Steering Wheel, 17 Left Spoiler, 18 Right Spoiler |
| `CA_SV_CSn_TRQ_R` / `_TRQ_P` / `_TRQ_Y` | 0 | эффективность по крену / тангажу / рысканию; QGC подставляет по типу |
| `CA_SV_CSn_TRIM` | 0 | −1…1: сдвиг нейтрали. В 1.17 для PWM-серв заменён на `CENTn` |
| `CA_SV_CSn_FLAP` | 0 | −1…1: отклонение при полностью выпущенных закрылках |
| `CA_SV_CSn_SPOIL` | 0 | −1…1: отклонение при полностью выпущенных спойлерах |
| `CA_SVn_SLEW` | 0 | 0…10 с на полный ход сервы n; 0 — без ограничения |
| `CA_SV_TL_COUNT` | 0 | 0…4 tilt-сервы |
| `CA_SV_TLn_MINA` / `_MAXA` | 0 / 90 | −90…90°: угол наклона при минимуме и максимуме сервы; 0 — вверх |
| `CA_SV_TLn_TD` | 0 | 0 — наклон вперёд, 90 — вправо |
| `CA_SV_TLn_CT` | 1 | 0 None, 1 Yaw, 2 Pitch, 3 Yaw and Pitch — участвует ли наклон в управлении |

Мотор привязывается к tilt-серве параметром `CA_ROTORn_TILT` (0 — нет, 1…4 — Tilt 1…4).

**Знак отклонения.** Определение одно — в документации (Control Surface Deflection Convention) и в комментарии `module.yaml`: положительная команда отклоняет горизонтальную поверхность задней кромкой вверх (элероны, элевоны, руль высоты), вертикальную — вправо (руль направления), смешанную — вверх/вправо (V- и A-хвост). Закрылки, спойлеры и воздушный тормоз работают в одну сторону: 0 — убрано, 1 — полное отклонение. Механику сервы под это правило подгоняют битом `REV`, а не знаками в геометрии.

**Коэффициенты.** `TRQ_*` — столбец матрицы эффективности: какой момент даёт положительное отклонение. Моменты считаются в осях FRD: крен «+» — правое крыло вниз, тангаж «+» — нос вверх, рыскание «+» — нос вправо. Знак выводится из правила, модуль — 1/N, где N — число поверхностей на оси. Для элевонов B = [[−0.5, 0.5], [0.5, 0.5]], обратная матрица даёт микс: левый = −крен + тангаж, правый = +крен + тангаж. Удвоишь коэффициенты — отклонения уменьшатся вдвое: числа стоят в матрице, которую обращают.

**Нейтраль.** До 1.17 сдвиг нейтрали задавал `CA_SV_CSn_TRIM` — в нормированных единицах, до реверса и пересчёта в микросекунды. В 1.17 для PWM-серв на выходах FMU появился `CENTn` в микросекундах. Совмещать нельзя: если хотя бы один `PWM_MAIN_CENTn` или `PWM_AUX_CENTn` отличен от −1, прошивка обнуляет все ненулевые `CA_SV_CSn_TRIM` и пишет предупреждение «…TRIM is reset to 0 as PWM CENTER is used». Формула переноса из документации: `CENT = MIN + (MAX − MIN) / 2 · (1 + TRIM)`. На выходах IO параметра `CENTn` нет, там остаётся `TRIM`.

Питание серв — как в модуле bf-servos-pwm: отдельный BEC на шину серв, общая земля, шина 5 В полётника серву не кормит. У Pixhawk плюсовая шина рейки выходов от модуля питания не запитана: без BEC серва не получит ничего.

### Disarmed, prearmed, armed, failsafe
| Состояние | Когда | Моторы | Сервы и прочие функции |
|---|---|---|---|
| Disarmed | нет арма, prearm выключен | `DIS` | `DIS` |
| Prearmed | `COM_PREARM_MODE` = 1 и нажата кнопка safety; = 2 — всегда, через 5 с после загрузки | `DIS` | рабочее значение |
| Armed | арм | рабочее значение | рабочее значение; NaN → `DIS` |
| Kill, lockdown | тумблер kill; ожидание броска при throw launch | `DIS` | `DIS` |
| Termination | flight termination | `FAIL` (по умолчанию `DIS`) | `FAIL` (серва — середина, парашют — `MAX`) |

На PWM и IO первые 0.5 с после арма каждый выход плавно идёт от `DIS` к рабочему значению; у DShot разгона нет. `COM_PREARM_MODE` по умолчанию 0: без арма серва стоит в `DIS`, стики её не двигают — и выходы полезной нагрузки тоже молчат. Самолёту ставят 2, чтобы проверить рули перед взлётом. Когда и чем включается termination и чем он отличается от kill — модуль px4-safety-return. `FAILn` — не реакция на потерю RC: при RC loss выходы продолжают работать, меняется режим полёта.

### Полезная нагрузка: что вместо реле
Параметров реле, как в ArduPilot (`RELAYn_*`, модуль `ap-outputs`), в PX4 нет. Любая нагрузка — это функция на выходе.

| Задача | Функция | Чем управляется | Настройка |
|---|---|---|---|
| Сброс, свет, питание из миссии или с companion | Peripheral via Actuator Set 1…6 | `MAV_CMD_DO_SET_ACTUATOR` (187): param1…6 = −1…1, NaN — не менять, param7 = 0 | до первой команды выход стоит в `DIS` |
| Тумблер на пульте | RC AUX 1…6 | канал из `RC_MAP_AUXn` | при потере RC выход уходит в `DIS` |
| Захват | Gripper | `MAV_CMD_DO_GRIPPER` (211): param2 = 0 отпустить, 1 схватить | `PD_GRIPPER_TYPE` = 0 (Servo), `PD_GRIPPER_TO` = 1 с (в 1.15 — 3 с и нужен `PD_GRIPPER_EN` = 1, удалённый в 1.16) |
| Шасси | Landing Gear | тумблер `RC_MAP_GEAR_SW`, автоматика взлёта и посадки | убрано = `MAX`, выпущено = `MIN` |
| Парашют | Parachute | flight termination | `MIN` в полёте, `MAX` при termination |

Логический выход «включить/выключить» получается из PWM: `MIN` и `MAX` — два положения, ключ или реле с PWM-входом стоит снаружи. Peripheral-выходы в миссии — пункт «Set actuator» в QGC; PX4 не ждёт срабатывания и сразу идёт к следующей точке. Два ограничения: без арма и без prearm команда запоминается, но выход остаётся в `DIS`; модуль захвата `payload_deliverer` собран не во все прошивки — в 1.17.0 он есть в сборках fmu-v5x, ARK FMUv6X и SITL, а в px4/fmu-v6x и fmu-v6c его нет (включается своей сборкой через `boardconfig`).

### Проверка без арма: `actuator_test`
Синтаксис из исходника команды:

- `actuator_test set -m <1…8> -v <значение> [-t <секунд>]` — мотор; `-s <1…8>` — серва; `-f <номер функции>` — любая функция.
- Значение −1…1; у мотора 0…1 (0 = `MIN`, а не `DIS`). Без `-t` команда держит выход до нажатия Enter.
- `actuator_test iterate-motors` — по очереди все моторы на 15 % по 0.4 с; `iterate-servos` — все сервы на +0.3.

Пока идёт тест, остальные выходы стоят в `DIS`; к значению сервы прибавляется её trim. При арме и при kill тест не действует. Слайдеры QGC шлют `MAV_CMD_ACTUATOR_TEST` (310), и commander отвечает **DENIED** в двух случаях: аппарат заармлен; есть кнопка safety и она не нажата (`Commander.cpp`, `handleCommandActuatorTest`). Это и есть «Motor test command denied». Выключателя теста `COM_MOT_TEST_EN` (до 1.18, умолчание 1) больше нет — тест разрешён всегда. Таймаут одной команды по MAVLink — не больше 3 с. Консольная `actuator_test` публикует команду напрямую и эти проверки обходит — пропеллеры снимают до неё. Состояние выходов: `pwm_out status`, `dshot status`, `px4io status`.

### Место в системе

- **Получает:** матрицу эффективности от аллокатора (`ctl-allocation`); флаги armed, prearmed, kill, termination от commander (`px4-safety-return`); протокол ESC и eRPM (`f-esc-firmware`); первый проход экрана Actuators (`px4-setup-scratch`); номера портов UART и включение выходов DroneCAN (`px4-hardware-peripherals`); схему питания серв (`bf-servos-pwm`).
- **Отдаёт:** импульсы и кадры DShot моторам и сервам; обороты в `esc_status` — динамическому notch и детектору отказа мотора (`px4-control`); выходы нагрузки — миссиям и companion; значения `FAILn` — flight termination (`px4-safety-return`).
- **Если ошибиться здесь:** серва в группе DShot или на 400 Гц — отказ руля в полёте; неверный знак `CA_SV_CSn_TRQ_*` или лишний бит `REV` — стабилизация раскачивает самолёт (`ctl-allocation`); `DSHOT_MOT_POLn` не по мотору — notch мимо, вибрации в гироскопе (`px4-control`); `FAILn` парашюта не проверен — termination не раскроет купол (`px4-safety-return`). Версии — по таблице в `px4-intro`.

### Шаг 2. Импульс сервы
Руль высоты — Servo 2 на выходе MAIN2 самолёта (выход IO, параметра `CENT` нет): `PWM_MAIN_MIN2` = 1050, `PWM_MAIN_MAX2` = 1900, `PWM_MAIN_DIS2` = 1500, `PWM_MAIN_FAIL2` = −1, `CA_SV_CS1_TRIM` = 0.08. Аллокатор отдаёт `v = clamp(TRIM + u, −1, 1)`, где u — команда контура.

Разобранный пример, u = +0.40, бит `REV` снят: v = 0.48; мкс = 1050 + (0.48 + 1) / 2 · 850 = 1050 + 629 = **1679**. В арифметике кода то же самое записано как a = 850 / 2 = 425, b = 1050 + 425 = 1475, мкс = 425 · 0.48 + 1475 = 1679.

Посчитай сам и запиши:

1. u = 0 (нейтраль), u = −1.0, u = +1.0 — без реверса.
2. Те же u = 0 и u = +0.40 при `PWM_MAIN_REV` = 2.
3. Что на выходе без арма при `COM_PREARM_MODE` = 0 и что при `COM_PREARM_MODE` = 2 и u = 0.
4. Что на выходе при flight termination и что при kill.
5. Серву переставили на выход FMU (PX4 1.17). Каким должен быть `PWM_AUX_CENTn`, чтобы нейтраль осталась прежней, что станет с `CA_SV_CS1_TRIM` и сколько микросекунд даст u = +0.40.

### Переход на реальное железо
Только после того, как сошлись все четыре шага. Пропеллеры сняты до конца процедуры.

1. Сервы — от отдельного BEC на рейку выходов, земля общая с полётником. Сигнальный провод ESC DShot — в AUX.
2. В QGC → Actuators назначь функции по своему плану, перезагрузи плату (смена `TIMn`), проверь в `pwm_out status` и `dshot status`, что каждая группа получила свой протокол.
3. Слайдером или `actuator_test set -s 1 -v 0.3 -t 2` подай положительную команду на каждую поверхность: кромка должна пойти вверх (руль направления — вправо). Идёт не туда — бит `REV`, а не знак `TRQ`.
4. Упоры: уменьшай `MAXn` и увеличивай `MINn`, пока серва не перестанет гудеть в крайних положениях. Нейтраль — `CENTn` (FMU, с 1.17) или `TRIM`.
5. Моторы: `actuator_test set -m 1 -v 0.1 -t 1` по одному, порядок и направление — как в px4-setup-scratch.

Критерии для железа: на каждом выходе тот протокол, что в плане; положительная команда отклоняет каждую поверхность по правилу; в крайних положениях серва не упирается (ток покоя не растёт); без арма при `COM_PREARM_MODE` = 0 рули стоят в нейтрали `DIS`.

Самопроверка: лабораторная выполнена, когда
- шаг 1: в таблице три группы FMU 4 + 2 + 2 и группа CAP1, DShot отмечен у двух; план не содержит ни одной группы с двумя протоколами, а в «неправильном» плане названы все четыре конфликта;
- шаг 2: все числа совпали с эталоном с точностью ±1 мкс;
- шаг 3: знаки всех десяти коэффициентов совпали с тремя airframe-файлами;
- шаг 4: маска раскодирована в выходы 5 и 6, обратная задача дала 22, найдены ровно три ошибки с правилами.

## diagnostics
- **Симптом:** серва греется, гудит или дёргается сразу после назначения функции.
  - Возможная причина: группа осталась на 400 Гц (в ней уже была функция) или стоит в DShot.
  - Что сделать: `PWM_AUX_TIMn` группы = 50, перезагрузка; мотор и серву развести по разным группам.
- **Симптом:** после включения bidirectional DShot моторы 5 и 6 молчат или нет оборотов в `esc_status`.
  - Возможная причина: в 1.18 BDShot выбран только у одной группы (`PWM_AUX_TIMn` = −6…−8 нужен у каждой группы моторов); в 1.16–1.17 bidirectional работал только на таймере с индексом 0 (первые четыре выхода FMU на H7); в 1.15 его нет; у группы нет DMA; ESC не поддерживает.
  - Что видно в логе: `esc_status.esc_rpm` = 0 при вращении, `dshot status` показывает BDShot не на всех группах.
  - Что сделать: в 1.18 — −6/−7/−8 в `TIMn` каждой группы моторов, перезагрузка; в 1.16–1.17 — моторы на первые четыре выхода FMU, для гекса и окта — телеметрия по UART (`DSHOT_TEL_CFG`); версию прошивки сверить с таблицей в px4-intro.
- **Симптом:** QGC на слайдере мотора пишет «command denied».
  - Возможная причина: аппарат заармлен; кнопка safety есть и не нажата; в 1.17 и раньше ещё `COM_MOT_TEST_EN` = 0 (в 1.18 параметра нет).
  - Что сделать: дизарм, нажать safety (или `CBRK_IO_SAFETY` = 22027 на плате без кнопки); из консоли — `actuator_test set -m 1 -v 0.1 -t 1`.
- **Симптом:** на земле рули не реагируют на стики.
  - Возможная причина: `COM_PREARM_MODE` = 0 — без арма выход стоит в `DIS`.
  - Что сделать: `COM_PREARM_MODE` = 2 (или 1 с кнопкой safety); проверять слайдерами.
- **Симптом:** самолёт в Stabilized раскачивается сильнее, чем в Manual, или уходит в крен при взятии ручки на себя.
  - Возможная причина: поверхность идёт против правила знаков, а исправлено знаком `TRQ` вместо `REV`; у элевонов перепутан знак `TRQ_R`.
  - Что сделать: слайдер вверх → кромка вверх на каждой поверхности; знаки — по шагу 3.
- **Симптом:** после обновления на 1.17 пропал trim поверхности, в QGC предупреждение про `TRIM is reset`.
  - Возможная причина: задан хотя бы один `CENTn` — прошивка обнулила все `CA_SV_CSn_TRIM`.
  - Что сделать: перенести trim в `CENTn` по формуле `MIN + (MAX − MIN)/2 · (1 + TRIM)` для каждой сервы на FMU.
- **Симптом:** DShot-ESC подключён к MAIN на Pixhawk с IO, моторы не инициализируются.
  - Возможная причина: IO умеет только PWM и OneShot.
  - Что сделать: перенести ESC на AUX (FMU PWM OUT) и переназначить функции.
- **Симптом:** обороты в `esc_status` не сходятся с расчётом по KV, динамический notch не помогает.
  - Возможная причина: `DSHOT_MOT_POLn` этого мотора (до 1.18 — `MOT_POLE_COUNT`) не равен числу магнитов.
  - Что сделать: посчитать магниты на колоколе; 12 полюсов вместо 14 дают ошибку в 7/6.
- **Симптом:** выход Peripheral via Actuator Set не реагирует на команду.
  - Возможная причина: param7 (индекс) не 0; значение в микросекундах вместо −1…1; выход в группе, занятой триггером или DShot.
  - Что сделать: param1…6 в диапазоне −1…1, param7 = 0; проверить группу таймера.

## checklist
- Группы таймеров платы выписаны из `timer_config.cpp` или с экрана Actuators до пайки.
- В каждой группе один протокол: моторы DShot отдельно, сервы 50 Гц отдельно, триггер камеры — своя группа.
- DShot и bidirectional DShot — только на выходах FMU; в 1.18 BDShot (−6/−7/−8) задан у каждой группы моторов (в 1.16–1.17 при `DSHOT_BIDIR_EN` = 1 — моторы только на первых четырёх).
- После назначения Servo проверено: `DISn` = 1500, `TIMn` группы = 50.
- Каждая поверхность идёт по правилу знаков; механика исправлена битом `REV`.
- `MINn` / `MAXn` подобраны по упорам, нейтраль — `CENTn` или `TRIM`, но не оба.
- `FAILn` проверен для парашюта и рулей; `COM_PREARM_MODE` выбран осознанно.
- `DSHOT_MOT_POLn` каждого мотора равен числу его магнитов.
- Сервы питаются от отдельного BEC, земля общая.
