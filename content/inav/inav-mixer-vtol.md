## summary
Миксер — последний программный слой между регуляторами и железом: он превращает три команды стабилизации и газ в числа для каждого мотора и каждой сервы, а таймеры микроконтроллера — в импульсы на падах. Модуль разбирает его целиком по исходнику INAV 9.1.0: типы платформы, строки `mmix` (включая значения газа −1 и −1.05…−2), правила `smix` и все 61 источник входа, команду `servo`, настройки `servo_*`, раздачу выходов по таймерам и `timer_output_mode`, таблицы для элевонов, V-хвоста, флаперонов и дифференциала, подвесы и head tracker, два профиля миксера и VTOL-переход. Практика без железа и симулятора: вывести `mmix` гексы из геометрии и сверить с пресетом, посчитать импульсы серв по формуле `servos.c`, разложить выходы настоящей платы MATEKF405TE под 4 и 5 моторов на DShot и найти три ошибки в VTOL-конфиге 4+1.

## theory
### Где стоит миксер
{{diagram:inav-mixer-signal-path|Моторы получают только три команды PID и газ; сервы — любой из 61 источника. Дальше всё решает таймер: один таймер — одна функция.}}

PID-регуляторы выдают `axisPID[ROLL/PITCH/YAW]` в диапазоне ±500. Моторный миксер (`mixTable()`, `mixer.c`) складывает их с газом по таблице `mmix`. Серво-миксер (`servoMixer()`, `servos.c`) считает сервы по правилам `smix` и параметрам `servo`. Готовых таблиц в прошивке нет: пресеты «Quad X», «Flying Wing» и остальные лежат в Configurator (`js/model.js`) и при загрузке просто записывают строки `mmix`/`smix`. Теория распределения управления — в ctl-allocation; здесь её ручная запись.

### Тип платформы
`platform_type` хранится в профиле миксера и включает набор флагов (`mixerUpdateStateFlags()`):

| Значение | Что включает | Следствие |
|---|---|---|
| `MULTIROTOR` (умолчание) | MULTIROTOR, ALTITUDE_CONTROL | мультироторные PID и навигация, AIRMODE, HEADFREE |
| `TRICOPTER` | то же | плюс `tri_unarmed_servo`: хвостовая серва работает и без арма |
| `AIRPLANE` | AIRPLANE, FIXED_WING, ALTITUDE_CONTROL, MOVE_FORWARD_ONLY | PID крыла, MANUAL, автозапуск, autotrim, autotune, FLAPERON при `has_flaps` |
| `ROVER`, `BOAT` | FIXED_WING, MOVE_FORWARD_ONLY, без ALTITUDE_CONTROL | нет ALTHOLD и AIRMODE, потолок газа 1850 вместо 2000 |
| `HELICOPTER` | те же флаги, что MULTIROTOR | отдельной логики автомата перекоса в `mixer.c` нет |

Документация (`docs/Mixer.md`, описание настройки) называет реализованными MULTIROTOR, AIRPLANE и TRICOPTER. Подробности самолётной платформы — в inav-wing.

### `mmix`: моторы
Синтаксис: `mmix <n> <throttle> <roll> <pitch> <yaw>`, `n` = 0…11 (`MAX_SUPPORTED_MOTORS` 12), `mmix reset` стирает таблицу. Формула (`mixer.c:537–540, 628`):

```text
motor[n] = pitch·P + roll·R − yaw·Y + constrain(газ · throttle)
```

P, R, Y — `axisPID`, ±500. Знаки весов по `docs/Mixer.md`: положительный `roll` — мотор ускоряется при крене вправо (значит, он слева); положительный `pitch` — ускоряется при опускании носа (он сзади); положительный `yaw` — ускоряется при повороте по часовой, то есть его проп крутится против часовой. Минус перед yaw в формуле не ошибка: `rcCommand[YAW]` — это стик с обратным знаком (`fc_core.c:402`). Настройка `motor_direction_inverted = ON` меняет знак всей yaw-колонки сразу (props-out), таблицу трогать не нужно.

Строка из геометрии: мотор на луче с азимутом φ по часовой от носа, длина лучей одинакова — `roll = −sin φ`, `pitch = −cos φ`. Для Quad X (φ = 45°, 135°, 225°, 315°) выходит ±0.707; пресет масштабирует таблицу до ±1 — общий множитель оси компенсируют PID, важны отношения между моторами.

```text
mmix 0  1.000 -1.000  1.000 -1.000   # задний правый, проп по часовой
mmix 1  1.000 -1.000 -1.000  1.000   # передний правый
mmix 2  1.000  1.000  1.000  1.000   # задний левый
mmix 3  1.000  1.000 -1.000 -1.000   # передний левый
```

Проверка: газ 1500, запрос крена +100 → правые моторы 1400, левые 1600, аппарат кренится вправо.

Колонка `throttle` — не только масштаб газа:

| `throttle` | Поведение (`mixer.c:636–644`) |
|---|---|
| 0 < t ≤ 1 | обычный мотор |
| 0 | пустая строка: `mmix`, `diff` и счётчик моторов обрываются на первой такой строке |
| −1.05 < t < 0 (пишут −1) | мотор остановлен, но строка занята — «пустышка», чтобы следующие строки не потерялись |
| −2.0 ≤ t ≤ −1.05 | остановлен; при активном MIXER TRANSITION крутится на `−t × 1000` мкс независимо от стика (−1.2 → 1200, это 20 % диапазона). Не работает с `REVERSIBLE_MOTORS` |

Число моторов считается по обоим профилям: мотор «есть», если его `throttle` ≠ 0 хотя бы в одном (`mixer.c:117–137`).

### `smix`: правила серв
Синтаксис: `smix <rule> <servo> <input> <weight> <speed> <lc>`. `rule` 0…35 (`MAX_SERVO_RULES`), `servo` 0…17, `weight` −1000…1000 %, `speed` 0…255, `lc` — номер логического условия −1…63 (−1 — правило работает всегда; ложное условие обнуляет вход правила, см. inav-ipf). Правила с одной сервой складываются. Таблица читается до первого правила с весом 0. `speed` ограничивает скорость изменения входа: `speed × 10` единиц в секунду, 0 — без ограничения; при весе 100 и стандартных концах это те самые «10 мкс/с на единицу» из документации.

Источники входа (`inputSource_e`, `servos.h:26–89`) — в 9.1.0 их 61, id 0…60:

| id | Источник | Значение |
|---|---|---|
| 0, 1, 2 | стабилизированные крен, тангаж, рыскание | `axisPID`, ±500; в MANUAL — стики |
| 3 | стабилизированный газ | команда газа − 1500; без арма −500 |
| 4–7 | RC крен, тангаж, рыскание, газ | канал − 1500, мимо стабилизации |
| 8–11, 15–22, 42–43 | RC CH5–CH8, CH9–CH16, CH17–CH18 | канал − 1500 |
| 44–59 | RC CH19–CH34 | только платы с флешем > 512 КБ (`USE_34CHANNELS`) |
| 12, 13 | GIMBAL PITCH, GIMBAL ROLL | тангаж ±90° и крен ±180° → ±500; только при режиме CAMSTAB, иначе 0 |
| 14 | FEATURE FLAPS | `flaperon_throw_offset` при режиме FLAPERON, иначе 0 |
| 23, 24 | крен «+» и «−» | положительная и отрицательная половины входа 0 |
| 25, 26 / 27, 28 | то же для тангажа / рыскания | половины входов 1 и 2 |
| 29 | MAX («Fixed Value» в Configurator) | всегда 500 |
| 30–37 | GVAR 0–7 | глобальные переменные IPF, ±1000 |
| 38 | MIXER TRANSITION | 500, пока активен переход, иначе 0 |
| 39, 40, 41 | head tracker pan, tilt, roll | PWM − 1500; 0 без устройства и в GIMBAL CENTER |
| 60 | MIXER_SWITCH_HELPER | служебный, появился в 9.x: прошивка сама создаёт такие правила при смене профиля, чтобы ограничитель `speed` доработал плавно |

Знак входа 2 противоположен стику рыскания — по той же причине, что и в `mmix`.

### `servo` и настройки серв
`servo <n> <min> <max> <mid> <rate>`: `min`/`max` 500…2500 мкс (умолчание 1000/2000), `mid` между ними (1500), `rate` −125…125 % (100). Формула (`servos.c:443–497`, деление целочисленное, отбрасывается дробная часть):

```text
sum = Σ trunc(input · weight / 100)          # все правила этой сервы
s   = trunc(sum · rate / 100)
s   = trunc(s · (max − mid) / 500)  при s > 0,  иначе  trunc(s · (mid − min) / 500)
out = constrain(mid + s, min, max)
```

Сумма ±500 приводит серву ровно в `max`/`min` — концы масштабируют ход, а не обрезают его. Обрезка начинается, когда сумма правил выходит за ±500 (сумма весов больше 100). Реверс: отрицательный `rate` разворачивает серву целиком, знак веса — одну ось (правило выбора — в inav-setup-wing). Серва без правил в текущем профиле стоит в `mid`.

После формулы работает фильтр `servo_lpf_hz` и ещё раз ограничение `min`/`max`. Выходы физически раздаются подряд от наименьшего до наибольшего использованного номера сервы по обоим профилям (`servos.c:147–172, 294–300`): правила для серв 1, 2 и 6 займут шесть выходов, три из них впустую. Питание серв (отдельный BEC, ток упора, общая земля) — в bf-servos-pwm, здесь не повторяется.

### Выходы и таймеры
Выход S на плате — канал аппаратного таймера. У таймера один счётчик и один период на все каналы: серво-таймер настраивается на период `1 МГц / servo_pwm_rate` (`pwm_output.c:738`), моторный — на частоту битов DShot или кадра OneShot. Поэтому мотор и серва на одном таймере несовместимы, и INAV раздаёт функции целыми таймерами (`pwm_mapping.c:273–369`):

1. В `target.c` каждый выход помечен: `TIM_USE_OUTPUT_AUTO` (мотор или серва), `TIM_USE_LED`, `TIM_USE_BEEPER`.
2. `timer_output_mode <таймер> <AUTO|MOTORS|SERVOS|LED>` жёстко задаёт функцию всем выходам таймера. Номер — индекс в таблице таймеров. На F4, F7 и AT32 это номер TIM минус 1; на H7 так только до TIM8, дальше TIM12 → 8, TIM13 → 9, TIM14 → 10, TIM15 → 11, TIM16 → 12, TIM17 → 13 (`timer_stm32h7xx.c`). Надёжнее смотреть вкладку Mixer: «Timer N» = индекс + 1. Подсказка CLI перечисляет только три значения, но `LED` парсер принимает (`cli.c:3194`). Что происходит с остальными выходами таймера при включённой ленте — в `inav-led-pinio-beeper`.
3. В AUTO прошивка идёт по таблице сверху вниз и забирает под моторы таймеры целиком, пока моторных выходов не хватит на миксер. Остальные AUTO-таймеры становятся серво.
4. Моторы миксера занимают моторные выходы по порядку, сервы — серво-выходы по порядку.
5. Не хватило — арминг блокирует флаг `PWMOUT`, а `status` печатает `PWM output init error` с причиной, например `Not enough servo outputs/timers`.

Следствие: пятый мотор на четырёхканальном таймере съедает все четыре выхода. Команда `resource` в INAV только показывает занятые ресурсы; перенести функцию на другой пин, как в Betaflight, нельзя — только `timer_output_mode` или своя сборка с правкой `target.c`. Настройки `output_mode` в 9.1.0 нет — ни самой настройки, ни таблицы значений в `settings.yaml`: режимы `AUTO`, `MOTORS`, `SERVOS`, `LED` заданы перечислением в `flight/mixer.h` и меняются только командой `timer_output_mode`.

Во вкладке Mixer таблица «Output Groups (Timers)» красит выходы одного таймера одним цветом и подписывает `S5 (Timer 2)`; строка под ней показывает назначенную функцию. Вкладка Outputs показывает текущие значения моторов и серв и правит `min`/`mid`/`max`/`rate`. Пока не включена `feature PWM_OUTPUT_ENABLE` («Enable motor and servo output»), импульсов на падах нет.

`servo_protocol = SBUS` выводит сервы не на пады, а в UART с функцией `SERVO_SERIAL` (4194304), до 18 каналов; `SBUS_PWM` — и туда, и на пады. `docs/ESC and servo outputs.md` предупреждает: на части плат в мультироторной конфигурации серво-выходов нет вовсе.

### Крыло: элевоны, V-хвост, флапероны, дифференциал
Таблицы из пресетов Configurator 9.1.0 (правила нумеруются подряд с 0, `speed` 0, `lc` −1):

| Схема | Серва: вход × вес |
|---|---|
| Летающее крыло | 1: крен 50, тангаж 50; 2: крен −50, тангаж 50 |
| Самолёт | 1: тангаж 100; 2: крен 100; 3: крен 100; 4: рыскание 100 |
| V-хвост | 1 и 2: крен 100; 3: тангаж 50, рыскание −50; 4: тангаж −50, рыскание −50 |

Элевон с весами 50 + 50 доходит до упора только при полных командах по обеим осям сразу. Флапероны: `set has_flaps = ON` открывает режим FLAPERON (id 34), и вход 14 выдаёт `flaperon_throw_offset` (200 мкс, 50…450). Строки `smix 4 2 14 100 20 -1` и `smix 5 3 14 -100 20 -1` опускают оба элерона; `speed 20` растягивает выпуск на 200 / (20 × 10) = 1.0 с. Отдельных «режимов закрылков» в прошивке нет — положения делают каналом пульта (входы 8–11) или несколькими правилами с логическими условиями. Дифференциал элеронов собирают из половинок 23/24 вместо входа 0: вес 100 на половину, которая поднимает элерон, и 60 на ту, что опускает; на зеркальной серве веса меняются местами. Какая половина поднимает — зависит от установки сервы; проверяют на столе.

### Подвесы и head tracker
**Серво-подвес** — два правила с входами 12 и 13. Они не равны нулю только при активном режиме CAMSTAB (id 8). Вход 12 даёт 500 / 90 = 5.56 единицы на градус тангажа, вход 13 — 2.78 единицы на градус крена. Для сервы с 11.11 мкс/° компенсация 1 : 1 требует веса 200 по тангажу и 400 по крену; знак — по тесту наклоном.

**Серийный подвес** (с INAV 8, протокол Walksnail GM): функция порта GIMBAL (67108864). Каналы пульта задают `gimbal_pan_channel`, `gimbal_tilt_channel`, `gimbal_roll_channel` (0 — нет), чувствительность — `gimbal_sensitivity` (−16…15), смещение центра — `gimbal_pan_trim`, `gimbal_tilt_trim`, `gimbal_roll_trim` (±500). Режимы: GIMBAL LEVEL TILT (65), GIMBAL LEVEL ROLL (66), GIMBAL CENTER (67), GIMBAL HEADTRACKER (68). Миксер серийным подвесом не управляет.

**Head tracker**: `headtracker_type` = NONE / SERIAL / MSP, функция порта GIMBAL_HEADTRACKER (134217728), коэффициенты `headtracker_pan_ratio`, `headtracker_tilt_ratio`, `headtracker_roll_ratio` (0…5, умолчание 1). `gimbal_serial_single_uart = ON` делит один UART: TX — подвесу, RX — трекеру. Обычную серво-турель трекер двигает через входы 39–41. Выбор и механика подвесов — в payload-gimbal.

### Профили миксера
Профилей два (`MAX_MIXER_PROFILE_COUNT`); на F411 и других платах с флешем до 512 КБ, кроме F7, — один, VTOL там недоступен (`target/common.h:206–222`). Команда `mixer_profile 1|2` выбирает профиль для редактирования и сохраняет выбор.

| Хранится в профиле миксера | Общее для обоих |
|---|---|
| `platform_type`, `motor_direction_inverted`, `has_flaps`, `motorstop_on_low`, `model_preview_type` | `timer_output_mode`, протоколы и частоты моторов и серв |
| `mixer_control_profile_linking`, `mixer_automated_switch`, `mixer_switch_trans_timer`, `tailsitter_orientation_offset`, `transition_pid_mmix_multiplier_*` | `servo` (min, max, mid, rate) |
| таблицы `mmix` и `smix` | ориентация платы, порты, режимы |

Без режима `MIXER PROFILE 2` смена профиля требует перезагрузки. С ним (id 62) профиль меняется в полёте: режим активен — профиль 2, иначе профиль 1. `mixer_control_profile_linking = ON` заставляет control-профиль следовать за профилем миксера (до 9.0 настройка называлась `mixer_pid_profile_linking`); документация советует ON в обоих профилях. При OFF самолёт полетит на PID мультиротора.

### VTOL: переход и его ограничения
INAV поддерживает три схемы (`docs/VTOL.md`): отдельный толкающий мотор («4+1» — самая простая в настройке), поворотные моторы (tilt-rotor) и tailsitter (`tailsitter_orientation_offset = ON` в профиле висения: поворот ориентации на 90° по тангажу, а в переходе +45° к цели ANGLE). Сравнение с ArduPilot, где VTOL — один набор параметров `Q_ENABLE`, `Q_FRAME_CLASS`, `Q_TRANSITION_MS`, `Q_ASSIST_SPEED`, `Q_TILT_TYPE`, — в ap-quadplane.

Режим `MIXER TRANSITION` (id 63) включает «переходное смешивание» в текущем профиле: вход 38 становится 500, моторы с `throttle` −1.05…−2 раскручиваются, а команды PID в `mmix` умножаются на `transition_pid_mmix_multiplier_roll/pitch/yaw` / 1000. Типовой трёхпозиционный тумблер из документации: самолёт — мультиротор с переходом — мультиротор.

Что проверено по `mixer_profile.c`:
- Переход идёт **по времени, не по воздушной скорости**: датчик скорости в логике перехода не участвует.
- Смена профиля отклоняется, пока идёт калибровка датчиков, открыт CLI или активен любой режим навигации, включая ALTHOLD (`navState` не IDLE).
- Переходное смешивание работает только без навигации или в ALTHOLD; в POSHOLD, RTH и миссии вход 38 равен 0.
- В failsafe тумблеры не читаются; остаётся только автоматический переход.

Автоматический переход: `mixer_automated_switch = ON` в мультироторном профиле — при RTH, если до дома больше 3 × `nav_fw_loiter_radius` (225 м при умолчании 7500 см), аппарат удерживает высоту, включает переходное смешивание на `mixer_switch_trans_timer` × 0.1 с и переключается на самолётный профиль. `ON` в самолётном профиле — перед посадкой RTH переключается обратно; таймер берётся из текущего профиля. Обязательное условие — режим `MIXER PROFILE 2` назначен на канал.

Требования документации: `airmode_type` не `THROTTLE_THRESHOLD`; компас для навигации в мультироторном профиле; каждый профиль сначала облётан отдельно; проверки на столе без пропов; функция названа экспериментальной. Переключение в самолётный профиль без скорости — немедленное сваливание.

### Разобранный пример: 4+1
Квадрокоптер X плюс толкающий мотор, самолётное оперение. Профиль 1 — самолёт, профиль 2 — висение:

```text
mixer_profile 1                        mixer_profile 2
set platform_type = AIRPLANE           set platform_type = MULTIROTOR
set mixer_control_profile_linking = ON set mixer_control_profile_linking = ON
```

### Место в системе
- **Получает:** `axisPID` от регуляторов (их масштабы и настройка — в `inav-mc-tuning`; ctl-allocation объясняет, почему таблица именно такая), каналы приёмника и режимы CAMSTAB, FLAPERON, MIXER PROFILE 2 и MIXER TRANSITION, переменные GVAR и условия из inav-ipf, карту таймеров платы из `target.c`.
- **Отдаёт:** значения моторов драйверам ESC и импульсы сервам рулей, поворотных узлов и подвеса (payload-gimbal); при смене профиля — тип платформы навигации и номер control-профиля (inav-wing, inav-setup-scratch).
- **Если ошибиться здесь:** неверный знак в `mmix` выглядит как переворот на взлёте, серва на моторном таймере — как запрет арминга `PWMOUT`, выключенная связка профилей — как раскачка самолёта на PID коптера, нулевой таймер перехода — как сваливание при RTH.

### Переход на реальное железо
Стол, пропы сняты. Сохрани `diff all`. Во вкладке Mixer сверь цвета таймеров со своей таблицей из `target.c` своей платы и назначь `timer_output_mode`; после перезагрузки `status` не должен содержать `PWM output init error`, а флаг `PWMOUT` — отсутствовать. Включи «Enable motor and servo output» и во вкладке Outputs проверь каждую серву: центр, концы без упора и гула, направление по правилу из inav-setup-wing. Сервы питай от отдельного BEC (bf-servos-pwm). Для VTOL: переключай трёхпозиционный тумблер и смотри в Outputs, что толкающий мотор в переходе показывает ровно `−throttle × 1000`, а после смены профиля моторы висения стоят. Прерывание: любой мотор крутится в неожиданном состоянии тумблера, серва гудит на упоре, полётник перезагружается при движении серв.

Самопроверка: лабораторная выполнена, когда:
- шаг 1: шесть строк `mmix` совпали с эталоном до третьего знака, а шесть значений моторов — до ±1;
- шаг 2: десять импульсов совпали с эталоном до ±1 мкс, ограничение найдено ровно в одном случае, время выпуска 1.0 с;
- шаг 3: для 4 моторов названы 7 серво-выходов, для 4+1 найдены оба конфликта и итоговая раскладка совпала с эталоном;
- шаг 4: таблица состояний совпала с эталоном и названы все три ошибки с их последствиями;
- (железо, если есть плата) `status` без `PWM output init error`, толкающий мотор в переходе показывает расчётное значение.

## diagnostics
- **Симптом:** коптер переворачивается на взлёте сразу после отрыва
  - Возможная причина: строки `mmix` не соответствуют реальным местам моторов, перепутаны выходы, моторы вращаются не в ту сторону или пропы стоят не на своих моторах; props-out без `motor_direction_inverted = ON`.
  - Что сделать: без пропов во вкладке Outputs раскрутить моторы по одному и сверить место и направление с таблицей; пересчитать строку по азимуту (`roll = −sin φ`, `pitch = −cos φ`).
  - Последствия: если не тот знак только у yaw — не переворот, а быстрое вращение вокруг вертикали.
- **Симптом:** не армится, в `status` флаг `PWMOUT`
  - Возможная причина: моторам или сервам не хватило таймеров; мотор с DShot попал на таймер без DMA.
  - Что сделать: `status` → строка `PWM output init error`; пересчитать раскладку по `target.c`, назначить `timer_output_mode`, либо сменить `motor_pwm_protocol`.
- **Симптом:** серва не двигается, хотя правило `smix` есть
  - Возможная причина: не включена `feature PWM_OUTPUT_ENABLE`; серва подключена к паду моторного таймера; перед правилом стоит правило с весом 0, и таблица на нём оборвалась; логическое условие правила ложно.
  - Что сделать: вкладка Mixer — функция выхода; `smix` без аргументов — правила подряд; проверить условие во вкладке Programming.
- **Симптом:** серва подключена к «своему» выходу, но работает соседняя
  - Возможная причина: пропуск в номерах серв — выходы раздаются подряд от наименьшего до наибольшего номера.
  - Что сделать: перенумеровать сервы без пропусков.
- **Симптом:** подвес не реагирует на наклон
  - Возможная причина: режим CAMSTAB не активен — входы 12 и 13 равны нулю.
  - Что сделать: назначить CAMSTAB на канал или постоянный диапазон; вес подобрать по мкс/° сервы.
- **Симптом:** после вставки `diff` пропал толкающий мотор
  - Возможная причина: в профиле перед ним стояла строка с `throttle` 0 — вывод `mmix` оборвался на ней, и строка мотора в бэкап не попала.
  - Что сделать: пустышки писать как −1.000; после восстановления сверять `mmix` в обоих профилях.
- **Симптом:** тумблер профиля не действует
  - Возможная причина: активен режим навигации (в том числе ALTHOLD), идёт калибровка датчиков после включения, открыт CLI или плата с одним профилем (F411).
  - Что сделать: переключать в ANGLE или ACRO без навигации; проверить в `diff all` наличие блока `mixer_profile 2`.
- **Симптом:** толкающий мотор крутится в висении при низком газе
  - Возможная причина: `airmode_type = THROTTLE_THRESHOLD` — документация запрещает его для VTOL.
  - Что сделать: `STICK_CENTER` или `STICK_CENTER_ONCE`.
- **Симптом:** при RTH аппарат переключился на самолёт и свалился
  - Возможная причина: `mixer_switch_trans_timer` мал или 0, толкающий мотор записан пустышкой −1.
  - Что сделать: измерить время разгона до скорости на 20–30 % выше сваливания в ручном переходе и записать его в десятых долях секунды.
  - Последствия: потеря высоты на десятки метров; ниже этого запаса автоматический переход включать нельзя.

## checklist
- Тип платформы задан в каждом профиле миксера, число моторов и серв посчитано по обоим профилям
- Каждая строка `mmix` сверена с местом мотора и направлением пропа; без пропов моторы проверены по одному
- Номера серв идут без пропусков, сумма весов на серву не уводит её за ±500 в обычном полёте
- Раскладка выходов выписана по `target.c`; ни одна серва не сидит на моторном таймере, DShot-моторы — только на таймерах с DMA
- `status` без `PWM output init error`, `feature PWM_OUTPUT_ENABLE` включена после проверки серв
- Сервы питаются от отдельного BEC, концы `min`/`max` подобраны без упора
- Для VTOL: связка control-профилей ON в обоих профилях, `MIXER PROFILE 2` и `MIXER TRANSITION` на трёхпозиционном тумблере, `airmode_type` не THROTTLE_THRESHOLD
- Пустышки моторов — −1.000, переходные моторы — от −1.05 до −2.0, таймер перехода в десятых долях секунды
- Каждый профиль облётан отдельно до первого перехода в воздухе; `diff all` сохранён

## notes
Документы `docs/VTOL.md` и `docs/MixerProfile.md` в теге 9.1.0 всё ещё пишут `set mixer_pid_profile_linking = ON` — прошивка 9.x эту строку отвергнет, настройка называется `mixer_control_profile_linking`. Там же диапазон «переходного» газа указан как −2.0 < throttle < −1.0, а в коде условие `≤ −1.05` и `≥ −2.0`; значение −1.0 — пустышка. Таблица входов в `docs/Mixer.md` заканчивается на id 29; входы 30–60 взяты из `servos.h`.
