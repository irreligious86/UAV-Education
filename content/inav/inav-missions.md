## summary
Миссия INAV — список точек с действиями, который аппарат выполняет в режиме NAV WP. Модуль показывает, из чего состоит точка, какие действия есть (WAYPOINT, POSHOLD_TIME, RTH, JUMP, SET_POI, LAND), как записать миссию через конфигуратор и через CLI командой `wp`, где лежит высота, и как INAV защищает от взлёта с «чужой» миссией.

## theory
### Структура точки
В CLI: `wp <n> <action> <lat> <lon> <alt> <p1> <p2> <p3> <flag>`.

- `lat`, `lon` — градусы × 10⁷ (123456789 = 12.3456789°).
- `alt` — сантиметры; бит 0 в `p3` задаёт, относительно дома (0) или над уровнем моря (1).
- `action`: 1 WAYPOINT, 3 POSHOLD_TIME, 4 RTH, 5 SET_POI, 6 JUMP, 7 SET_HEAD, 8 LAND.
- `p1`: для WAYPOINT и LAND — скорость к точке (см/с; только мультиротор; берётся при 50 ≤ p1 ≤ `nav_max_auto_speed` (1000), больше — обрезается до `nav_max_auto_speed`, меньше 50 — летит на `nav_auto_speed`); для POSHOLD_TIME — время в секундах; для RTH — p1 > 0 разрешает посадку; для JUMP — индекс цели.
- `p2`: для POSHOLD_TIME — скорость к точке (те же правила, что у `p1` WAYPOINT); для JUMP — число повторов.
- `p3` — битовое поле: бит 0 (1) — тип высоты, биты 1–4 (2, 4, 8, 16) — метки user action 1–4 этой точки. `p3 = 6` — высота относительно дома, включены действия 1 и 2.
- `flag`: 0 — обычная точка, 165 (0xA5) — последняя точка миссии, 72 (0x48) — точка берёт координаты дома вместо `lat`/`lon` (так же, как точка с `lat = lon = 0`). CLI отвергает любой другой флаг.

Ёмкость: `NAV_MAX_WAYPOINTS` = 120 точек на все миссии вместе (`target/common.h` 9.1.0); в 9.1.0 своё значение задаёт только FISHDRONEF4 — 60, и официальных сборок этого target'а нет (`SKIP_RELEASES`). Номер точки в CLI — с 0, в Mission Control — с 1.

### Правила JUMP: проверяются при арме
Ошибка в JUMP не всплывает в полёте: арм блокирует флаг `NAV` (`navigationIsBlockingArming()`, `navigation.c` 9.1.0). Правила в номерах CLI (с 0):
1. JUMP не может быть первой точкой миссии.
2. Цель `p1` — номер существующей точки: `p1` меньше числа точек.
3. Нельзя прыгать на соседнюю точку и на себя: для JUMP с номером n цель n − 1, n и n + 1 запрещены.
4. Цель — точка с координатами: WAYPOINT, POSHOLD_TIME или LAND (не RTH, SET_POI, SET_HEAD и не другой JUMP).
5. `p2` (повторы) не меньше −1; −1 — бесконечно.

Проверка: список `wp 0 1 …`, `wp 1 1 …`, `wp 2 1 …`, `wp 3 6 0 0 0 0 2 0 0`, `wp 4 4 0 0 0 1 0 0 165` — JUMP с номером 3 на точку 0 дважды, правила выполнены. С `p1 = 2` (соседняя) арм заблокирован. В Mission Control номера на единицу больше: там та же цель — точка 1.

`wp load` загружает список из EEPROM, `wp save` — сохраняет, `wp reset` — очищает. При восстановлении из бэкапа (`inav-cli-backup`) строки `wp` из `diff all` попадают только в оперативную память: обычная `save` их не записывает, после перезагрузки список будет прежним. Миссию сохраняет `wp save` перед `save`; она проверяет список (последняя точка с флагом 165) и заодно сама записывает в EEPROM все несохранённые настройки CLI — выполняй её, когда в выводе вставки нет красных строк.

### Выполнение
Режим NAV WP включается тумблером. Аппарат летит от точки к точке на `nav_auto_speed` (или скорости из `p1`), радиус захвата точки — `nav_wp_radius`. Миссия, сохранённая `wp save`, после включения питания сама в память не попадает: `nav_wp_load_on_boot` = OFF, её загружает `wp load` (повторный `wp load` при уже загруженной миссии её выгружает), кнопка в Mission Control или стик-команда загрузки (`inav-adjustments`). Поставь ON, если аппарат летает одну и ту же миссию без ноутбука в поле. JUMP даёт циклы, SET_POI — поворот камеры на точку интереса, LAND — посадка на точке.

### Защита от чужой миссии
Если загружена миссия, первая точка которой дальше `nav_wp_max_safe_distance`, арм блокируется. Это защита от сценария «приехал на другое поле с вчерашней миссией». Обход — yaw-стик вправо при арме (в Mode 2 левый стик вниз-вправо), независимо от `nav_extra_arming_safety`, и это именно обход; 0 в `nav_wp_max_safe_distance` (дефолт 100 м) отключает проверку. `nav_extra_arming_safety = ALLOW_BYPASS` (дефолт в 9.1, как и в 8.0) касается другой блокировки — арма без GPS-фикса.

### Несколько миссий (multi-mission)
До 9 миссий лежат в одном списке точек подряд (`navigation.c`, `USE_MULTI_MISSION` есть во всех target'ах): каждая заканчивается точкой с флагом 165, а конец всего файла — ещё одна запись с флагом 165 и действием RTH сразу за последней миссией. Mission Control сохраняет и загружает такой файл целиком, `wp save` пишет его в EEPROM. Активная миссия — `nav_wp_multi_mission_index` (1–9, умолчание 1), её номер показывает OSD. Выбрать миссию можно четырьмя способами:

| Способ | Когда работает | Как |
|---|---|---|
| CLI, Configurator | не в арме | `set nav_wp_multi_mission_index = 2`, `save` |
| Стик-команда | не в арме, газ внизу | крен вправо — следующая, крен влево — предыдущая, рыскание и тангаж в центре |
| `adjrange`, функция 59 | в арме, не в режиме WP | канал подстройки шагает по 1 от 1 до числа миссий (`inav-adjustments`) |
| Режим MISSION CHANGE (id 59) | в арме, при двух миссиях и больше | пока режим включён, NAV WP не стартует, а каждое включение тумблера NAV WP переключает на следующую миссию по кругу; выключил MISSION CHANGE — выбранная миссия загрузится |

Проверка перед взлётом: номер миссии в OSD тот, что нужен, и первая её точка ближе `nav_wp_max_safe_distance`. Операнды Programming Framework для точек относятся к выбранной миссии.

### User actions: как точка миссии управляет PINIO
Биты 1–4 `p3` сами ничего не переключают. Цепочка в 9.1.0 такая: бит в `p3` → операнд миссии типа 7 (6–9 — действие активно на этом участке) → логическое условие операцией 38 (Override RC Channel) подменяет канал, на котором висит диапазон режима USER1–4 → режим USER включает свой PINIO (`pinio_box1..4`). Какой участок «помечен», решает номер операнда (`logic_condition.c` 9.1.0): 6–9 читают `p3` точки, **от** которой аппарат летит, 10–13 — точки, **к** которой летит. Пример: точка 2 с `p3 = 2` (user action 1), правило `logic 0 1 -1 1 7 6 0 1 0` («действие 1 активно = 1»), правило `logic 1 1 0 38 0 12 0 2000 0` (пока правило 0 true, канал 12 = 2000 мкс), `aux` USER1 на канале 12 в диапазоне 1700–2100, `pinio_box1` = 47 (USER1). PINIO1 включён на участке от точки 2 до точки 3; с операндом 10 вместо 6 — на участке от точки 1 до точки 2. Разбор с затвором камеры по расстоянию и проверкой на столе — в `inav-led-pinio-beeper`, номера операций и операндов — в `inav-ipf`.

### Против ArduPilot
В INAV миссия проще: нет CONDITION-команд, нет DO-команд в чистом виде (часть действий — через user actions в `p3` и логические условия), загрузка через MSP/CLI, MAVLink-протокол миссий (MISSION_COUNT/MISSION_ITEM) поддерживается упрощённо (что именно принимает обработчик — в `inav-telemetry-gcs`). Для съёмки участка и облёта — достаточно; для сложной логики — Programming Framework или ArduPilot.

### Параметры выполнения и защиты
`nav_auto_speed` (500 см/с) — скорость по умолчанию, `nav_wp_radius` (100 см) — радиус захвата точки (для крыла — больше, 1000–3000), `nav_wp_max_safe_distance` (100 м; 0 — выключить) — первая точка дальше этого от места арма → арм заблокирован («вчерашняя миссия на новом поле»). Мультиротор у точки тормозит и разворачивается (`nav_mc_wp_slowdown` = ON); OFF — поворачивает на ходу. Скорость: `nav_auto_speed` (500 см/с) по умолчанию, `p1` точки — не выше `nav_max_auto_speed` (1000 см/с); обе настройки только для мультиротора. Крыло летит на крейсерском газе и проходит точку по правилу `nav_fw_wp_turn_smoothing`: OFF (умолчание) — долетает до радиуса захвата и только потом поворачивает, ON — входит в поворот по дуге loiter так, что точка лежит на дуге, ON-CUT — срезает угол и в саму точку не попадает. Для съёмки по точкам — OFF или ON; ON-CUT — когда важна плавность, а не попадание.

### Разобранный пример: облёт участка 200×100 м для съёмки
Высота 60 м, поперечное перекрытие кадров 70% при горизонтальном FOV камеры 84° (охват поперёк галса ≈ 2·60·tan42° ≈ 108 м) → расстояние между галсами 108 × (1 − 0.7) ≈ 32 м → на 100 м ширины 4 галса; точки: WAYPOINT ×8 с `p1` = 0 (скорость `nav_auto_speed` = 5 м/с), в конце RTH с `p1` = 1 (посадка разрешена). Время: ~1 км пути / 5 м/с ≈ 3.5 мин + развороты. В CLI это 9 строк `wp`, последняя с флагом 165. Триггер камеры — логическим условием по user action из `p3`: само действие ничего не переключает, правило операцией 38 подменяет канал режима USER, а за режимом следует PINIO (`inav-led-pinio-beeper`); либо интервальная съёмка на самой камере. Проверка миссии в конфигураторе на карте: ни одна точка не над людьми/дорогой, высота выше деревьев.

### Что происходит, когда в миссии что-то ломается
- **Потеря RC в NAV WP**: решает `failsafe_mission_delay` (0–600 с, −1; умолчание 0). 0 — процедура failsafe (`failsafe_procedure`, обычно RTH) начинается сразу, как без миссии; N — миссия идёт ещё N секунд, и если связь не вернулась, начинается процедура; −1 — процедура не начинается вовсе, миссия идёт до конца, а дальше действует её последняя точка (RTH с посадкой или удержание). −1 выбирают для миссий за пределом дальности связи, и тогда последняя точка обязана быть RTH. Проверяйте, что RTH-высота выше препятствий на всём маршруте.
- **Потеря GPS**: навигационные режимы невозможны; через `nav_position_timeout` (5 с) без оценки позиции аппарат переходит в аварийную посадку со скоростью `nav_emerg_landing_speed` (подробно в `inav-gps`). Миссия над водой или лесом — с запасом высоты и понятным планом «куда упадёт».
- **Низкий заряд**: планируйте миссию на 60–70 % ёмкости и следите за предупреждениями OSD; не рассчитывайте, что прошивка сама прервёт миссию вовремя.
- **Пилот выключил NAV WP**: аппарат возвращается в выбранный тумблером режим; что будет при повторном включении — продолжение или начало сначала — задаёт `nav_wp_mission_restart`.

### Место в системе

- **Получает:** оценку позиции и дом (`inav-gps`); скорость `nav_auto_speed` и радиус захвата `nav_wp_radius`; процедуру failsafe (`inav-setup-scratch`); для крыла — проход точек по дуге и больший радиус (`inav-wing`).
- **Отдаёт:** маршрут режиму NAV WP; точки миссии как операнды логических условий (`inav-ipf`); блокировку арма, если первая точка дальше `nav_wp_max_safe_distance` (`inav-intro`).
- **Если ошибиться здесь:** маршрут проложен без оглядки на высоту RTH → при потере RC миссия не продолжается, срабатывает failsafe, и аппарат возвращается ниже препятствий (`inav-gps`, `inav-setup-scratch`). Приехал на другое поле со вчерашней миссией → арм заблокирован, причина читается в OSD и `status` (`inav-intro`); обход стиком рыскания снимает защиту, а не ошибку.

## practice
### Шаг 1. Миссия в конфигураторе
1. Вкладка Mission Control: поставить 3–4 точки, высота 30 м относительно дома.
2. Последняя — RTH с посадкой (или без для крыла).
3. Сохранить в FC (Save to FC) и в файл.

### Шаг 2. Та же миссия в CLI
```
wp reset
wp 0 1 505000000 304000000 3000 0 0 0 0
wp 1 1 505005000 304005000 3000 0 0 0 0
wp 2 3 505010000 304000000 3000 20 0 0 0
wp 3 4 0 0 0 1 0 0 165
wp save
wp
```

Точка 2 — POSHOLD_TIME 20 с, точка 3 — RTH с посадкой, последний флаг 165.

### Шаг 2б. Генератор CLI из списка координат
Руками переводить градусы в «× 10⁷» и сантиметры — верный способ ошибиться на порядок. Скрипт:
```python
def wp_cli(points, alt_m=30, rth_land=True):
    # points: [(lat, lon), ...] in degrees -> INAV CLI lines; altitude relative to home
    lines = ["wp reset"]
    for i, (lat, lon) in enumerate(points):
        lines.append(f"wp {i} 1 {round(lat * 1e7)} {round(lon * 1e7)} {round(alt_m * 100)} 0 0 0 0")
    n = len(points)
    lines.append(f"wp {n} 4 0 0 0 {1 if rth_land else 0} 0 0 165")   # RTH, last point flag 0xA5
    lines += ["wp save", "wp"]
    return "\n".join(lines)

print(wp_cli([(50.4500000, 30.5200000), (50.4505000, 30.5205000), (50.4510000, 30.5200000)]))
```
Вывод вставить в CLI, затем сравнить с тем, что показывает вкладка Mission Control. Расхождение в координатах на 7-м знаке — норма округления; на 1–2-м — ошибка в порядке lat/lon.

### Шаг 3. Полёт
1. 3D-фикс, дом записан, миссия загружена (`wp` показывает список).
2. Арм, ANGLE, взлёт вручную на безопасную высоту.
3. Включить NAV WP тумблером. Следить за прохождением точек в OSD.
4. В любой момент — выключить NAV WP и забрать управление.

### Лабораторная
Записать одну миссию двумя способами (конфигуратор и CLI через генератор), сравнить вывод `wp` — он должен совпасть. Контроль генератора на координатах из шага 2б: первая строка `wp` после `wp reset` — `wp 0 1 504500000 305200000 3000 0 0 0 0`, последняя точка — `wp 3 4 0 0 0 1 0 0 165`; если широта и долгота поменялись местами, точка уедет уже в 1–2-м знаке. Прогнать с POSHOLD_TIME и RTH. Для каждой точки маршрута записать, что будет при потере RC и GPS именно там (высота RTH над препятствиями, место аварийной посадки).

## diagnostics
- **Симптом:** не армится с загруженной миссией
  - Возможная причина: первая точка дальше `nav_wp_max_safe_distance`.
  - Что сделать: перезаписать миссию под текущее место или сбросить.
- **Симптом:** аппарат идёт к точкам, но не садится в конце
  - Возможная причина: у RTH p1 = 0 (посадка запрещена) или `nav_rth_allow_landing` = NEVER.
  - Что сделать: поставить p1 = 1 и проверить `nav_rth_allow_landing`.
- **Симптом:** высота миссии не та
  - Возможная причина: бит 0 в p3 (абсолютная высота) или путаница сантиметров и метров.
  - Что сделать: проверить `p3` и единицы `alt`.
- **Симптом:** `wp` показывает пустой список после перезагрузки
  - Возможная причина: не выполнен `wp save`.
  - Что сделать: сохранить и проверить `wp load`.
- **Симптом:** аппарат пролетает мимо точек
  - Возможная причина: `nav_wp_radius` мал для скорости (особенно крыло).
  - Что сделать: радиус больше, скорость меньше у точек.
