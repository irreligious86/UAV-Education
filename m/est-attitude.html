Ориентация: углы Эйлера, кватернионы, комплементарный фильтр

L3 — Специалистчтение 40 минучёба ~4 члюбая прошивкаОСВОЕН

«Где верх» — первый вопрос, на который автопилот отвечает тысячу раз в секунду. Гироскоп даёт быстрый, но дрейфующий ответ; акселерометр — медленный и шумный, но без дрейфа; компас — курс. Модуль объясняет, почему углы Эйлера ломаются (gimbal lock) и прошивки живут на кватернионах, как интегрировать угловую скорость, как работает комплементарный фильтр (на Python, ~40 строк) и как он относится к DCM ArduPilot и к Mahony/Madgwick в Betaflight/INAV. Теория

Представления ориентации

  • Углы Эйлера (roll φ, pitch θ, yaw ψ) — удобны человеку. Проблема: при θ = ±90° roll и yaw сливаются (gimbal lock), и уравнения для скоростей изменения углов содержат деление на cos θ. Для фристайла с петлями — неприемлемо. Используются только для вывода (ATT.Roll/Pitch/Yaw).
  • Матрица поворота (DCM) — 3×3, столбцы — оси аппарата в земной системе. Без особых точек, но 9 чисел с 6 связями; нужна ортонормализация после интегрирования.
  • Кватернион q = (w, x, y, z), |q| = 1 — 4 числа, одна связь, без особых точек, дешёвое умножение. Стандарт в Betaflight (с 3.x), INAV, PX4 (vehicle_attitude.q), EKF3 (состояния 0–3).

Переход кватернион → Эйлер (для вывода): φ = atan2(2(wx + yz), 1 − 2(x² + y²)); θ = asin(2(wy − zx)); ψ = atan2(2(wz + xy), 1 − 2(y² + z²)).

Интегрирование гироскопа

Угловая скорость ω (в осях аппарата) меняет кватернион: q̇ = ½ · q ⊗ (0, ω). Дискретно за шаг Δt: q ← q ⊗ (cos(|ω|Δt/2), ω/|ω| · sin(|ω|Δt/2)), затем нормировать. Только гироскоп → дрейф со скоростью bias (0.05 °/с → 3°/мин) плюс накопление шума.

Комплементарный фильтр

Идея: гироскопу верим на высоких частотах, акселерометру (гравитации) — на низких. Алгоритм Mahony: 1. Предсказать «вниз» в осях аппарата из текущего q: v = R(q)ᵀ · (0, 0, 1). 2. Измеренный «вниз» — нормированный акселерометр a/|a|. 3. Ошибка — векторное произведение e = a × v (мал при согласии, направление — ось поправки). 4. Поправить угловую скорость: ω' = ω + Kp·e + Ki·∫e (Ki — оценка bias гироскопа!). 5. Проинтегрировать ω' в q.

Kp задаёт постоянную времени «доверия» акселерометру: τ ≈ 1/Kp; Kp = 0.5 → ~2 с. Во время манёвров |a| ≠ 1 g — акселерометр врёт; стандартная защита: уменьшать Kp, когда | |a| − g | велико (ArduPilot DCM: AHRS_GPS_GAIN, использование GPS для центростремительной поправки; Betaflight: imu_dcm_kp, отключение коррекции при больших ускорениях). Компас добавляется тем же способом для оси yaw: ошибка между измеренным и ожидаемым направлением горизонтальной составляющей поля.

Что это в прошивках

  • Betaflight: Mahony-подобный фильтр на кватернионах, imu_dcm_kp (по умолчанию 2500 → 0.25 после масштаба), imu_dcm_ki; без компаса yaw дрейфует — для Acro неважно, для GPS Rescue используется курс по GPS.
  • INAV: тот же класс фильтра + компас и GPS-курс, поправки с учётом ускорения по GPS.
  • ArduPilot: DCM (матрица, с поправкой по GPS-скорости) как резерв, основной — EKF3, где ориентация — часть вектора состояния вместе со скоростью, позицией и bias датчиков. Комплементарный фильтр — это EKF с постоянными, не адаптивными коэффициентами.
  • PX4: EKF2 (ekf2), ориентация в vehicle_attitude.

Почему yaw — особенный

Гравитация не содержит информации о курсе: без компаса или GPS-курса yaw дрейфует с bias гироскопа Z. На висении это ~3°/мин, незаметно; за 10 минут — 30°, и Loiter поедет по спирали («туалетная воронка» — классический симптом). Источники yaw: компас (помехи), GPS-курс при движении (не на висении), два GPS (moving baseline), EKF-GSF (оценка по движению, ArduPilot EK3_SRC1_YAW = 8), внешняя навигация.

Практика

Шаг 1. Запись IMU

ArduPilot: лог с IMU (gyro, accel) и ATT; LOG_BITMASK с IMU_RAW не нужен — 50–400 Гц IMU достаточно. Betaflight: blackbox с debug_mode = ATTITUDE (пишет углы) или использовать gyro + accel из обычного лога. Полёт 2–3 минуты с наклонами и висением.

Шаг 2. Свой фильтр

import numpy as np
def qmul(a, b):
    w1,x1,y1,z1 = a; w2,x2,y2,z2 = b
    return np.array([w1*w2-x1*x2-y1*y2-z1*z2, w1*x2+x1*w2+y1*z2-z1*y2,
                     w1*y2-x1*z2+y1*w2+z1*x2, w1*z2+x1*y2-y1*x2+z1*w2])
def down_body(q):          # gravity direction in body frame from quaternion (w,x,y,z)
    w,x,y,z = q
    return np.array([2*(x*z - w*y), 2*(w*x + y*z), w*w - x*x - y*y + z*z])
def mahony(gyro, acc, dt, kp=0.5, ki=0.01):
    q = np.array([1.0, 0, 0, 0]); ib = np.zeros(3); out = []
    for g, a in zip(gyro, acc):                 # g in rad/s, a in m/s^2 (body frame)
        an = np.linalg.norm(a)
        if an > 1e-3:
            a_u = a / an; v = down_body(q)
            e = np.cross(a_u, v)
            trust = 1.0 if abs(an - 9.81) < 2.0 else 0.0   # ignore accel during hard manoeuvres
            ib += ki * e * dt * trust
            g = g + (kp * e * trust) + ib
        n = np.linalg.norm(g)
        if n > 1e-9:
            dq = np.concatenate([[np.cos(n*dt/2)], g/n*np.sin(n*dt/2)])
            q = qmul(q, dq); q /= np.linalg.norm(q)
        w,x,y,z = q
        out.append([np.degrees(np.arctan2(2*(w*x+y*z), 1-2*(x*x+y*y))),
                    np.degrees(np.arcsin(np.clip(2*(w*y-z*x), -1, 1)))])
    return np.array(out)

Прогнать на своей записи; построить roll/pitch против ATT.Roll/Pitch (ArduPilot) или углов из debug-лога.

Шаг 3. Эксперименты

  • Ki = 0: наблюдать медленный уход при постоянном bias.
  • Kp = 0: только гироскоп — дрейф.
  • Kp = 5: акселерометр «тянет» в манёврах — ошибки во время разгона.
  • Сравнить RMS-ошибку относительно ATT при трёх Kp.

Шаг 4. Yaw

Проинтегрировать gyro Z без коррекции — записать дрейф за минуту; сравнить с ATT.Yaw. Объяснить, откуда прошивка берёт курс. Лабораторная: фильтр реализован, сравнение с ATT, дрейф yaw объяснён.

Диагностика

Симптом: горизонт в OSD уезжает после резких манёвров и медленно возвращается

  • Возможная причина: гироскоп накопил ошибку, Kp мал — долгое восстановление.
  • Что сделать: норма для Acro; для Angle — поднять Kp умеренно, проверить вибрации.

Симптом: Loiter ходит по спирали, курс в OSD не совпадает с реальным

  • Возможная причина: дрейф yaw / плохой компас.
  • Что сделать: компас, GPS yaw, GSF; проверить помехи.

Симптом: свой фильтр расходится с ATT на 5–10° в манёврах

  • Возможная причина: без компенсации центростремительного ускорения.
  • Что сделать: добавить коррекцию по GPS-скорости или снижать доверие accel при |a| ≠ g.

Симптом: NaN в кватернионе

  • Возможная причина: нормировка пропущена или acc = 0.
  • Что сделать: проверять нормы, защищать деления.
