Слежение и управление по цели

L4 — Экспертчтение 40 минучёба ~4 чArduPilot · PX4ОСВОЕН

Замкнуть контур «камера → ошибка в кадре → команда скорости» просто; сделать так, чтобы он не раскачивался и не улетал при потере цели — инженерная задача. Модуль собирает её из уже пройденного: детектор и трекер (per-cv), задержка цепочки (камера → инференс → команда → автопилот → отклик), теория управления (запас по фазе при задержке 100–200 мс), интерфейсы GUIDED (ArduPilot SET_POSITION_TARGET_LOCAL_NED со скоростями) и Offboard (PX4 TrajectorySetpoint), защиты (лимиты скорости/ускорения, watchdog по детекциям, таймаут потери цели → зависание, геозона, ручной перехват). Лабораторная в SITL с симулированной целью; стартовый код — в examples/ros2-skeleton.

После модуля ты умеешь
  • замкнуть контур: ошибка в кадре → команда скорости в GUIDED/Offboard
  • учесть задержку и ограничить динамику
  • построить защиты: потеря цели, таймауты

Теория

От пикселя к команде

Ошибка в кадре (e_x, e_y) в нормированных координатах [−1, 1] от центра. Для камеры, смотрящей вниз: смещение цели в метрах ≈ h · tan(e·FOV/2) — при малых углах линейно по e и пропорционально высоте h. Команда скорости: v = K_p · (смещение) с ограничением |v| ≤ v_max. Для камеры вперёд/под углом — геометрия сложнее: нужно знать угол камеры и высоту (или дальность до цели по размеру бокса), иначе K_p «плавает» с расстоянием. Гимбал с управлением по цели (ArduPilot MNT1_*/GIMBAL_MANAGER) разделяет задачи: гимбал держит цель в центре, аппарат летит на углы гимбала.

Структура контура: внешний (наш, 10–30 Гц, по ошибке изображения) выдаёт скорость → внутренний (автопилот: скорость → углы → рейты, 50–400 Гц). Правило каскада из теории управления: наш контур должен быть заметно медленнее контура скорости автопилота — и он таким и будет из-за задержки.

Задержка — главный ограничитель

Цепочка: экспозиция + захват (10–30 мс) → инференс (10–50) → трекер/команда (1–5) → MAVLink/DDS (2–10) → автопилот принимает setpoint скорости и отрабатывает (контур скорости PSC_VELXY_P, постоянная времени 0.3–1 с). Итого 50–150 мс чистой задержки + динамика. При задержке T_d и усилении K_p контур P-типа начинает осциллировать на частоте порядка 1/(4·T_d) (фаза −90° от задержки + −90° от интегратора «скорость → позиция»): при T_d = 100 мс — около 2.5 Гц, и предел K_p ≈ π/(2·T_d) ≈ 15 1/с в идеале. Но автопилот не меняет скорость мгновенно: с отработкой скорости τ ≈ 0.4 с предел падает до ~10 1/с при 100 мс и ~3.7 1/с при 300 мс, а с ограничениями скорости и ускорения (насыщение) — ещё ниже: ~7.8 и ~2.8 1/с (симуляция в практике). Рабочий K_p выбирают в 3–5 раз ниже предела ради запаса по фазе — отсюда типичные 0.5–2 1/с (м/с на метр ошибки). Приёмы: предсказание положения цели трекером на T_d вперёд, фильтр команды, D-составляющая по скорости цели (из трекера), ограничение ускорения — и прежде всего уменьшение задержки.

Интерфейсы

ArduPilot GUIDED: SET_POSITION_TARGET_LOCAL_NED с type_mask, разрешающим только скорости (0b110111000111 = 3527: позиция, ускорение, курс и скорость курса игнорируются, работают vx, vy, vz), frame MAV_FRAME_BODY_OFFSET_NED (скорость в осях аппарата — удобно для слежения) или LOCAL_NED; слать ≥ 2–3 Гц, иначе через GUID_TIMEOUT (3 с) цели сбрасываются (аппарат зависает — это и есть защита). Ограничения автопилота: WP_SPD (до 4.7 — WPNAV_SPEED), PSC_*, GUID_OPTIONS. Пилот перехватывает сменой режима с пульта — всегда. PX4 Offboard: OffboardControlMode (velocity=true) + TrajectorySetpoint (velocity, position NaN) на ≥ 2 Гц (рекомендуется 10+), COM_OF_LOSS_T (таймаут потери offboard) и COM_OBL_RC_ACT (действие); вход в Offboard — после потока setpoint'ов, арм — VehicleCommand. Через MAVROS — /mavros/setpoint_velocity/cmd_vel_unstamped в режиме OFFBOARD.

Защиты (обязательные)

  1. Лимиты: v_max (1–3 м/с для первых тестов), a_max (1–2 м/с²), высота — фиксированная или с нижним пределом, геозона включена.
  2. Watchdog детекций: нет валидной детекции 0.3–0.5 с → команда нулевой скорости (зависание), не «последняя команда».
  3. Таймаут потери цели: 2–5 с без цели → зависание и выход из режима (Loiter/Hold), сообщение оператору; повторный захват — только по команде.
  4. Санитизация: NaN/бесконечности, скачки ошибки > порога (ложная детекция) — отбрасывать; трекер с минимальным числом кадров подтверждения.
  5. Перехват: смена режима с пульта мгновенно обрывает контур; companion не должен «бороться» — после перехвата публикация прекращается.
  6. Логи: companion пишет ошибку, команду, статус трекера с timestamp; синхронизировано с логом FC — иначе разбор невозможен.

Тест-план

SITL + симулированная цель (точка, движущаяся по известному закону, проецируемая в «кадр» по позиции аппарата) → реальная камера на стенде (аппарат привязан, цель на полу движется) → низкий полёт над открытой площадкой с наблюдателем и пилотом с пальцем на тумблере.

Практика

Шаг 1. Симулированная цель в SITL

Скрипт: цель движется по кругу R = 10 м, 0.5 м/с; «камера» вниз с FOV 90°: ошибка в кадре = (цель − позиция аппарата)/(h·tan45°), ограничена [−1, 1]; детекция «теряется» с вероятностью 5% на кадр + «слепое» окно 3 с раз в минуту. 20 Гц.

Шаг 2. Предел усиления: расчёт и симуляция

Прежде чем лететь — посчитать. Одномерная модель контура: ошибка из кадра с задержкой T_d → команда скорости K_p·e → автопилот отрабатывает скорость с постоянной времени τ и лимитами:

import math

def run(kp, delay, tau_v=0.4, v_max=3.0, a_max=3.0, dt=0.01, T=30.0):
    """1-D loop: delayed image error -> velocity command -> autopilot velocity lag tau_v.
    Start 5 m off a still target; returns peak |error| over the last 10 s (large = unstable)."""
    n_d = int(round(delay / dt))
    seen = [5.0] * (n_d + 1)                # what the camera reported n_d steps ago
    x, v, tail = 5.0, 0.0, 0.0
    for k in range(int(T / dt)):
        cmd = max(-v_max, min(v_max, -kp * seen[0]))
        dv = max(-a_max * dt, min(a_max * dt, (cmd - v) / tau_v * dt))
        v += dv
        x += v * dt
        seen = seen[1:] + [x]
        if k * dt > T - 10:
            tail = max(tail, abs(x))
    return tail

def critical_kp(delay, **kw):
    lo, hi = 0.05, 30.0
    for _ in range(40):                     # bisection: largest Kp that still settles
        mid = (lo + hi) / 2
        lo, hi = (mid, hi) if run(mid, delay, **kw) < 0.05 else (lo, mid)
    return lo

def analytic_kp(delay, tau_v=0.4):
    """Zero phase margin of Kp·e^(-s·Td) / (s·(tau_v·s + 1))."""
    lo, hi = 0.01, 100.0
    for _ in range(100):
        w = (lo + hi) / 2
        lo, hi = (w, hi) if math.atan(w * tau_v) + w * delay < math.pi / 2 else (lo, w)
    return w * math.hypot(1, w * tau_v)

for d in (0.1, 0.3):
    print(f"T_d = {d * 1000:.0f} мс: без динамики {math.pi / (2 * d):4.1f}, "
          f"с τ = 0.4 с {analytic_kp(d):4.1f}, с лимитами v и a {critical_kp(d):4.1f}  (1/с)")
# T_d = 100 мс: без динамики 15.7, с τ = 0.4 с 10.4, с лимитами v и a  7.8  (1/с)
# T_d = 300 мс: без динамики  5.2, с τ = 0.4 с  3.7, с лимитами v и a  2.8  (1/с)

Поменять τ (0.2 и 0.8 с — так отличаются лёгкий и тяжёлый аппарат) и a_max, записать, как сдвигается предел. Выбрать K_p для своей задержки с запасом в 3–5 раз.

Шаг 3. Контур в SITL

P-регулятор скорости в GUIDED (BODY_OFFSET_NED) или Offboard из examples/ros2-skeleton: выбранный K_p, v_max = 2, a_max = 2. Записать ошибку во времени; добавить искусственную задержку 100 и 300 мс и поднимать K_p до раскачки — сравнить найденный предел с симуляцией шага 2.

Шаг 4. Защиты

Проверить каждую: watchdog (цель пропала 0.5 с → скорость 0), таймаут (3 с → Loiter), ложная детекция (скачок ошибки → отброшен), перехват с пульта (переключить режим в SITL через RC override) — companion замолкает.

Шаг 5. Разбор

Совместный график: ошибка, команда, фактическая скорость (XKF1.VN/VE), режим; задержка цепочки по кросс-корреляции команда → скорость. Лабораторная засчитывается, когда предел K_p посчитан для своей задержки и подтверждён в SITL, контур работает с лимитами, каждая защита проверена (watchdog, таймаут, ложная детекция, перехват), задержка цепочки измерена по кросс-корреляции.

Диагностика

Симптом: аппарат раскачивается вокруг цели

  • Возможная причина: K_p велик для задержки.
  • Что сделать: снизить K_p, уменьшить задержку, предсказание цели, ограничение ускорения.

Симптом: медленно догоняет движущуюся цель

  • Возможная причина: только P — статическая ошибка по скорости.
  • Что сделать: FF по скорости цели из трекера, умеренный I с anti-windup.

Симптом: рывки при каждой детекции

  • Возможная причина: команды от сырого детектора без трекера/фильтра.
  • Что сделать: трекер, фильтр команды, ограничение ускорения.

Симптом: после потери цели аппарат улетел по последней команде

  • Возможная причина: нет watchdog, автопилот держал последнюю скорость до GUID_TIMEOUT.
  • Что сделать: watchdog 0.5 с → нулевая скорость; таймаут → Loiter.

Симптом: команды не принимаются

  • Возможная причина: не GUIDED/Offboard, низкая частота setpoint'ов, type_mask.
  • Что сделать: проверить режим, ≥ 10 Гц, маску; смотреть GUIDED сообщения/COM_OF_LOSS_T.
