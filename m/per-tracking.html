Слежение и управление по цели

L4 — Экспертчтение 40 минучёба ~4 чArduPilot · PX4ОСВОЕН

Замкнуть контур «камера → ошибка в кадре → команда скорости» просто; сделать так, чтобы он не раскачивался и не улетал при потере цели — инженерная задача. Модуль собирает её из уже пройденного: детектор и трекер (per-cv), задержка цепочки (камера → инференс → команда → автопилот → отклик), теория управления (запас по фазе при задержке 100–200 мс), интерфейсы GUIDED (ArduPilot SET_POSITION_TARGET_LOCAL_NED со скоростями) и Offboard (PX4 TrajectorySetpoint), защиты (лимиты скорости/ускорения, watchdog по детекциям, таймаут потери цели → зависание, геозона, ручной перехват). Лабораторная в SITL с симулированной целью; стартовый код — в examples/ros2-skeleton.

После модуля ты умеешь
  • замкнуть контур: ошибка в кадре → команда скорости в GUIDED/Offboard
  • учесть задержку и ограничить динамику
  • построить защиты: потеря цели, таймауты

Теория

От пикселя к команде

Ошибка в кадре (e_x, e_y) в нормированных координатах [−1, 1] от центра. Для камеры, смотрящей вниз: смещение цели в метрах ≈ h · tan(e·FOV/2) — при малых углах линейно по e и пропорционально высоте h. Команда скорости: v = K_p · (смещение) с ограничением |v| ≤ v_max. Для камеры вперёд/под углом — геометрия сложнее: нужно знать угол камеры и высоту (или дальность до цели по размеру бокса), иначе K_p «плавает» с расстоянием. Гимбал с управлением по цели (ArduPilot MNT_*/GIMBAL_MANAGER) разделяет задачи: гимбал держит цель в центре, аппарат летит на углы гимбала.

Структура контура: внешний (наш, 10–30 Гц, по ошибке изображения) выдаёт скорость → внутренний (автопилот: скорость → углы → рейты, 50–400 Гц). Правило каскада из теории управления: наш контур должен быть заметно медленнее контура скорости автопилота — и он таким и будет из-за задержки.

Задержка — главный ограничитель

Цепочка: экспозиция + захват (10–30 мс) → инференс (10–50) → трекер/команда (1–5) → MAVLink/DDS (2–10) → автопилот принимает setpoint скорости и отрабатывает (контур скорости PSC_VELXY_P, постоянная времени 0.3–1 с). Итого 50–150 мс чистой задержки + динамика. При задержке T_d и усилении K_p контур P-типа начинает осциллировать на частоте порядка 1/(4·T_d) (фаза −90° от задержки + −90° от интегратора «скорость → позиция»): при T_d = 100 мс — около 2.5 Гц, и предел K_p ≈ π/(2·T_d) ≈ 15 1/с в идеале; на практике K_p 0.5–2 1/с (м/с на метр ошибки) с запасом. Приёмы: предсказание положения цели трекером на T_d вперёд, фильтр команды, D-составляющая по скорости цели (из трекера), ограничение ускорения — и прежде всего уменьшение задержки.

Интерфейсы

ArduPilot GUIDED: SET_POSITION_TARGET_LOCAL_NED с type_mask, разрешающим только скорости (0b0000111111000111 → vx, vy, vz, yaw/yaw_rate по желанию), frame MAV_FRAME_BODY_OFFSET_NED (скорость в осях аппарата — удобно для слежения) или LOCAL_NED; слать ≥ 2–3 Гц, иначе через GUID_TIMEOUT (3 с) цели сбрасываются (аппарат зависает — это и есть защита). Ограничения автопилота: WPNAV_SPEED, PSC_*, GUID_OPTIONS. Пилот перехватывает сменой режима с пульта — всегда. PX4 Offboard: OffboardControlMode (velocity=true) + TrajectorySetpoint (velocity, position NaN) на ≥ 2 Гц (рекомендуется 10+), COM_OF_LOSS_T (таймаут потери offboard) и COM_OBL_RC_ACT (действие); вход в Offboard — после потока setpoint'ов, арм — VehicleCommand. Через MAVROS — /mavros/setpoint_velocity/cmd_vel_unstamped в режиме OFFBOARD.

Защиты (обязательные)

  1. Лимиты: v_max (1–3 м/с для первых тестов), a_max (1–2 м/с²), высота — фиксированная или с нижним пределом, геозона включена.
  2. Watchdog детекций: нет валидной детекции 0.3–0.5 с → команда нулевой скорости (зависание), не «последняя команда».
  3. Таймаут потери цели: 2–5 с без цели → зависание и выход из режима (Loiter/Hold), сообщение оператору; повторный захват — только по команде.
  4. Санитизация: NaN/бесконечности, скачки ошибки > порога (ложная детекция) — отбрасывать; трекер с минимальным числом кадров подтверждения.
  5. Перехват: смена режима с пульта мгновенно обрывает контур; companion не должен «бороться» — после перехвата публикация прекращается.
  6. Логи: companion пишет ошибку, команду, статус трекера с timestamp; синхронизировано с логом FC — иначе разбор невозможен.

Тест-план

SITL + симулированная цель (точка, движущаяся по известному закону, проецируемая в «кадр» по позиции аппарата) → реальная камера на стенде (аппарат привязан, цель на полу движется) → низкий полёт над открытой площадкой с наблюдателем и пилотом с пальцем на тумблере.

Практика

Шаг 1. Симулированная цель в SITL

Скрипт: цель движется по кругу R = 10 м, 0.5 м/с; «камера» вниз с FOV 90°: ошибка в кадре = (цель − позиция аппарата)/(h·tan45°), ограничена [−1, 1]; детекция «теряется» с вероятностью 5% на кадр + «слепое» окно 3 с раз в минуту. 20 Гц.

Шаг 2. Контур

P-регулятор скорости в GUIDED (BODY_OFFSET_NED) или Offboard из examples/ros2-skeleton: K_p = 1.0, v_max = 2, a_max = 2. Записать ошибку во времени; добавить искусственную задержку 100 и 300 мс — найти K_p осцилляций; сравнить с оценкой π/(2·T_d).

Шаг 3. Защиты

Проверить каждую: watchdog (цель пропала 0.5 с → скорость 0), таймаут (3 с → Loiter), ложная детекция (скачок ошибки → отброшен), перехват с пульта (переключить режим в SITL через RC override) — companion замолкает.

Шаг 4. Разбор

Совместный график: ошибка, команда, фактическая скорость (XKF1.VN/VE), режим; задержка цепочки по кросс-корреляции команда → скорость. Лабораторная: контур работает в SITL, задержка учтена (K_p обоснован), потеря цели → зависание.

Диагностика

Симптом: аппарат раскачивается вокруг цели

  • Возможная причина: K_p велик для задержки.
  • Что сделать: снизить K_p, уменьшить задержку, предсказание цели, ограничение ускорения.

Симптом: медленно догоняет движущуюся цель

  • Возможная причина: только P — статическая ошибка по скорости.
  • Что сделать: FF по скорости цели из трекера, умеренный I с anti-windup.

Симптом: рывки при каждой детекции

  • Возможная причина: команды от сырого детектора без трекера/фильтра.
  • Что сделать: трекер, фильтр команды, ограничение ускорения.

Симптом: после потери цели аппарат улетел по последней команде

  • Возможная причина: нет watchdog, автопилот держал последнюю скорость до GUID_TIMEOUT.
  • Что сделать: watchdog 0.5 с → нулевая скорость; таймаут → Loiter.

Симптом: команды не принимаются

  • Возможная причина: не GUIDED/Offboard, низкая частота setpoint'ов, type_mask.
  • Что сделать: проверить режим, ≥ 10 Гц, маску; смотреть GUIDED сообщения/COM_OF_LOSS_T.
