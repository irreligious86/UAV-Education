Веб-GCS: телеметрія, карта, режими

Проєкт 1L3~30 годє стартерЗДАНО

Наземна станція в браузері: бекенд читає MAVLink і роздає телеметрію по WebSocket, фронтенд малює апарат на карті, показує режим, батарею та STATUSTEXT, уміє армити й змінювати режим із підтвердженням.

Стек

  • Python 3, pymavlink, asyncio
  • WebSocket (websockets)
  • JS, Leaflet, без фреймворка
  • ArduPilot SITL

Стартер: examples/web-gcs — клонуй і починай з його README.

Може замінити підсумковий проєкт треку «Інженер: код на борту».

Етапи

  1. Міст MAVLink → JSON по WebSocket: HEARTBEAT, GLOBAL_POSITION_INT, ATTITUDE, SYS_STATUS, STATUSTEXT
    Перевірка: pytest examples/web-gcs/tests -k "frame or battery"
  2. Сторінка з картою й маркером апарата, режим і батарея на панелі
    Перевірка: демонстрація у звіті
  3. Команди з браузера: arm/disarm і зміна режиму через COMMAND_LONG з очікуванням ACK, відповідь в UI
    Перевірка: pytest examples/web-gcs/tests -k commands_are_acked
  4. Стійкість: втрату зв'язку видно за 3 с (heartbeat timeout), перепідключення без перезавантаження сторінки
    Перевірка: pytest examples/web-gcs/tests -k link_loss
  5. Запис сесії в tlog і відтворення її в тому самому UI
    Перевірка: демонстрація у звіті

Критерії приймання

Проєкт здано, коли виконано всі пункти. Позначай у міру готовності:

Автоперевірка

pytest examples/web-gcs/tests: розбір повідомлень у JSON, команди з ACK, таймаут heartbeat

Оцінка

Здано — коли виконано всі критерії приймання. Рівень роботи — за критеріями нижче; кожен рівень включає попередній.

  • Функціональність
    • Зараховано: Усі етапи працюють у сценарії з README
    • Добре: Плюс сценарії відмов: втрата зв'язку, пропуск даних, хибне введення
    • Відмінно: Плюс хоча б одне завдання «на відмінно» зі списку проєкту
  • Перевірюваність
    • Зараховано: Тести стартера проходять, власні функції покрито хоча б одним тестом
    • Добре: Тест на кожен етап; тести запускаються в CI
    • Відмінно: Тести на відмови й регресію на власних даних; покриття ключової логіки видно у звіті
  • Інженерний звіт
    • Зараховано: Є заміри, яких вимагають критерії приймання
    • Добре: Заміри з методикою та повторюваністю (кілька прогонів, розкид)
    • Відмінно: Порівняння варіантів рішення з висновком, обмеження та що робити далі
  • Код і документація
    • Зараховано: README: запуск однією командою, архітектура
    • Добре: Модулі розділено, інтерфейси описано, немає «магічних чисел» без пояснення
    • Відмінно: Код читається без автора: docs/, приклади, історія комітів за етапами
