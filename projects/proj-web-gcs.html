Веб-GCS: телеметрия, карта, режимы

Проект 1L3~30 честь стартерСДАН

Наземная станция в браузере: бэкенд читает MAVLink и раздаёт телеметрию по WebSocket, фронтенд рисует аппарат на карте, показывает режим, батарею и STATUSTEXT, умеет армить и менять режим с подтверждением.

Стек

  • Python 3, pymavlink, asyncio
  • WebSocket (websockets)
  • JS, Leaflet, без фреймворка
  • ArduPilot SITL

Стартер: examples/web-gcs — клонируйте и начинайте с его README.

Может заменить итоговый проект трека «Инженер: код на борту».

Этапы

  1. Мост MAVLink → JSON по WebSocket: HEARTBEAT, GLOBAL_POSITION_INT, ATTITUDE, SYS_STATUS, STATUSTEXT
    Проверка: pytest examples/web-gcs/tests -k "frame or battery"
  2. Страница с картой и маркером аппарата, режим и батарея на панели
    Проверка: демонстрация в отчёте
  3. Команды из браузера: arm/disarm и смена режима через COMMAND_LONG с ожиданием ACK, ответ в UI
    Проверка: pytest examples/web-gcs/tests -k commands_are_acked
  4. Устойчивость: потеря связи видна за 3 с (heartbeat timeout), переподключение без перезагрузки страницы
    Проверка: pytest examples/web-gcs/tests -k link_loss
  5. Запись сессии в tlog и воспроизведение её в том же UI
    Проверка: демонстрация в отчёте

Критерии приёмки

Проект сдан, когда выполнены все пункты. Отмечайте по мере готовности:

Автопроверка

pytest examples/web-gcs/tests: разбор сообщений в JSON, команды с ACK, таймаут heartbeat

Оценка

Сдан — когда выполнены все критерии приёмки. Уровень работы — по критериям ниже; каждый уровень включает предыдущий.

  • Функциональность
    • Засчитано: Все этапы работают в сценарии из README
    • Хорошо: Плюс отказные сценарии: потеря связи, пропуск данных, неверный ввод
    • Отлично: Плюс хотя бы одно задание «на отлично» из списка проекта
  • Проверяемость
    • Засчитано: Тесты стартера проходят, свои функции покрыты хотя бы одним тестом
    • Хорошо: Тест на каждый этап; тесты запускаются в CI
    • Отлично: Тесты на отказы и регрессию на собственных данных; покрытие ключевой логики видно в отчёте
  • Инженерный отчёт
    • Засчитано: Есть замеры, которых требуют критерии приёмки
    • Хорошо: Замеры с методикой и повторяемостью (несколько прогонов, разброс)
    • Отлично: Сравнение вариантов решения с выводом, ограничения и что делать дальше
  • Код и документация
    • Засчитано: README: запуск одной командой, архитектура
    • Хорошо: Модули разделены, интерфейсы описаны, нет «магических чисел» без пояснения
    • Отлично: Код читается без автора: docs/, примеры, история коммитов по этапам

Задания «на отлично»

  • Загрузка и редактирование миссии на карте (MISSION_ITEM_INT) с проверкой обратным чтением
  • Несколько аппаратов в одном UI по sysid

Что сдать

  • Репозиторий с backend/, web/, docs/protocol.md
  • Видео или GIF: полёт миссии в SITL в вашем UI
  • Отчёт: замер задержки, что сделано для устойчивости

Нужные модули

  1. MAVLink изнутри: кадр, CRC, диалекты, подпись
  2. Микросервисы MAVLink: команды, параметры, миссии, потоки
  3. Маршрутизация и транспорт MAVLink: радио, 4G, несколько GCS
  4. Библиотеки над MAVLink: pymavlink, MAVSDK, MAVROS — что и когда
  5. Raspberry Pi + ArduPilot
  6. SITL: дрон без дрона
Безопасность. Всё, что управляет аппаратом, сначала проходит тесты и SITL. Реальный полёт — только с проверенным failsafe и пилотом, готовым забрать управление.
