CI/CD для флота

Проект 10L3~20 честь стартерСДАН

Параметры и скрипты флота живут в git; каждый коммит прогоняет тест failsafe и миссию в SITL, сравнивает параметры с эталоном и собирает артефакт для выкладки на аппарат.

Стек

  • GitHub Actions
  • ArduPilot SITL
  • pymavlink
  • параметры в .param, Lua-скрипты

Стартер: examples/sitl-pymavlink — клонируйте и начинайте с его README.

Может заменить итоговый проект трека «Инженер: код на борту».

Этапы

  1. Репозиторий флота: параметры по аппаратам, общие и личные
    Проверка: демонстрация в отчёте
  2. Workflow: SITL + тест failsafe (стартер ci.yml)
    Проверка: python examples/sitl-pymavlink/test_check_lab_log.py
  3. Diff параметров против эталона с объяснением изменений
    Проверка: демонстрация в отчёте
  4. Тест миссии и проверка лога грейдером
    Проверка: python examples/sitl-pymavlink/check_lab_log.py flight.bin --lab mission --json result.json
  5. Выкладка: артефакт с параметрами и чек-листом
    Проверка: демонстрация в отчёте

Критерии приёмки

Проект сдан, когда выполнены все пункты. Отмечайте по мере готовности:

Автопроверка

сам workflow — это тест (examples/sitl-pymavlink/ci.yml, check_lab_log.py)

Оценка

Сдан — когда выполнены все критерии приёмки. Уровень работы — по критериям ниже; каждый уровень включает предыдущий.

  • Функциональность
    • Засчитано: Все этапы работают в сценарии из README
    • Хорошо: Плюс отказные сценарии: потеря связи, пропуск данных, неверный ввод
    • Отлично: Плюс хотя бы одно задание «на отлично» из списка проекта
  • Проверяемость
    • Засчитано: Тесты стартера проходят, свои функции покрыты хотя бы одним тестом
    • Хорошо: Тест на каждый этап; тесты запускаются в CI
    • Отлично: Тесты на отказы и регрессию на собственных данных; покрытие ключевой логики видно в отчёте
  • Инженерный отчёт
    • Засчитано: Есть замеры, которых требуют критерии приёмки
    • Хорошо: Замеры с методикой и повторяемостью (несколько прогонов, разброс)
    • Отлично: Сравнение вариантов решения с выводом, ограничения и что делать дальше
  • Код и документация
    • Засчитано: README: запуск одной командой, архитектура
    • Хорошо: Модули разделены, интерфейсы описаны, нет «магических чисел» без пояснения
    • Отлично: Код читается без автора: docs/, примеры, история коммитов по этапам

Задания «на отлично»

  • Автоматический diff параметров с объяснением из документации
