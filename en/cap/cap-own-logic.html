Your own logic + an ESP32 module

Track 6 capstone projectPASSED

Result: a working module, an exchange protocol, a README and tests

What to submit

  • Repository: firmware/, lua/ or a companion service, docs/
  • Exchange protocol: every message, its fields, who is allowed to send it
  • README with installation and usage
  • Tests: echo/heartbeat, timeout, companion failure
  • Demo in SITL (and in the air only with a geofence and a pilot)
  • Project engineering folder: requirements with IDs, what was tested and how, changelog (see the "Engineering Method 101" module)

Software alternative

A track's capstone project can be replaced with a project from the “UAS software” catalog — with the same submission requirements: criteria, automated tests, README.

  • Project 1: Web GCS: telemetry, map, flight modes
  • Project 2: Fleet telemetry to the cloud + dashboard
  • Project 8: MAVLink component on ESP32 + SITL twin
  • Project 9: 4G/Wi-Fi bridge with reconnection and encryption
  • Project 10: CI/CD for a fleet
  • Project 12: Companion module for the TX16S radio

Track modules

  1. Companion: why, and where the boundary is
  2. MAVLink and MAVSDK
  3. MAVLink internals: frame, CRC, dialects, signing
  4. MAVLink microservices: commands, parameters, missions, streams
  5. Libraries on top of MAVLink: pymavlink, MAVSDK, MAVROS: what to use and when
  6. ESP32 and peripherals
  7. Embedded: interrupts, timers, DMA, RTOS
  8. UART, I2C, SPI, CAN at the signal and driver level
  9. Raspberry Pi + ArduPilot
  10. MAVLink routing and transport: radio, 4G, multiple GCSs
  11. Remote ID and vehicle security: broadcast, MAVLink signing, firmware protection
  12. Your own MAVLink component: sensor, parameters, messages
  13. Gimbals and payload: MAVLink Gimbal v2, camera, drop
  14. Companion + ArduPilot: control from code
  15. Multiple vehicles: addressing, separation, formation and a supervisor
  16. Your own firmware builds
  17. How to read firmware source code: Betaflight and ArduPilot
  18. Systems engineering: requirements, FMEA, documentation, tests
  19. CI and versioning of configs and code
Safety. Everything you can do in SITL or without props, you do there. Real flights only after ground tests, with a verified failsafe.
