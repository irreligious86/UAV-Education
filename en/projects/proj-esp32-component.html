MAVLink component on ESP32 + SITL twin

Project 8L3~30 hhas a starterPASSED

An ESP32 as a full MAVLink component: its own heartbeat and compid, a sensor (rangefinder or current) in DISTANCE_SENSOR/BATTERY_STATUS, and command handling. A Python twin of the same component passes the same tests against SITL and a fake vehicle.

Stack

  • ESP-IDF или PlatformIO, C
  • c_library_v2
  • Python-двойник (examples/mavlink)
  • ArduPilot SITL

Starter: examples/mavlink — clone it and start with its README.

Can replace the capstone project of track “Engineer: code on board”.

Stages

  1. Python twin passes the tests (starter: virtual_rangefinder.py)
    Verification: pytest examples/mavlink/tests -k rangefinder
  2. ESP32 firmware: UART MAVLink, heartbeat, DISTANCE_SENSOR
    Verification: demo in the report
  3. Receiving COMMAND_LONG with ACK
    Verification: pytest examples/mavlink/tests -k "arm_command or rejected"
  4. The autopilot uses the component (RNGFND1_TYPE=10), verified in the log
    Verification: demo in the report
  5. Test bench: ESP32 ↔ USB-UART ↔ SITL on a PC
    Verification: demo in the report

Acceptance criteria

The project is passed when all items are done. Check them off as you go:

Auto-check

pytest examples/mavlink/tests as a starting point; add tests for your component

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • Component parameters via PARAM_* (your component in the GCS parameter list)
  • MAVLink 2 signing between the ESP32 and the autopilot

What to submit

  • Firmware, digital twin, tests, SITL log with the sensor

Required modules

  1. Your own MAVLink component: sensor, parameters, messages
  2. MAVLink internals: frame, CRC, dialects, signing
  3. ESP32 and peripherals
  4. UART, I2C, SPI, CAN at the signal and driver level
  5. SITL: a drone without a drone
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
