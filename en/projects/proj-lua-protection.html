CourseProjectsProject 11

A Lua safeguard package with tests

Project 11L3~20 hhas a starterPASSED

A set of ArduPilot Lua scripts for your mission (vibration monitoring, polygon geofence, payload protection), each with a SITL test and clear behavior when the script itself fails.

Stack

  • ArduPilot Lua scripting
  • SITL
  • pymavlink-тесты

Starter: examples/lua-protection — clone it and start with its README.

Can replace the capstone project of track “Autonomy”.

Stages

  1. Script skeleton: parameters, rate, logging, error handling
    Verification: pytest examples/lua-protection/tests -k "quiet or disarm"
  2. The first safeguard and its SITL test
    Verification: pytest examples/lua-protection/tests -k vibration
  3. Two more safeguards
    Verification: pytest examples/lua-protection/tests -k polygon
  4. Behavior on script error: safe mode
    Verification: pytest examples/lua-protection/tests -k "errors or no_fix"
  5. Parameter documentation
    Verification: demo in the report

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • A third protection (voltage sag under load) with a test via a mock and in SITL
  • Safeguard parameters can be changed in flight without restarting the script

What to submit

  • Scripts, tests, documentation

Required modules

  1. Lua: scenarios and fault injection
  2. Fault tolerance: failsafe, geofence, flight FMEA
  3. SITL: a drone without a drone
  4. CI and versioning of configs and code
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
