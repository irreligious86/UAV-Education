Detector + tracker + following in Gazebo

Project 4L4~45 hhas a starterPASSED

A simulated camera → detector (YOLO-nano or color-based) → tracker → controller that keeps the target centered in the frame at a set distance using velocity setpoints in Offboard/GUIDED.

Stack

  • ROS 2 Humble
  • Gazebo + PX4 или ArduPilot SITL
  • OpenCV, ONNX Runtime
  • examples/ros2-docker

Starter: examples/follow-target — clone it and start with its README.

Can replace the capstone project of track “Perception and intelligence”.

Stages

  1. Camera stream from Gazebo into ROS 2, FPS measured
    Verification: demo in the report
  2. Detector with metrics on a recorded bag
    Verification: demo in the report
  3. A tracker with IDs and prediction during dropouts
    Verification: demo in the report
  4. Follow controller (starter: follow.py, a pure function with limits and a target-loss watchdog), latency measured
    Verification: pytest examples/follow-target/tests
  5. A simulator scenario with a moving target and target loss
    Verification: demo in the report

Acceptance criteria

The project is passed when all items are done. Check them off as you go:

Auto-check

controller test as a pure function + a run on a recorded bag

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • Detector metrics by distance and lighting slices
  • Target re-acquired after 3 s of loss without an ID change

What to submit

  • ROS 2 package, launch file, README
  • Video and a plot of the target's position error in the frame

Required modules

  1. Cameras and video streaming on the companion
  2. Computer vision: from OpenCV to neural networks
  3. Tracking and target-based control
  4. Onboard ML: budget, quantization, evaluation, maintenance
  5. ROS 2 + PX4: uXRCE-DDS, an offboard node as a state machine
  6. Architecture of an onboard ROS 2 application: nodes, lifecycle, watchdog
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
