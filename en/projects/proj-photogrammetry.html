CourseProjectsProject 7

Photogrammetry on an open dataset

Project 7L3~20 hhas a starterPASSED

An orthomosaic and a terrain model from an open image dataset using OpenDroneMap; accuracy assessment at checkpoints and an analysis of what it depends on.

Stack

  • OpenDroneMap (Docker)
  • QGIS
  • Python для метрик

Starter: examples/perception — clone it and start with its README.

Can replace the capstone project of track “Perception and intelligence”.

Stages

  1. Running ODM on an open dataset
    Verification: demo in the report
  2. Orthophoto and DEM, viewed in QGIS
    Verification: demo in the report
  3. Accuracy metric at checkpoints (starter: checkpoints.py; GCPs are not included in the evaluation)
    Verification: pytest examples/perception/tests -k checkpoints
  4. Experiment: overlap and resolution versus accuracy
    Verification: pytest examples/perception/tests -k gsd_and_spacing
  5. A plan for your own survey mission with GSD calculation
    Verification: pytest examples/perception/tests -k "gsd or fx_from"

Acceptance criteria

The project is passed when all items are done. Check them off as you go:

Auto-check

an RMSE metric script on reference points

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • "Overlap → accuracy" curve with at least 4 points
  • Comparison of EXIF-based and GCP-based georeferencing on the same dataset

What to submit

  • Report with maps and an accuracy table

Required modules

  1. Mapping: surveying, georeferencing, photogrammetry
  2. Cameras and video streaming on the companion
  3. Visual navigation: optical flow, VIO, SLAM overview
  4. GNSS: how GPS works, errors, RTK
  5. Missions and planning
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
