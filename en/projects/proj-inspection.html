CourseProjectsProject 6

Route inspection with georeferenced findings

Project 6L3~30 hhas a starterPASSED

A mission along a line (power line, pipeline, fence), distance-based image capture, automatic georeferencing of frames, and a report with findings on a map.

Stack

  • ArduPilot миссии, CAM1_TRIGG_DIST / DO_SET_CAM_TRIGG_DIST
  • EXIF/XMP геотеги
  • Python, Leaflet-отчёт

Starter: examples/inspection — clone it and start with its README.

Can replace the capstone project of track “Autonomy”.

Stages

  1. Mission generator along a polyline with overlap
    Verification: pytest examples/inspection/tests -k "offset or mission"
  2. Distance-based triggering, CAM log with shutter feedback (CAM1_FEEDBAK_PIN)
    Verification: demo in the report
  3. Matching frames to CAM log entries, writing geotags
    Verification: pytest examples/inspection/tests -k "matching or naive"
  4. Tagging findings and a map report
    Verification: pytest examples/inspection/tests -k geojson
  5. Georeferencing accuracy checked against control points
    Verification: demo in the report

Acceptance criteria

The project is passed when all items are done. Check them off as you go:

Auto-check

matching test on fixtures (CAM log + EXIF set)

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • DEM-based terrain following over hilly ground
  • Automatic frame selection for findings by the model, not by hand

What to submit

  • Mission generator, georeferencing tool, report for one route

Required modules

  1. Missions and planning
  2. Cameras and video streaming on the companion
  3. Mapping: surveying, georeferencing, photogrammetry
  4. Camera geometry: from a pixel to a point on the ground
  5. GNSS: how GPS works, errors, RTK
  6. Field operations and teamwork
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
