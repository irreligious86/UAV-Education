CourseProjectsProject 9

4G/Wi-Fi bridge with reconnection and encryption

Project 9L3~25 hhas a starterPASSED

The companion maintains the GCS ↔ vehicle link over a cellular network: VPN (WireGuard), MAVLink routing, reconnection, prioritizing commands over telemetry, and behavior on link loss.

Stack

  • WireGuard
  • mavlink-router
  • Python или Go
  • tc/netem для имитации плохой сети

Starter: examples/cell-bridge — clone it and start with its README.

Can replace the capstone project of track “Engineer: code on board”.

Stages

  1. VPN between the companion and the server, auto-reconnect
    Verification: demo in the report
  2. MAVLink routing through a tunnel
    Verification: pytest examples/cell-bridge/tests -k control_never
  3. Simulating loss and latency (netem), measurements
    Verification: pytest examples/cell-bridge/tests -k commands_get_through
  4. Reducing the telemetry rate on a poor link
    Verification: pytest examples/cell-bridge/tests -k bad_link
  5. Vehicle-side failsafe on GCS loss tested
    Verification: pytest examples/cell-bridge/tests -k outage

Acceptance criteria

The project is passed when all items are done. Check them off as you go:

Auto-check

netem test: loss, latency, dropout

Grading

Passed when all acceptance criteria are met. The quality level is judged by the criteria below; each level includes the previous one.

  • Functionality
    • Accepted: All stages work in the scenario from the README
    • Good: Plus failure scenarios: link loss, missing data, invalid input
    • Excellent: Plus at least one "excellent" assignment from the project list
  • Verifiability
    • Accepted: Starter tests pass, your own functions are covered by at least one test
    • Good: A test for each stage; tests run in CI
    • Excellent: Failure and regression tests on your own data; coverage of the key logic visible in the report
  • Engineering report
    • Accepted: The measurements required by the acceptance criteria are present
    • Good: Measurements with a method and repeatability (several runs, spread)
    • Excellent: A comparison of solution options with a conclusion, limitations and next steps
  • Code and documentation
    • Accepted: README: one-command launch, architecture
    • Good: Modules separated, interfaces documented, no unexplained "magic numbers"
    • Excellent: The code is readable without the author: docs/, examples, commit history by stage

“Excellent”-level tasks

  • Wi-Fi ↔ 4G switchover without losing a command
  • Traffic cost measured for an hour of flight, telemetry budget for the data plan

What to submit

  • Configs, scripts, report with measurements

Required modules

  1. MAVLink routing and transport: radio, 4G, multiple GCSs
  2. Raspberry Pi + ArduPilot
  3. Navigation and link resilience to interference
  4. Fault tolerance: failsafe, geofence, flight FMEA
Safety. Anything that controls the aircraft goes through tests and SITL first. Real flights only with a verified failsafe and a pilot ready to take over.
