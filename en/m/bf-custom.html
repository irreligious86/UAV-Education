Your own firmware builds

L4 — Expertreading 25 minstudy ~3 hMASTERED

Флеш-память полётника не резиновая: включить всё сразу нельзя, а значит, прошивка под твой аппарат — это выбор. Модуль объясняет, как в Betaflight собрать прошивку под свой набор функций через Cloud Build и когда нужны custom defines, и как в ArduPilot собрать свой вариант из исходников — например, убрать GPS и лишние драйверы, чтобы уместить нужное на F405. С примером из проекта HeeWing.

Theory

Зачем вообще собирать

  • На F411/F405 стандартная прошивка со всеми опциями не влезает или влезает без нужной функции.
  • Нужна опция, которой нет в стандартном наборе (дальномер, транспондер, экзотический протокол).
  • Нужно убрать то, чего на борту нет и не будет (GPS, компас, OSD-чип), освободив место и память.

Betaflight: Cloud Build

Начиная с 4.4, прошивку собирает облачный сервер под твой список опций. В Firmware Flasher выбираешь протокол приёмника, тип OSD, телеметрию, ESC-протокол и прочее; каждая опция — это флаг USE_* в исходниках, имя вводится без префикса. Выбор тянет зависимости сам: CRSF добавит CRSF-телеметрию, GPS — GPS Rescue и элементы OSD. Драйверы конкретной платы (гироскоп, флеш, OSD-чип) добавляются по таргету автоматически.

Custom defines — поле в экспертном режиме для опций вне списков. Они не тестируются на всех платах; если опции нужен пин, его назначают в CLI через resource. Слишком большая прошивка — сборка просто падает.

Проверка на плате: команда version в CLI показывает версию и таргет, а BUILD KEY выводит status — ключ, по которому Cloud Build соберёт ровно такую же прошивку ещё раз. В diff all ключа нет — вывод status сохраняйте отдельно.

ArduPilot: сборка из исходников

ArduPilot собирается waf: ./waf configure --board <board> и ./waf copter (или plane). Таргет описывается в libraries/AP_HAL_ChibiOS/hwdef/<board>/hwdef.dat: пины, шины, какие драйверы включать. Там же через define-строки отключают ненужное.

Для плат с маленькой флешью существуют урезанные конфигурации: много функций в коде обёрнуто проверками #if AP_<FEATURE>_ENABLED, и hwdef может задать define AP_<FEATURE>_ENABLED 0. Веб-инструмент Custom Firmware Builder (ссылка в документации «Building the code») делает то же через интерфейс: ставишь галочки, получаешь прошивку.

Кейс: HeeWing F405 без GPS

Стоковый F405 в проекте HeeWing T1 — плата с ограниченной флешью: нет Lua-скриптинга, часть возможностей урезана. Варианты прошивки, которые планировались для него: убрать поддержку GPS (на этой сборке он не используется для арма и базового полёта) и лишние драйверы, чтобы освободить место под нужное. Это осмысленное решение, если понимаешь последствия: без GPS в прошивке не будет ни RTL, ни геозоны по координатам — не только «сейчас», а вообще.

Правила своих сборок

  1. Хранить конфигурацию сборки в git рядом с параметрами: список опций Betaflight или hwdef-патч ArduPilot.
  2. Называть сборку с датой и хешем коммита; вывод version и BUILD KEY из status должны совпадать с записью.
  3. Перед прошивкой — полный бэкап (diff all / файл параметров), после — перечитать всё критичное.
  4. Не смешивать: своя сборка + стандартный конфиг от другой версии = непредсказуемость.

Локальная сборка Betaflight (когда Cloud Build не подходит)

git clone https://github.com/betaflight/betaflight && cd betaflight
make arm_sdk_install                      # toolchain
make configs                              # unified target configs
make STM32H743 EXTRA_FLAGS="-DUSE_RANGEFINDER -DUSE_GPS_LAP_TIMER"   # family target + extra defines
# или с конфигом конкретной платы:
make SPEEDYBEEF405V4 EXTRA_FLAGS="-DUSE_..."

Результат — obj/betaflight_<ver>_<target>.hex, прошивается конфигуратором «Load Firmware [Local]». Для проверки без железа — make SITL и make test (юнит-тесты gtest, модуль «Как читать исходники»). Размер прошивки — в конце сборки; F411 (512 КБ flash) требует отключать опции -DUSE_* через EXTRA_FLAGS с минусом или урезанные target-конфиги.

Что ломается после своей сборки и как проверять

  1. по BUILD KEY из status (https://build.betaflight.com/api/builds/<key>/json) — ожидаемые опции; 2. status — гироскоп найден; 3. Ports/Receiver — приёмник отвечает; 4. Motors — DShot и bidir работают без пропов; 5. OSD видно; 6. diff all совпадает с бэкапом по смыслу. Чек-лист — в журнал аппарата вместе с хешем коммита и EXTRA_FLAGS.

Practice

Betaflight: сборка под конкретный аппарат

  1. Firmware Flasher → таргет платы → версия.
  2. Опции: приёмник (CRSF), OSD (аналог или цифра), телеметрия, ESC-протокол (DShot), GPS только если он есть.
  3. Expert mode → Custom Defines, если нужно что-то вне списков.
  4. Build → Flash. После прошивки в CLI: version и status — сохранить вывод (BUILD KEY — в status) в папку дрона.
  5. Восстановить конфиг из diff all той же мажорной версии, перечитать ключевые параметры.

ArduPilot: сборка из исходников

git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git
cd ardupilot
Tools/environment_install/install-prereqs-ubuntu.sh -y
./waf configure --board MatekF405-Wing   # example board name; use yours
./waf plane
ls build/MatekF405-Wing/bin/             # arduplane.apj / .bin / .hex

Отключение функции: добавить в hwdef.dat платы (или в отдельный файл extra hwdef) строку вида define AP_<FEATURE>_ENABLED 0, пересобрать, проверить размер в выводе сборки. Для первого опыта проще Custom Firmware Builder на сайте.

Лабораторная

Собери две прошивки ArduPlane для своей платы: стандартную и без одной подсистемы. Сравни размер бинарников, прошей вторую в SITL-подобный стенд (плата на столе) и убедись, что отключённая подсистема действительно исчезла из параметров.

Что должно получиться и что записать

  • Betaflight. После прошивки урезанной сборки version и status сохранены в файл рядом с конфигом (BUILD KEY позволяет пересобрать ровно ту же прошивку). Конфиг восстановлен из diff all той же мажорной версии, а ключевые параметры перечитаны через get. Настройки отключённых опций в CLI отсутствуют — проверь, например, что после сборки без GPS команда get gps ничего не находит.
  • ArduPilot. Вывод сборки показывает размер прошивки и свободную flash. Запиши оба числа для двух сборок: разница — цена отключённой подсистемы в байтах. После прошивки параметры подсистемы (её префикс) исчезают из полного списка параметров в наземке — сделай скриншот поиска по префиксу до и после.
  • Git. Файл с опциями сборки (hwdef с define AP_<FEATURE>_ENABLED 0 или список опций Custom Firmware Build) лежит в репозитории рядом с конфигом. Через полгода на вопрос «почему на этом дроне нет X» ответит коммит, а не память.

Лабораторная засчитывается, когда собраны стандартная и урезанная прошивки, размеры сравнены и вывод version/BUILD KEY сохранён, исчезновение отключённой подсистемы из параметров подтверждено скриншотом или выводом CLI, а конфигурация сборки лежит в git.

Troubleshooting

Симптом: Cloud Build падает с ошибкой размера

  • Возможная причина: слишком много опций для флеша платы.
  • Что сделать: убрать неиспользуемое (второй OSD, лишние протоколы, GPS без GPS).

Симптом: после своей сборки функция «есть», но не работает

  • Возможная причина: опции нужен пин, не назначенный через resource.
  • Что сделать: resource в CLI, перезагрузка, проверить status.

Симптом: ArduPilot waf configure не находит плату

  • Возможная причина: опечатка в имени, нет сабмодулей.
  • Что сделать: ./waf list_boards, git submodule update --init --recursive.

Симптом: после своей сборки часть параметров исчезла

  • Возможная причина: это и есть эффект отключённой подсистемы.
  • Что сделать: сверить с записью о сборке; если параметр нужен — вернуть функцию.
