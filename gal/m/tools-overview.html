Інструменти: Configurator, GCS, git

L1 — Операторчитання 15 хвнавчання ~2 годОПАНОВАНО

Інженерові БпЛА потрібен не один інструмент, а набір: конфігуратор під прошивку, наземна станція, аналізатор логів, термінал і система контролю версій для конфігів. Модуль описує мінімальний стек на 2026 рік, що чим робити, і одне правило, яке береже найбільше нервів: конфіги й логи живуть у папках із датами та в git.

Після модуля ти вмієш
  • встановити Betaflight App, Mission Planner/QGC
  • зберігати конфіги в git з датою в імені

Теорія

Конфігуратори прошивок

  • Betaflight App — налаштування Betaflight: порти, приймач, режими, PID, OSD, CLI, прошивка. Є версії під Windows/macOS/Linux і веб-версія.
  • INAV Configurator — те саме для INAV, із планувальником місій.
  • Mission Planner (Windows) і QGroundControl (кросплатформний) — наземні станції для ArduPilot і PX4: параметри, калібрування, місії, телеметрія, логи. Для ArduPilot на Linux зручний і консольний MAVProxy.

Прошивка і ESC

  • Betaflight App → Firmware Flasher із Cloud Build.
  • ESC Configurator (веб) або Bluejay/AM32 Configurator для прошивки ESC через passthrough.
  • ExpressLRS Configurator — прошивка приймачів і модулів ELRS.
  • Іноді потрібен Zadig (Windows) для драйвера DFU під час прошивки.

Логи

  • Blackbox Explorer (Betaflight) і PIDscope (відкрите продовження PIDtoolbox на GNU Octave; сам PIDtoolbox з 2024 року платний) — логи Betaflight.
  • Mission Planner / MAVExplorer / UAV Log Viewer — DataFlash ArduPilot.
  • Python з orangebox (Betaflight) і pymavlink.DFReader (ArduPilot) — коли потрібні власні метрики.

Термінал і Python

Linux-термінал або WSL на Windows: picocom/minicom для UART, pyserial для скриптів до CLI, pymavlink для MAVLink, scipy/matplotlib для спектрів. Віртуальне оточення на проєкт (python -m venv), щоб версії бібліотек не заважали одна одній.

Git для конфігів

Конфігурація дрона — це код. diff all Betaflight і .param ArduPilot — текстові файли, їх можна зберігати в git, порівнювати й відкочувати. Структура:

drones/
  viking2/
    configs/   2026-11-03_viking2_F405_diff.txt
    logs/      2026-11-03_daylight_profiles/
    notes/     session_notes.md, SUMMARY_2026-11-03.md
  viking10/

Ім'я файлу починається з дати ГГГГ-ММ-ДД — сортування за іменем дає хронологію. Перед будь-якою зміною — файл «до», після — файл «після», різницю видно в git diff.

SITL

Для ArduPilot — SITL, для PX4 — Gazebo/jMAVSim. Будь-який сценарій, скрипт і параметр — спершу на симуляторі.

Порядок встановлення (Linux / WSL2)

sudo apt install git python3-venv picocom build-essential
python3 -m venv ~/uav && . ~/uav/bin/activate
pip install pymavlink MAVProxy pandas numpy scipy matplotlib pyserial
sudo usermod -aG dialout $USER     # access to /dev/ttyACM*/ttyUSB*; re-login
git clone --depth 1 https://github.com/ArduPilot/ardupilot && cd ardupilot && Tools/environment_install/install-prereqs-ubuntu.sh -y

Перевірка: mavproxy.py --master=tcp:127.0.0.1:5760 підключається до sim_vehicle.py -v ArduCopter. У WSL2 USB-пристрої прокидаються через usbipd (Windows 11) — або використовуй Windows-застосунки для USB, а Linux — для скриптів і логів.

Куди що логується (щоб потім знайти)

Betaflight: flash на FC → вивантаження через конфігуратор (вкладка Blackbox) у .BFL; ArduPilot: SD-карта /APM/LOGS/*.BIN або MAVFtp з Mission Planner; телеметрійні логи GCS (.tlog) — окремо, містять усе, що йшло через MAVLink; PX4: .ulg на SD, перегляд через Flight Review (веб) або pyulog. Іменування: ГГГГ-ММ-ДД_аппарат_цель.ext у папці апарата.

Практика

Мінімальне встановлення

  1. Betaflight App, Mission Planner або QGroundControl.
  2. Python 3 + pip install pyserial pymavlink orangebox scipy matplotlib у venv.
  3. Git; репозиторій drones/ за структурою вище.
  4. Термінал послідовного порту.
  5. Для ArduPilot — SITL за модулем «SITL: дрон без дрона».

Перший коміт

  1. Підключити дрон, diff all у CLI (або зберегти .param).
  2. Зберегти в drones/<имя>/configs/<дата>_<имя>_<плата>_diff.txt.
  3. git add, git commit -m "<имя>: baseline <дата>".
  4. Після будь-якої зміни — новий файл і коміт з описом, що й навіщо.

Що має вийти

Після двох комітів git log --oneline drones/<имя>/configs/ показує два рядки зі зрозумілими описами, а git diff між файлами — рівно один змінений рядок:

-set rpm_filter_min_hz = 100
+set rpm_filter_min_hz = 50

Якщо в різниці більше рядків, ніж ти змінював, отже, у диф потрапили неочікувані зміни: інша версія прошивки (нові або перейменовані налаштування), чиїсь правки, скидання до типових значень. Це привід розібратися до польоту, а не після. Порівнюй дифи однієї версії прошивки. Після оновлення прошивки роби окремий базовий коміт «baseline після оновлення».

Типові помилки

  • Ім'я файлу без дати або без плати — за місяць не зрозуміти, що це і звідки.
  • Зберігати dump замість diff all: у дампі сотні рядків типових значень, і корисна зміна в ньому губиться.
  • Коміт без опису «навіщо». За пів року «змінив фільтр» нічого не скаже, а «rpm_filter_min_hz 100→50: мотори 10" нижче 100 Гц на зависанні» — скаже.

Лабораторна

Зроби два дифи з різницею в один параметр і покажи git diff між ними. Це твоє перше «код-рев'ю» власного дрона.

Лабораторна зараховується, коли репозиторій drones/ створено за структурою, конфіг збережено з датою та платою в імені й закомічено з описом, а git diff двох конфігів показує рівно одну зміну з поясненням у повідомленні коміту.

Діагностика

Симптом: конфігуратор не бачить плату

  • Можлива причина: драйвер (Windows), кабель лише для заряджання, плата в DFU.
  • Що зробити: Zadig для DFU, інший кабель, перевірити COM-порт.

Симптом: не пам'ятаю, що змінював перед тим, як зламалося

  • Можлива причина: немає дифів «до/після».
  • Що зробити: правило «файл до змін — завжди», git.

Симптом: бібліотеки Python конфліктують між проєктами

  • Можлива причина: усе ставиться в системний Python.
  • Що зробити: venv на проєкт.
