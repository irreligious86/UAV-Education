L4 — Експертчитання 25 хвнавчання ~3 годОПАНОВАНО

Флеш-пам'ять польотника не гумова: вшитко нараз не ввімкнеш, тож прошивка під твій апарат — то завжди вибір. Модуль пояснює, як у Betaflight зібрати прошивку під свій набір функцій через Cloud Build і коли треба custom defines, і як в ArduPilot зібрати свій варіант із вихідного коду — наприклад, викинути GPS і зайві драйвери, аби вмістити потрібне на F405. З прикладом із проєкту HeeWing.

Після модуля ти вмієш
  • зібрати прошивку під обмеження FC

Перед цим модулем: CLI та remap

Теорія

Нащо взагалі збирати

  • На F411/F405 стандартна прошивка з усіма опціями не влазить або влазить, але без потрібної функції.
  • Треба опція, котрої нема в стандартному наборі (далекомір, транспондер, екзотичний протокол).
  • Треба викинути те, чого на борту нема і не буде (GPS, компас, OSD-чип), і звільнити місце та пам'ять.

Betaflight: Cloud Build

Від версії 4.4 прошивку збирає хмарний сервер під твій список опцій. У Firmware Flasher вибираєш протокол приймача, тип OSD, телеметрію, ESC-протокол і так далі; кожна опція — то прапорець USE_* у вихідному коді, ім'я вводиться без префікса. Вибір сам тягне залежності: CRSF додасть CRSF-телеметрію, GPS — GPS Rescue та елементи OSD. Драйвери конкретної плати (гіроскоп, флеш, OSD-чип) ся додають за таргетом самі.

Custom defines — поле в експертному режимі для опцій поза списками. Їх не тестують на всіх платах; як опції треба пін, його призначають у CLI через resource. Завелика прошивка — і збірка просто падає.

Перевірка на платі: команда version у CLI показує версію й таргет, а BUILD KEY виводить status — ключ, за котрим Cloud Build збере рівно таку саму прошивку ще раз. У diff all ключа нема — вивід status тримай окремо.

ArduPilot: збірка з вихідного коду

ArduPilot збирається waf: ./waf configure --board <board> і ./waf copter (або plane). Таргет описаний у libraries/AP_HAL_ChibiOS/hwdef/<board>/hwdef.dat: піни, шини, які драйвери вмикати. Там само через define-рядки вимикають непотрібне.

Для плат із маленькою флеш-пам'яттю є урізані конфігурації: багато функцій у коді обгорнуто перевірками #if AP_<FEATURE>_ENABLED, і hwdef може задати define AP_<FEATURE>_ENABLED 0. Веб-інструмент Custom Firmware Builder (посилання в документації «Building the code») робить то саме через інтерфейс: ставиш галочки — маєш прошивку.

Кейс: HeeWing F405 без GPS

Стоковий F405 у проєкті HeeWing T1 — плата з обмеженою флеш-пам'яттю: нема Lua-скриптингу, частину можливостей урізано. Варіанти прошивки, котрі для нього планували: викинути підтримку GPS (на цій збірці він не потрібен ні для арму, ні для базового польоту) і зайві драйвери, аби звільнити місце під потрібне. То є розумне рішення, як знаєш наслідки: без GPS у прошивці не буде ні RTL, ні геозони за координатами — і то не «зара», а гет взагалі.

Правила власних збірок

  1. Тримати конфігурацію збірки в git поруч із параметрами: список опцій Betaflight або hwdef-патч ArduPilot.
  2. Називати збірку з датою та хешем коміту; вивід version і BUILD KEY зі status мусять збігатися із записом.
  3. Заки прошивати — повний бекап (diff all / файл параметрів), після — перечитати все критичне.
  4. Не мішати: власна збірка + стандартний конфіг від іншої версії = непередбачуваність.

Локальна збірка Betaflight (коли Cloud Build не надається)

git clone https://github.com/betaflight/betaflight && cd betaflight
make arm_sdk_install                      # toolchain
make configs                              # unified target configs
make STM32H743 EXTRA_FLAGS="-DUSE_RANGEFINDER -DUSE_GPS_LAP_TIMER"   # family target + extra defines
# або з конфігом конкретної плати:
make SPEEDYBEEF405V4 EXTRA_FLAGS="-DUSE_..."

Результат — obj/betaflight_<ver>_<target>.hex, прошивається конфігуратором «Load Firmware [Local]». Аби перевірити без заліза — make SITL і make test (юніт-тести gtest, модуль «Як читати вихідний код»). Розмір прошивки видно наприкінці збірки; F411 (512 КБ flash) вимагає вимикати опції -DUSE_* через EXTRA_FLAGS з мінусом або брати урізані target-конфіги.

Що ся ламає після власної збірки і як перевіряти

  1. за BUILD KEY зі status (https://build.betaflight.com/api/builds/<key>/json) — очікувані опції; 2. status — гіроскоп знайдено; 3. Ports/Receiver — приймач відповідає; 4. Motors — DShot і bidir працюють без пропів; 5. OSD видно; 6. diff all за змістом збігається з бекапом. Чек-лист — у журнал апарата разом із хешем коміту та EXTRA_FLAGS.

Практика

Betaflight: збірка під конкретний апарат

  1. Firmware Flasher → таргет плати → версія.
  2. Опції: приймач (CRSF), OSD (аналог або цифра), телеметрія, ESC-протокол (DShot), GPS — лиш як він є.
  3. Expert mode → Custom Defines, як треба щось поза списками.
  4. Build → Flash. Після прошивання в CLI: version і status — зберегти вивід (BUILD KEY — у status) у папку дрона.
  5. Відновити конфіг із diff all тієї самої мажорної версії, перечитати ключові параметри.

ArduPilot: збірка з вихідного коду

git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git
cd ardupilot
Tools/environment_install/install-prereqs-ubuntu.sh -y
./waf configure --board MatekF405-Wing   # example board name; use yours
./waf plane
ls build/MatekF405-Wing/bin/             # arduplane.apj / .bin / .hex

Вимкнення функції: додати в hwdef.dat плати (або в окремий файл extra hwdef) рядок на кшталт define AP_<FEATURE>_ENABLED 0, перезібрати, перевірити розмір у виводі збірки. Для першого разу простіше взяти Custom Firmware Builder на сайті.

Лабораторна

Збери дві прошивки ArduPlane для своєї плати: стандартну й без однієї підсистеми. Порівняй розмір бінарників, проший другу в SITL-подібний стенд (плата на столі) і пересвідчи-ся, що вимкнена підсистема справді щезла з параметрів.

Що має вийти і що записати

  • Betaflight. Після прошивання урізаної збірки version і status збережено у файл поруч із конфігом (BUILD KEY дає змогу перезібрати рівно ту саму прошивку). Конфіг відновлено з diff all тієї самої мажорної версії, а ключові параметри перечитано через get. Налаштувань вимкнених опцій у CLI нема — перевір, наприклад, що після збірки без GPS команда get gps ніц не знаходить.
  • ArduPilot. Вивід збірки показує розмір прошивки та вільну flash. Запиши обидва числа для двох збірок: різниця — то ціна вимкненої підсистеми в байтах. Після прошивання параметри підсистеми (її префікс) щезають із повного списку параметрів у наземці — зроби скриншот пошуку за префіксом до і після.
  • Git. Файл з опціями збірки (hwdef з define AP_<FEATURE>_ENABLED 0 або список опцій Custom Firmware Build) лежить у репозиторії поруч із конфігом. За пів року на питання «чом на цьому дроні нема X» відповість коміт, а не пам'ять.

Лабораторна зараховується, коли зібрано стандартну й урізану прошивки, розміри порівняно і вивід version/BUILD KEY збережено, зникнення вимкненої підсистеми з параметрів підтверджено скриншотом або виводом CLI, а конфігурація збірки лежить у git.

Діагностика

Симптом: Cloud Build падає з помилкою розміру

  • Можлива причина: забагато опцій для флеш-пам'яті плати.
  • Що зробити: викинути невикористовуване (другий OSD, зайві протоколи, GPS без GPS).

Симптом: після власної збірки функція «є», але не працює

  • Можлива причина: опції треба пін, а його не призначено через resource.
  • Що зробити: resource у CLI, перезавантаження, перевірити status.

Симптом: ArduPilot waf configure не знаходить плату

  • Можлива причина: одрук в імені, нема сабмодулів.
  • Що зробити: ./waf list_boards, git submodule update --init --recursive.

Симптом: після власної збірки частина параметрів щезла

  • Можлива причина: то і є ефект вимкненої підсистеми.
  • Що зробити: звірити із записом про збірку; як параметр треба — вернути функцію.
