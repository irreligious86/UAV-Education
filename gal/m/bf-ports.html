Теорія

Що то є UART і нащо налаштування портів

UART — послідовний інтерфейс: пара TX (передавання) і RX (приймання). У вкладці Ports кожному фізичному UART призначають роль: Serial RX, GPS, телеметрія, MSP тощо.

Правило: на одному UART в один момент — одна основна роль для потоку даних. Як ся сумістить, наприклад, Serial Rx і Telemetry Output на одному порту без розуміння протоколу, то часто маєш конфлікт, і збереження налаштувань ся «ламає».

Типи приймачів і розпаювання

Протокол задає і проводку, і пункт Serial Receiver Provider у конфігураторі.

  • SBUS (FrSky, Futaba, частина DJI) — у BF: SBUS. Сигнал із приймача → RX вибраного UART (не на TX).
  • CRSF (TBS Crossfire, ExpressLRS) — у BF: CRSF. RX приймача → TX FC, TX приймача → RX FC (класичне перехресне з'єднання для повного дуплексу).
  • FPort (FrSky) — FrSky FPort; один провід, інверсія/пін залежать від плати та версії — звіряйся з мануалом FC.
  • IBUS (FlySky, Turnigy) — IBUS, сигнал → RX.
  • Spektrum DSM — SPEKTRUM1024 / SPEKTRUM2048, сигнальний провід за документацією приймача.

F4 і SBUS: на частині плат нема апаратного інвертора під інвертований SBUS — бери виділений пін SBUS на FC або інший протокол (FPort тощо), бо інакше треба буде зовнішній інвертор.

Betaflight 4.4+ і Cloud Build

З 4.4.0 під час збирання через Cloud Build у прошивку трафляють лише вибрані протоколи приймача. За замовчуванням у Firmware Flasher позначено лише CRSF; SBUS і GHST теж треба вибрати руками. IBUS, Spektrum та ін. треба явно позначити під час збирання — інакше приймач «мовчить», хоч як ти його розпаяв.

Обмеження MSP

MSP треба конфігуратору та частині пристроїв. Обмеження: одночасно не більше трьох UART з увімкненим MSP; з четвертим конфігурація портів вважається невалідною і під час завантаження вся скидається до замовчувань.

Порада: з'єднання з ПК по USB зазвичай займає окремий канал; не перепризначай його під приймач, якщо не розумієш схеми плати.

Команда serial: що зберігається насправді

Вкладка Ports — обгортка над serial <id> <маска функций> <msp baud> <gps baud> <telemetry baud> <blackbox baud>: ідентифікатор порту (у 4.5: 0 = UART1, 1 = UART2, … 20 = VCP/USB, 30+ = SoftSerial; у 2025.12 diff пише імена, наприклад serial UART3 64 …), бітова маска функцій (MSP = 1, GPS = 2, … Serial RX = 64, Blackbox = 128, ESC Sensor, SmartAudio, Tramp, MSP DisplayPort — свої біти; точні значення — перелік serialPortFunction_e у src/main/io/serial.h), і швидкості. Тому diff all має рядки на кшталт serial 2 64 115200 57600 0 115200 — UART3 = Serial RX. Читати їх варто, коли переносиш конфіги між платами: номери UART у різних плат різні.

Розібраний приклад: розкласти 5 пристроїв по 4 UART на F405

Пристрої: ELRS (CRSF), GPS, цифровий VTX (DisplayPort), ESC-телеметрія, SmartAudio-VTX — та де: цифрового й аналогового VTX нараз не буває; бай буде аналоговий VTX зі SmartAudio + камера з RunCam-протоколом. UART1 — CRSF (не SBUS-порт треба), UART2 — GPS, UART3 — SmartAudio (TX-пін), UART4 — ESC Sensor (RX-пін), RunCam Device — на SoftSerial 11 через LED-пад. Правило: спершу повнодуплексні (CRSF, GPS, DisplayPort), потім однопровідні, потім softserial для некритичного.

Практика

Крок 1. Ідентифікація UART на FC

  1. Знайди розпіновку (шовкографія на платі або сайт виробника).
  2. UART підписані як UART1… або RX1/TX1 і відповідають рядкам у вкладці Ports.

Порада: USB на STM32-платах — окремий віртуальний порт (рядок USB VCP у Ports), а не UART1; виняток — рідкісні плати із зовнішнім USB-UART мостом — такий порт не бери під приймач, поки не прочитаєш схему.

Крок 2. Фізичне підключення приймача

  1. Знеструмити FC перед паянням/вставлянням у роз'єм.
  2. Для приймача взяти вільний UART (часто зручно лишити канал USB як є і зайняти UART2/UART3).
  3. Розпаяти за таблицею вище (SBUS → RX, CRSF → перехресно тощо).
  4. Перевірити паяння і що нема КЗ між сусідніми пінами.

Крок 3. Вкладка Ports

  1. Підключити FC по USB, відкрити Betaflight Configurator.
  2. Ports — знайти рядок UART, куди йде приймач.
  3. Не вимикати MSP на тому UART, котрий нараз потрібен для зв'язку з ПК (див. мануал плати).
  4. Увімкнути лише Serial Rx на вибраному UART; решту функцій на тому самому UART — вимкнути (MSP, зайва телеметрія тощо, якщо вони конфліктують з твоєю схемою).
  5. Save and Reboot.

Крок 4. Протокол приймача (Configuration)

  1. Після перезавантаження — вкладка Receiver.
  2. Receiver Mode: Serial-based receiver (як у підказці конфігуратора).
  3. Serial Receiver Provider — строго під залізо:
  • TBS Crossfire / ELRS → CRSF
  • FrSky SBUS → SBUS
  • FrSky FPort → FrSky FPort
  • FlySky / Turnigy → IBUS
  • Spektrum → SPEKTRUM1024 / SPEKTRUM2048
  1. Save and Reboot.

Крок 5. Перевірка Receiver

  1. Приймач зв'язаний з пультом (індикація за інструкцією).
  2. Вкладка Receiver — рух стиків і тумблерів рухає повзунки каналів.
  3. Діапазон типово ~1000–2000, центр ~1500.

Крок 6. Додатково

  • Повзунки «не тих» каналів — Channel Map (AETR, TAER …) на Receiver.
  • Краї діапазону криві — endpoints на пульті або rxrange у CLI.
  • Телеметрія на пульт (CRSF/ELRS): зазвичай іде тим самим UART, що й керування; як треба — перевір опції Telemetry у Configuration для своєї зв'язки.

Діагностика

Симптом: Після збереження портів і перезавантаження налаштування «відкотилися».

  • Можлива причина: конфлікт функцій на одному UART (Serial Rx + зайвий MSP тощо) або ліміт MSP на трьох портах.
  • Що зробити: у вкладці Ports лишити на UART приймача лише потрібне; переконатися, що не більше трьох портів з MSP; зберегти й перезавантажити.

Симптом: У Receiver повзунки ся не рухають, приймач у лінку.

  • Можлива причина: Serial Rx не на тому UART; неправильний Provider; прошивка без потрібного протоколу (Cloud Build).
  • Що зробити: перевірити Ports і Configuration; для BF 4.4+ перезібрати прошивку з потрібним протоколом приймача.

Симптом: CRSF/ELRS працює, на пульті нема телеметрії.

  • Можлива причина: вимкнена телеметрія в налаштуваннях зв'язки або провайдер не CRSF.
  • Що зробити: Serial Receiver Provider = CRSF; увімкнути телеметрію за мануалом ELRS/пульта.

Симптом: SBUS на F4 не запускається.

  • Можлива причина: нема інвертора, сигнал іде не на пін SBUS / не той UART.
  • Що зробити: пін SBUS на платі, FPort, зовнішній інвертор або інший протокол.

Симптом: Повзунки ся рухають, але не вкладаються в 1000–2000.

  • Можлива причина: endpoints на пульті; не налаштований rxrange.
  • Що зробити: виставити хід на пульті; як треба — `rxrange` у CLI.

Симптом: Після налаштувань GPS passthrough «щезають» MSP-налаштування.

  • Можлива причина: перевищено ліміт трьох портів з MSP.
  • Що зробити: вимкнути MSP там, де він не треба; лишити не більше трьох UART з MSP.

Симптом: після збереження Ports конфігуратор «відвалюється»

  • Можлива причина: вимкнений MSP на порту USB/VCP або увімкнений MSP на 4-му порту.
  • Що зробити: підключення через інший порт/DFU, serial 20 1 115200 … для VCP.

Симптом: ESC Sensor не дає телеметрії

  • Можлива причина: провід на TX замість RX, ESC без телеметрії, не ввімкнений esc_sensor.
  • Що зробити: RX-пін, прошивка ESC, feature ESC_SENSOR у CLI (або bidirectional DShot як альтернатива для RPM).
