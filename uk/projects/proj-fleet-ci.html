CI/CD для флоту

Проєкт 10L3~20 годє стартерЗДАНО

Параметри й скрипти флоту живуть у git; кожен коміт проганяє тест failsafe і місію в SITL, порівнює параметри з еталоном і збирає артефакт для викладання на апарат.

Стек

  • GitHub Actions
  • ArduPilot SITL
  • pymavlink
  • параметры в .param, Lua-скрипты

Стартер: examples/sitl-pymavlink — клонуй і починай з його README.

Може замінити підсумковий проєкт треку «Інженер: код на борту».

Етапи

  1. Репозиторій флоту: параметри по апаратах, спільні й особисті
    Перевірка: демонстрація у звіті
  2. Workflow: SITL + тест failsafe (стартер ci.yml)
    Перевірка: python examples/sitl-pymavlink/test_check_lab_log.py
  3. Diff параметрів проти еталона з поясненням змін
    Перевірка: демонстрація у звіті
  4. Тест місії та перевірка логу грейдером
    Перевірка: python examples/sitl-pymavlink/check_lab_log.py flight.bin --lab mission --json result.json
  5. Викладка: артефакт із параметрами та чек-листом
    Перевірка: демонстрація у звіті

Критерії приймання

Проєкт здано, коли виконано всі пункти. Позначай у міру готовності:

Автоперевірка

сам workflow — це тест (examples/sitl-pymavlink/ci.yml, check_lab_log.py)

Оцінка

Здано — коли виконано всі критерії приймання. Рівень роботи — за критеріями нижче; кожен рівень включає попередній.

  • Функціональність
    • Зараховано: Усі етапи працюють у сценарії з README
    • Добре: Плюс сценарії відмов: втрата зв'язку, пропуск даних, хибне введення
    • Відмінно: Плюс хоча б одне завдання «на відмінно» зі списку проєкту
  • Перевірюваність
    • Зараховано: Тести стартера проходять, власні функції покрито хоча б одним тестом
    • Добре: Тест на кожен етап; тести запускаються в CI
    • Відмінно: Тести на відмови й регресію на власних даних; покриття ключової логіки видно у звіті
  • Інженерний звіт
    • Зараховано: Є заміри, яких вимагають критерії приймання
    • Добре: Заміри з методикою та повторюваністю (кілька прогонів, розкид)
    • Відмінно: Порівняння варіантів рішення з висновком, обмеження та що робити далі
  • Код і документація
    • Зараховано: README: запуск однією командою, архітектура
    • Добре: Модулі розділено, інтерфейси описано, немає «магічних чисел» без пояснення
    • Відмінно: Код читається без автора: docs/, приклади, історія комітів за етапами

Завдання «на відмінно»

  • Матриця CI за двома версіями прошивки
  • Автоматичний diff параметрів з поясненням із документації

Що здати

  • Репозиторій флоту із зеленим CI та історією змін

Потрібні модулі

  1. CI та версіонування конфігів і коду
  2. SITL: дрон без дрона
  3. Відмовостійкість: failsafe, геозона, FMEA польоту
  4. Автоматизація CLI через serial
Безпека. Усе, що керує апаратом, спершу проходить тести і SITL. Реальний політ — тільки з перевіреним failsafe і пілотом, готовим перебрати керування.
