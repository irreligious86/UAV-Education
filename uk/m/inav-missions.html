Миссии INAV: waypoints и CLI wp

L2 — Интеграторчтение 20 минучёба ~2 чINAV 7.0+ОСВОЕН

Миссия INAV — список точек с действиями, который аппарат выполняет в режиме NAV WP. Модуль показывает, из чего состоит точка, какие действия есть (WAYPOINT, POSHOLD_TIME, RTH, JUMP, SET_POI, LAND), как записать миссию через конфигуратор и через CLI командой wp, где лежит высота, и как INAV защищает от взлёта с «чужой» миссией.

  • записать миссию через конфигуратор и CLI wp
  • объяснить защиту от чужой миссии

Теория

Структура точки

В CLI: wp <n> <action> <lat> <lon> <alt> <p1> <p2> <p3> <flag>.

  • lat, lon — градусы × 10⁷ (123456789 = 12.3456789°).
  • alt — сантиметры; бит 0 в p3 задаёт, относительно дома (0) или над уровнем моря (1).
  • action: 1 WAYPOINT, 3 POSHOLD_TIME, 4 RTH, 5 SET_POI, 6 JUMP, 7 SET_HEAD, 8 LAND.
  • p1: для WAYPOINT — скорость к точке (см/с; только мультиротор и только если 50 < p1 < nav_auto_speed); для POSHOLD_TIME — время в секундах; для RTH — p1 > 0 разрешает посадку; для JUMP — индекс цели.
  • p2: для POSHOLD_TIME — скорость; для JUMP — число повторов.
  • flag последней точки — 165 (0xA5).

wp load загружает список из EEPROM, wp save — сохраняет, wp reset — очищает.

Выполнение

Режим NAV WP включается тумблером. Аппарат летит от точки к точке на nav_auto_speed (или скорости из p1), радиус захвата точки — nav_wp_radius. JUMP даёт циклы, SET_POI — поворот камеры на точку интереса, LAND — посадка на точке.

Защита от чужой миссии

Если загружена миссия, первая точка которой дальше nav_wp_max_safe_distance, арм блокируется. Это защита от сценария «приехал на другое поле с вчерашней миссией». Обход — nav_extra_arming_safety = ALLOW_BYPASS плюс yaw-стик при арме, и это именно обход.

Несколько миссий

Конфигуратор умеет хранить несколько миссий в одном списке точек и переключаться между ними; операнды Programming Framework для точек относятся к выбранной миссии.

Против ArduPilot

В INAV миссия проще: нет CONDITION-команд, нет DO-команд в чистом виде (часть действий — через user actions в p3 и логические условия), загрузка через MSP/CLI, MAVLink-протокол миссий (MISSION_COUNT/MISSION_ITEM) поддерживается упрощённо. Для съёмки участка и облёта — достаточно; для сложной логики — Programming Framework или ArduPilot.

Параметры выполнения и защиты

nav_auto_speed (500 см/с) — скорость по умолчанию, nav_wp_radius (100 см) — радиус захвата точки (для крыла — больше, 1000–3000), nav_wp_max_safe_distance (100 м; 0 — выключить) — первая точка дальше этого от места арма → арм заблокирован («вчерашняя миссия на новом поле»). Для крыла точки проходятся по дуге, для мультиротора — с остановкой; nav_mc_wp_slowdown управляет торможением у точки.

Разобранный пример: облёт участка 200×100 м для съёмки

Высота 60 м, поперечное перекрытие кадров 70% при горизонтальном FOV камеры 84° (охват поперёк галса ≈ 2·60·tan42° ≈ 108 м) → расстояние между галсами 108 × (1 − 0.7) ≈ 32 м → на 100 м ширины 4 галса; точки: WAYPOINT ×8 с p1 = 0 (скорость nav_auto_speed = 5 м/с), в конце RTH с p1 = 1 (посадка разрешена). Время: ~1 км пути / 5 м/с ≈ 3.5 мин + развороты. В CLI это 9 строк wp, последняя с флагом 165. Триггер камеры — через PINIO/user action по p3 или интервальная съёмка на самой камере. Проверка миссии в конфигураторе на карте: ни одна точка не над людьми/дорогой, высота выше деревьев.

Что происходит, когда в миссии что-то ломается

  • Потеря RC в NAV WP: срабатывает failsafe INAV (failsafe_procedure, обычно RTH); миссию по умолчанию не продолжает — это решение пилота, а не прошивки. Проверяйте, что RTH-высота выше препятствий на всём маршруте.
  • Потеря GPS: навигационные режимы невозможны — аппарат переходит в аварийную посадку (nav_emerg_landing_speed). Миссия над водой или лесом — с запасом высоты и понятным планом «куда упадёт».
  • Низкий заряд: планируйте миссию на 60–70 % ёмкости и следите за предупреждениями OSD; не рассчитывайте, что прошивка сама прервёт миссию вовремя.
  • Пилот выключил NAV WP: аппарат возвращается в выбранный тумблером режим; что будет при повторном включении — продолжение или начало сначала — задаёт nav_wp_mission_restart.

Практика

Шаг 1. Миссия в конфигураторе

  1. Вкладка Mission Control: поставить 3–4 точки, высота 30 м относительно дома.
  2. Последняя — RTH с посадкой (или без для крыла).
  3. Сохранить в FC (Save to FC) и в файл.

Шаг 2. Та же миссия в CLI

wp reset
wp 0 1 505000000 304000000 3000 0 0 0 0
wp 1 1 505005000 304005000 3000 0 0 0 0
wp 2 3 505010000 304000000 3000 20 0 0 0
wp 3 4 0 0 0 1 0 0 165
wp save
wp

Точка 2 — POSHOLD_TIME 20 с, точка 3 — RTH с посадкой, последний флаг 165.

Шаг 2б. Генератор CLI из списка координат

Руками переводить градусы в «× 10⁷» и сантиметры — верный способ ошибиться на порядок. Скрипт:

def wp_cli(points, alt_m=30, rth_land=True):
    # points: [(lat, lon), ...] in degrees -> INAV CLI lines; altitude relative to home
    lines = ["wp reset"]
    for i, (lat, lon) in enumerate(points):
        lines.append(f"wp {i} 1 {round(lat * 1e7)} {round(lon * 1e7)} {round(alt_m * 100)} 0 0 0 0")
    n = len(points)
    lines.append(f"wp {n} 4 0 0 0 {1 if rth_land else 0} 0 0 165")   # RTH, last point flag 0xA5
    lines += ["wp save", "wp"]
    return "\n".join(lines)

print(wp_cli([(50.4500000, 30.5200000), (50.4505000, 30.5205000), (50.4510000, 30.5200000)]))

Вывод вставить в CLI, затем сравнить с тем, что показывает вкладка Mission Control. Расхождение в координатах на 7-м знаке — норма округления; на 1–2-м — ошибка в порядке lat/lon.

Шаг 3. Полёт

  1. 3D-фикс, дом записан, миссия загружена (wp показывает список).
  2. Арм, ANGLE, взлёт вручную на безопасную высоту.
  3. Включить NAV WP тумблером. Следить за прохождением точек в OSD.
  4. В любой момент — выключить NAV WP и забрать управление.

Лабораторная

Записать одну миссию двумя способами (конфигуратор и CLI через генератор), сравнить вывод wp — он должен совпасть. Прогнать с POSHOLD_TIME и RTH. Для каждой точки маршрута записать, что будет при потере RC и GPS именно там (высота RTH над препятствиями, место аварийной посадки).

Диагностика

Симптом: не армится с загруженной миссией

  • Возможная причина: первая точка дальше nav_wp_max_safe_distance.
  • Что сделать: перезаписать миссию под текущее место или сбросить.

Симптом: аппарат идёт к точкам, но не садится в конце

  • Возможная причина: у RTH p1 = 0 (посадка запрещена) или nav_rth_allow_landing = NEVER.
  • Что сделать: поставить p1 = 1 и проверить nav_rth_allow_landing.

Симптом: высота миссии не та

  • Возможная причина: бит 0 в p3 (абсолютная высота) или путаница сантиметров и метров.
  • Что сделать: проверить p3 и единицы alt.

Симптом: wp показывает пустой список после перезагрузки

  • Возможная причина: не выполнен wp save.
  • Что сделать: сохранить и проверить wp load.

Симптом: аппарат пролетает мимо точек

  • Возможная причина: nav_wp_radius мал для скорости (особенно крыло).
  • Что сделать: радиус больше, скорость меньше у точек.
